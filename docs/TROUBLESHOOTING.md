# 트러블슈팅

## 기록 기준

재현 조건·진단 근거·해결 또는 우회·재발 확인 방법을 재사용할 수 있는 문제만 등록한다. 아직 원인·해결을 모르면 미확인으로 표시한다. 단순 일지·일회성 오타·근거 없는 추측을 사례로 확정하지 않는다.

사례에는 원인과 진단·해결에 필요한 핵심 조건만 남기고, 당일 실행 결과·작업 상태 등은 [AGENTS](../AGENTS.md#작업-목적에-따라-읽을-문서)에 따른 해당 문서로 연결한다.

## 사례 색인

등록된 사례 없음. 문제가 생기면 `TS-001`부터 ID를 부여하고 이 문서의 사례 기록 절에 추가한다. 별도 사례 파일은 만들지 않는다.

| ID | 증상·범위 | 상태 | 사례 | 최근 재발 확인 근거 |
| --- | --- | --- | --- | --- |

## 작성·재발 확인

1. [사례 양식](#사례-작성-양식)에 증상·영향·재현 조건·진단·원인·조치를 기록한다.
2. 해결 뒤 원래 재현 조건과 관련 경계에서 재확인하고 worklog에 결과를 남긴다.
3. 색인에 미해결·우회·해결 상태와 최근 검증 근거를 연결한다. 미재현을 원인 해소로 단정하지 않는다.
4. 재발하면 같은 사례에 새 근거를 연결하고 원인·적용 범위가 다른 경우 별도 ID로 구분한다.

## 사례 작성 양식

아래 양식을 복사해 사례 기록 절에 추가한다.

```markdown
### TS-<번호>: <증상>

상태: 미해결 / 우회 / 해결
작업 ID: <TASKS 링크>
관련 설계·DEC ID: <링크>

#### 증상·영향·재현 조건

관찰 가능한 현상, 영향 사용자·환경·범위, 재현 순서:

#### 진단과 원인

확인한 근거·배제한 가설·확인된 원인과 미확인 부분:

#### 해결·우회와 적용 범위

조치·적용 조건·부작용·주의점:

#### 재발 확인 방법

원래 재현 시나리오와 경계 조건, 회귀 확인 방법:

#### 실행 근거

당일 조건·명령·실제 결과는 해당 [worklog](worklogs/TEMPLATE.md)로 연결한다. 원인·해결이 확인되지 않았다면 상태와 한계를 명시한다.
```
