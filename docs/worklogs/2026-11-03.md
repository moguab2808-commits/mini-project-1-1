### 수행과 관찰

1. 시작 준비가 5초보다 늦으면 `GameService.#waitStarted`가 먼저 풀려 경기 없는 이탈을 처리하고 이후 시작이 다시 진행될 수 있었다. 시작 준비 훅을 서비스 안의 동일한 완료 신호에 포함하고 임의의 5초 우회를 없앴다. 단위 테스트에서 시작을 6초 지연해 이탈이 기다리는지, 시작 실패도 대기를 해제하고 전적을 만들지 않는지 확인했다.
2. 두 사용자의 이탈 훅·DB 변경이 동시에 돌면 참여자 정리와 방장 정리가 같은 세션을 건드린다. 시간 제한 제거 뒤 실제 클라이언트 통합 테스트 정리에서 방이 남는 것으로 재현했다. 방별 이탈 직렬화와 잠금 안 재조회로 해결했다. 두 좌석 동시 `leave()`가 완료되고 전적이 각각 한 번 저장되는 통합 테스트를 추가했다.
3. 이탈 종료의 `rematchDeadlineMs`가 API 표와 달리 채워졌다. 런타임이 수락한 이탈 기권에는 `null`, 방에 남아 기권 버튼만 누른 경우에는 기존 재도전 마감을 전달한다. 이벤트와 최종 뷰가 같은 결과를 가진다. 이는 새로운 제품 정책이 아닌 기존 API 계약과의 정합성 수정이다.
4. 기존 런타임이 `game:over`를 보낸 뒤 최종 `game:state`를 보냈다. 최종 신뢰 전송 뷰를 결과 이벤트보다 먼저 보내 API 순서 규칙 6에 맞췄다. `game-service.test.ts`에서 종료 뒤 상태 이벤트가 없음을 확인했다.
5. PR #63의 `INTERNAL_ERROR` 추가를 원격 명령 ack에 그대로 수용했다. PR #62는 이미 병합됐으므로 IMPL-005 완료 상태도 맞췄다.

## IMPL-010 온라인 대전 클라이언트

### 범위와 기준 문서

[IMPL-010](../TASKS.md#impl-010-온라인-대전-클라이언트), [LOCAL GameSession](../design/LOCAL.md#gamesession-시그니처)·[온라인 연결 구성](../design/LOCAL.md#온라인-연결-구성), [API 이벤트 순서](../design/API.md#이벤트-순서), DEC-030.

### 구현

- `RemoteGameSession`: 기존 GameSession 구현. 발사·방해요소·기권·재도전·판 돌리기의 ack 객체를 그대로 전달하고, 조준·몸짓 입력은 volatile로 보낸다. 다른 경기·지나간 시작·증가하지 않은 revision·종료 뒤 이벤트를 버린다.
- `RoomClient`: 방 생성·참가·즉시 참가·이탈, 방 상태·폐쇄, 중복 접속·연결 실패·끊김을 처리한다. `room:state` 처리 중 동기적으로 세션과 스토어를 생성해 시작·지급을 놓치지 않는다. 재도전과 방장 대기 뒤 새 참여자도 같은 세션을 사용한다.
- `SocketRequests`: 명령 ack에 임의 시간 제한을 두지 않고 연결 종료·정리 때 대기를 마친다. 자동 재접속을 끄고 로그인 전환 콜백을 한 번만 호출한다. 소켓 이벤트 구독과 스토어를 정리한다. 원격 `dispose()`는 `room:leave`를 보낸다.
- `/online`: 기존 `GameScreen` 코드를 바꾸지 않고 원격 세션을 넘기는 개발용 연결 확인 화면. 같은 출처 인증 쿠키가 필요하며 정식 로그인·로비 화면은 IMPL-012다. 연결 종료는 `/login` 이동에 연결했다. Vite 개발 서버는 `/api`·`/socket.io`를 기본 서버 포트로 프록시한다.
- `online.test.ts` 9건: ack 이전 시작·지급, 재도전·다음 참여자, 낡은 이벤트·뷰, 모든 오류 코드의 객체 동일성, 닫힌 방의 늦은 성공 ack, 시작 실패, 세 종류의 접속 종료, dispose 정리.
- `tests/integration/online.db.test.ts` 5건: 실제 인증·Socket.IO·DB로 두 계정 입장→발사·몸짓→기권 종료→재도전→참여자 이탈→다음 참여자, 동시 이탈, 중복 접속, 서버 연결 종료, 시작 실패를 검증한다. 테스트 설정은 외부에서 지정한 DB URL도 받으며 저장소 밖 통합 테스트를 포함한다.

### 검증 결과

- `npm test`: 26개 파일·303개 통과.
- `npm run test:db`: 임시 로컬 PostgreSQL에서 5개 파일·82개 통과(기존 77개 + 원격 클라이언트 통합 5개). 최종 단위 테스트와 DB 테스트를 각각 다시 실행해 같은 결과를 확인했다.
- `npm run lint`, `npm run format`, `npm run build`: 통과. 클라이언트 빌드는 기존의 500kB 초과 번들 경고를 낸다.
- 통합 테스트를 5건으로 늘린 첫 실행은 한 IP의 인증 요청이 분당 20회를 넘어 429를 받았다. 계정별 테스트 IP를 분리한 뒤 82건 모두 통과했다. 제품 빈도 제한은 바꾸지 않았다.
- 변경 문서의 상대 링크 532개를 검사했다. 추가한 링크의 경로·앵커 오류는 없었다. 단순 slug 검사기는 기존 IMPL-004의 가운데점 포함 앵커 한 건을 지적하므로 전체 기존 링크의 브라우저 유효성까지 보장한 검증은 아니다.
- 원격 명령·필터링은 대역 소켓으로, 실제 이벤트 순서·기권·재도전·이탈은 서버 통합 테스트로 확인했다. 실행 값·세션 쿠키·비밀번호를 기록하지 않았다.
