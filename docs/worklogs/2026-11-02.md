# 2026-11-02 작업·검증 기록

## IMPL-006 DB·마이그레이션

### 범위와 기준 문서

- 작업: [IMPL-006](../TASKS.md#impl-006-db마이그레이션)
- 기준: [DATABASE](../design/DATABASE.md)(테이블·제약·세션 테이블·마이그레이션), [OPERATIONS 사용량·부하](../design/OPERATIONS.md#사용량부하-확인)(연결 풀 유휴 시간), [AUTH 세션](../design/AUTH.md#세션), [DEC-022·023·027](../DECISIONS.md#결정-색인)
- 범위: Drizzle 스키마(`users`·`rooms`·`session`), 마이그레이션 파일과 실행기, 연결 풀. 인증·방 API는 IMPL-007·008이다.

### 작업·검증 조건

- 브랜치·변경: `feat/impl-006-db-migration`, 검증 때는 미커밋 변경이었고, 이후 커밋·푸시하고 [PR #54](https://github.com/moguab2808-commits/mini-project-1-1/pull/54)를 만들었다.
- 환경: Windows 11, Node 24.22.0, npm 11.19.1. 검증 DB는 Neon 무료 플랜 PostgreSQL(싱가포르 리전)의 개발용 프로젝트이며 로컬 `.env`의 `DATABASE_URL`로 연결했다(값은 기록하지 않는다). 이 PC에는 psql·Docker가 없다.
- 고정한 라이브러리: `drizzle-orm` 0.45.4, `pg` 8.23.1, `drizzle-kit` 0.31.11, `@types/pg` 8.23.1(정확한 버전, lock 파일 갱신).
- 방식: 테스트가 Neon에 임시 데이터베이스(`alkkagi_test_<무작위>`)를 만들어 마이그레이션을 적용하고 검증한 뒤 `DROP DATABASE`로 지운다. 개발 DB의 `public` 스키마에는 마이그레이션을 적용하지 않았다.

### 수행과 관찰

변경: `packages/server/src/db/{schema,pool,migrate}.ts`, `packages/server/drizzle.config.ts`, 생성된 `packages/server/drizzle/0000_*.sql`, 검증 테스트 `schema.test.ts`, `db:generate`·`db:migrate` 스크립트, vitest가 루트 `.env`를 읽도록 `config/vitest.config.ts` 수정.

실행: `npm run db:generate -w @alkkagi/server`, `npm run format:write`, `npm run lint`, `npm run build -w @alkkagi/server`, `npm test`(DB 테스트 포함 설정). 개발자 A의 리뷰(PR #54)를 반영해 DB 테스트를 `schema.db.test.ts`로 옮기고 `npm run test:db`로만 실행하도록 분리했다. 기본 `npm test`는 `.env`를 읽지 않고 DB에 접속하지 않는다.

- 첫 `npm test`에서 DB 테스트 11건 중 2건이 실패했다. 둘 다 스키마가 아니라 테스트의 오류였다.
  - 인덱스 정의 정규식이 실제 출력 `(lower((nickname)::text))`과 맞지 않았다. 정규식을 고쳤다.
  - `total_games = -1`이면 `users_total_games_nonneg`와 `users_record_within_total`이 함께 깨져 DB가 후자를 보고했다. 이 한 건은 제약 이름을 단정하지 않고 CHECK 위반(`23514`)만 확인하도록 고쳤다.
- 수정 뒤 `npm test`: 2개 파일 20건 통과(DB 테스트 11건 포함). 실행 뒤 `alkkagi_test_%` 데이터베이스가 0개임을 확인했다.
- 생성된 SQL에 `CREATE UNIQUE INDEX "users_nickname_lower_idx" ... (lower("nickname"))`가 있고, Neon에서 `pg_indexes`로 `lower((nickname)::text)` 유니크 인덱스를 확인했다.
- `session` 테이블: connect-pg-simple 10.0.0 패키지의 `table.sql`(`sid` varchar PK, `sess` json, `expire` timestamp(6), `IDX_session_expire`)과 컬럼 이름·타입·널 여부·정밀도·PK 이름·인덱스가 같음을 `information_schema`로 확인했다. 차이: `sid`의 `COLLATE "default"`는 DB 기본 콜레이션과 같아 생략했다.

### 한계·미검증

- 마이그레이션 실행기(`db:migrate`)를 개발 DB의 `public` 스키마에 직접 실행하지 않았다. 검증은 임시 DB에서 `runMigrations`를 호출해 했다.
- connect-pg-simple을 실제로 연결해 세션을 읽고 쓰는 동작, 기본 만료(24시간)와 만료 행 정리 기능은 확인하지 않았다. 의존성에도 추가하지 않았다(IMPL-007에서 확인).
- 풀의 유휴 연결이 실제로 닫히는지, Neon 컴퓨트가 5분 뒤 중지되는지, CU-hour 사용량은 측정하지 않았다.
- 같은 사용자가 방을 동시에 만드는 경합과 입장 동시성(`UPDATE ... WHERE guest_id IS NULL`)은 IMPL-008의 범위라 검증하지 않았다.
- 테스트는 Neon 한 곳에서 한 번 통과했다. 반복 실행이나 다른 PostgreSQL 버전에서는 확인하지 않았다.
- `pg`가 연결 문자열의 `sslmode=require`에 대해 "`verify-full`의 별칭으로 취급하며 다음 메이저 버전(pg v9)에서 의미가 바뀐다"는 경고를 냈다. 현재 연결에는 문제가 없었다.

### 문서 대조·후속 작업

- DATABASE의 컬럼·제약·인덱스·마이그레이션 원칙과 구현이 일치한다. 제약 이름은 DATABASE에 명시돼 있지 않아 구현에서 정했고(`rooms_host_id_unique` 등), 리뷰 요청에 따라 [DATABASE](../design/DATABASE.md#rooms)에 계약으로 추가했다.
- DATABASE의 "현재 구현: 없음"과 미정 사항의 "`lower(nickname)` 인덱스 확인"은 병합 때 갱신한다. TASKS·PROGRESS도 병합 뒤 완료 처리한다.
- 참고(IMPL-007에서 확인할 값): connect-pg-simple 10.0.0 README상 `ttl` 기본값은 쿠키에 `maxAge`가 없으면 1일, `pruneSessionInterval` 기본값은 900초(15분)이다. [AUTH](../design/AUTH.md#세션)의 "기본 만료 24시간·정리 기능" 확인은 연결해 실제로 보는 것까지 IMPL-007에서 한다.
- 후속: IMPL-007에서 connect-pg-simple 실연결, 배포(IMPL-013)에서 `DATABASE_URL`의 `sslmode`를 명시하는 방안 검토.

## IMPL-007 인증

### 범위와 기준 문서

- 작업: [IMPL-007](../TASKS.md#impl-007-인증)
- 기준: [AUTH](../design/AUTH.md), [API REST](../design/API.md#rest-api)·[오류 형식](../design/API.md#오류-형식과-코드), [로그인](../PRD.md#로그인)·[회원등록](../PRD.md#회원등록)·[캐릭터 변경](../PRD.md#캐릭터-변경), [DEC-025·028](../DECISIONS.md#결정-색인)
- 범위: 가입·로그인·로그아웃·`GET /api/me`·비밀번호 변경·캐릭터 변경 API, 세션, IP당 요청 빈도 제한, argon2id 해시, Socket.IO 연결 인증·중복 접속 대체. 기권 명령 변환은 IMPL-009, `rooms` 정리·`/health`·정적 파일은 IMPL-008·013이다.

### 작업·검증 조건

- 브랜치: `feat/impl-007-auth`(IMPL-006 병합 뒤 `main`에서 분기). 이 브랜치 하나에서 구현·문서·완료 처리까지 한다.
- 환경: Windows 11, Node 24.22.0. 통합 테스트는 IMPL-006과 같은 방식으로 Neon 개발 프로젝트에 임시 데이터베이스를 만들어 마이그레이션을 적용하고 지운다. 개발 DB(`neondb`)에는 마이그레이션을 적용하지 않았다.
- 추가한 라이브러리(정확한 버전 고정): `express` 5.3.0, `express-session` 1.19.0, `connect-pg-simple` 10.0.0, `@node-rs/argon2` 2.2.2, `express-rate-limit` 8.7.2, `socket.io` 4.8.4. 개발용: `supertest` 7.3.1, `socket.io-client` 4.8.4, `@types/express` 5.0.6, `@types/express-session` 1.19.0, `@types/connect-pg-simple` 7.0.3, `@types/supertest` 7.2.1.
- 테스트 입력: 통합 테스트는 테스트마다 다른 IP(`X-Forwarded-For`, `trust proxy 1`)로 요청해 IP당 빈도 제한 카운터가 섞이지 않게 했다. 해시 측정은 30회 반복, 워밍업 1회 제외.

### 수행과 관찰

변경:

- `packages/shared/src/auth.ts`(+`auth.test.ts`): 가입·로그인·비밀번호 변경·캐릭터 변경 Zod 스키마, 인증 오류 코드, `Me`·`PlayerRecord`·`CharacterId` 타입. 닉네임은 NFC 정규화 뒤 2~12자 한글·영문·숫자, 비밀번호는 8~64자. `protocol.ts`(개발자 A 영역)는 건드리지 않았다.
- `packages/server/src`: `config.ts`(환경 변수), `app.ts`(Express·세션·Socket.IO 조립), `auth/`(라우터·비밀번호 해시·세션·빈도 제한·오류 처리·사용자 저장소), `realtime/`(Socket.IO 인증·연결 등록부), `index.ts`(시작·종료).
- 가입은 먼저 조회하지 않고 INSERT가 `users_nickname_lower_idx`에 걸린 것(`23505`)을 `NICKNAME_TAKEN`으로 바꾼다. 없는 닉네임으로 로그인해도 더미 해시를 검증해 닉네임 없음과 비밀번호 틀림을 구분하지 못하게 한다. 로그인 성공 때 세션을 재발급(`regenerate`)한다.
- 비밀번호 변경은 새 해시를 저장한 뒤 `session` 행에서 `sess ->> 'userId'`가 같고 현재가 아닌 행을 삭제하고, 다른 세션에 연결된 소켓에 `session:replaced`를 보내 끊는다. 로그아웃은 그 세션의 소켓을 알림 없이 끊는다(문서에 없던 동작, 경기 중이면 IMPL-009에서 이탈로 처리된다).

실행과 결과:

- `npm run lint`, `npm run build -w @alkkagi/server`·`-w @alkkagi/shared`(타입 검사): 통과.
- `npm test`: 5개 파일 54건 통과(기본 설정, DB 접속 없음).
- `npm run test:db`: 2개 파일 32건 통과(`schema.db.test.ts` 11건 + `auth.db.test.ts` 21건). 오류 수정 없이 처음부터 통과했다.
- 테스트가 실패를 잡는지 확인하려고 `deleteOtherSessions` 호출과 기존 연결 대체를 일부러 지워 실행했다. 비밀번호 변경 테스트와 중복 접속 테스트 2건이 실패했고 원래 코드로 되돌렸다.
- 실제 진입점: `.env`와 임시 `SESSION_SECRET`으로 `index.ts`를 띄워 `GET /api/me`가 `401 UNAUTHENTICATED`, 깨진 JSON 로그인이 `400 INVALID_INPUT`임을 확인하고 종료했다. DB 조회가 필요한 요청은 보내지 않았다.
- argon2id(메모리 19,456KiB, 반복 2, 병렬 1) 해시 시간, 이 PC(Intel Core i5-1335U 12스레드, 32GiB, Node 24.22.0): hash 중앙값 10.9ms·p95 17.2ms, verify 중앙값 10.8ms·p95 15.1ms(30회).
- 세션 기본값: connect-pg-simple 10.0.0 README에서 `ttl` 기본값(쿠키 `maxAge`가 없으면 1일)과 `pruneSessionInterval` 기본값(900초)을 확인했다. 실제 DB에서 로그인 직후 `expire`가 현재보다 약 86,400초 뒤이고, 만료된 행을 넣은 뒤 `pruneSessions`를 호출하면 지워짐을 테스트했다.

### 한계·미검증

- Render 무료 인스턴스에서의 해시 시간은 측정하지 못했다. 이 PC의 약 11ms는 설계 목표(약 100~300ms)와 큰 차이가 있지만 환경이 달라 결론을 내지 않는다. 목표에 못 미치면 IMPL-013에서 메모리·반복을 올린다.
- 개발 DB(`neondb`)에 마이그레이션을 적용하지 않았고 개발 DB로는 가입·로그인을 직접 해 보지 않았다. 임시 DB에서 같은 마이그레이션으로 검증했다.
- 실제 브라우저에서 쿠키가 브라우저 종료 때 사라지는지, 탭 복원 때 어떻게 되는지는 확인하지 않았다. 응답 헤더에 `Max-Age`·`Expires`가 없음만 확인했다.
- 로그인 응답 시간이 닉네임 유무에 따라 같은지는 측정하지 않았다. 더미 해시 검증을 구현했을 뿐이다.
- 세션 재발급(세션 고정 방지)은 구현했지만 전용 테스트는 없다. 로그인 응답의 쿠키 발급만 확인했다.
- 로그인 요청 빈도 제한은 메모리 저장이라 서버가 재시작하면 초기화된다(설계에서 감수한 사항).
- 같은 계정이 여러 브라우저에서 로그인(세션 여러 개)하는 것은 막지 않았고 소켓 연결만 하나로 유지한다. 설계 문서에 세션 개수 제한은 없다.
- `npm audit`에 개발 도구 경고가 있다: `drizzle-kit`이 쓰는 구버전 `esbuild`(개발 서버 요청 노출), `eslint`가 쓰는 `minimatch`(정규식 DoS). 둘 다 `devDependencies`의 도구이고 서버 런타임 번들에는 들어가지 않는다. `npm audit fix --force`는 `drizzle-kit`·`eslint`를 크게 낮추므로 하지 않았다.
- `npm run format` 전체 검사는 이 PC 작업 폴더의 CRLF 줄바꿈 때문에 기존 파일 21개를 지적한다. IMPL-007의 변경 파일은 통과한다.

### 문서 대조·후속 작업

- [AUTH](../design/AUTH.md): 현재 구현 상태, 세션 만료·정리 기본값 확인, 해시 시간 측정 결과와 이관, `SESSION_SECRET` 길이 조건을 반영했다.
- [API](../design/API.md): `shared`의 `PlayerRecord` 이름과 서버 오류 `500 INTERNAL_ERROR` 응답을 추가했다. 이 코드는 구현에서 정했으므로 개발자 A의 확인이 필요하다.
- [TASKS](../TASKS.md): IMPL-013에 "Render에서 해시 시간 측정·파라미터 조정" 수용 기준을 추가했다(IMPL-007에서 이관). 수용 기준 조정에 대한 개발자 A의 확인이 필요하다.
- 후속: [IMPL-008](../TASKS.md#impl-008-로비방-서버)·[IMPL-009](../TASKS.md#impl-009-온라인-대전-서버)가 `ConnectionRegistry`(`realtime/connections.ts`)와 `createRealtime`의 `onConnection`을 확장해 방 이벤트·기권 변환을 붙인다. [IMPL-014](../TASKS.md#impl-014-패키지-의존-경계-린트와-envexample)의 `.env.example`에 `SESSION_SECRET`(32자 이상) 안내가 필요하다. 서버를 직접 띄우려면 로컬 `.env`에 `SESSION_SECRET`을 추가해야 한다.
