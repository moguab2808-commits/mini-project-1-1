# 2026-11-02 작업·검증 기록

## IMPL-006 DB·마이그레이션

### 범위와 기준 문서

- 작업: [IMPL-006](../TASKS.md#impl-006-db마이그레이션)
- 기준: [DATABASE](../design/DATABASE.md)(테이블·제약·세션 테이블·마이그레이션), [OPERATIONS 사용량·부하](../design/OPERATIONS.md#사용량부하-확인)(연결 풀 유휴 시간), [AUTH 세션](../design/AUTH.md#세션), [DEC-022·023·027](../DECISIONS.md#결정-색인)
- 범위: Drizzle 스키마(`users`·`rooms`·`session`), 마이그레이션 파일과 실행기, 연결 풀. 인증·방 API는 IMPL-007·008이다.

### 작업·검증 조건

- 브랜치·변경: `feat/impl-006-db-migration`, 검증 때는 미커밋 변경이었고, 이후 커밋·푸시하고 [PR #54](https://github.com/moguab2808-commits/mini-project-1-1/pull/54)를 만들었다.
- 환경: Windows 11, Node 24.22.0, npm 11.19.1. 검증 DB는 Neon 무료 플랜 PostgreSQL(싱가포르 리전)의 개발용 프로젝트이며 로컬 `.env`의 `DATABASE_URL`로 연결했다(값은 기록하지 않는다). 이 PC에는 psql·Docker가 없다.
- 고정한 라이브러리: `drizzle-orm` 0.45.4, `pg` 8.23.1, `drizzle-kit` 0.31.11, `@types/pg` 8.23.1(정확한 버전, lock 파일 갱신).
- 방식: 테스트가 Neon에 임시 데이터베이스(`alkkagi_test_<무작위>`)를 만들어 마이그레이션을 적용하고 검증한 뒤 `DROP DATABASE`로 지운다. 개발 DB의 `public` 스키마에는 마이그레이션을 적용하지 않았다.

### 수행과 관찰

변경: `packages/server/src/db/{schema,pool,migrate}.ts`, `packages/server/drizzle.config.ts`, 생성된 `packages/server/drizzle/0000_*.sql`, 검증 테스트 `schema.test.ts`, `db:generate`·`db:migrate` 스크립트, vitest가 루트 `.env`를 읽도록 `config/vitest.config.ts` 수정.

실행: `npm run db:generate -w @alkkagi/server`, `npm run format:write`, `npm run lint`, `npm run build -w @alkkagi/server`, `npm test`(DB 테스트 포함 설정). 개발자 A의 리뷰(PR #54)를 반영해 DB 테스트를 `schema.db.test.ts`로 옮기고 `npm run test:db`로만 실행하도록 분리했다. 기본 `npm test`는 `.env`를 읽지 않고 DB에 접속하지 않는다.

- 첫 `npm test`에서 DB 테스트 11건 중 2건이 실패했다. 둘 다 스키마가 아니라 테스트의 오류였다.
  - 인덱스 정의 정규식이 실제 출력 `(lower((nickname)::text))`과 맞지 않았다. 정규식을 고쳤다.
  - `total_games = -1`이면 `users_total_games_nonneg`와 `users_record_within_total`이 함께 깨져 DB가 후자를 보고했다. 이 한 건은 제약 이름을 단정하지 않고 CHECK 위반(`23514`)만 확인하도록 고쳤다.
- 수정 뒤 `npm test`: 2개 파일 20건 통과(DB 테스트 11건 포함). 실행 뒤 `alkkagi_test_%` 데이터베이스가 0개임을 확인했다.
- 생성된 SQL에 `CREATE UNIQUE INDEX "users_nickname_lower_idx" ... (lower("nickname"))`가 있고, Neon에서 `pg_indexes`로 `lower((nickname)::text)` 유니크 인덱스를 확인했다.
- `session` 테이블: connect-pg-simple 10.0.0 패키지의 `table.sql`(`sid` varchar PK, `sess` json, `expire` timestamp(6), `IDX_session_expire`)과 컬럼 이름·타입·널 여부·정밀도·PK 이름·인덱스가 같음을 `information_schema`로 확인했다. 차이: `sid`의 `COLLATE "default"`는 DB 기본 콜레이션과 같아 생략했다.

### 한계·미검증

- 마이그레이션 실행기(`db:migrate`)를 개발 DB의 `public` 스키마에 직접 실행하지 않았다. 검증은 임시 DB에서 `runMigrations`를 호출해 했다.
- connect-pg-simple을 실제로 연결해 세션을 읽고 쓰는 동작, 기본 만료(24시간)와 만료 행 정리 기능은 확인하지 않았다. 의존성에도 추가하지 않았다(IMPL-007에서 확인).
- 풀의 유휴 연결이 실제로 닫히는지, Neon 컴퓨트가 5분 뒤 중지되는지, CU-hour 사용량은 측정하지 않았다.
- 같은 사용자가 방을 동시에 만드는 경합과 입장 동시성(`UPDATE ... WHERE guest_id IS NULL`)은 IMPL-008의 범위라 검증하지 않았다.
- 테스트는 Neon 한 곳에서 한 번 통과했다. 반복 실행이나 다른 PostgreSQL 버전에서는 확인하지 않았다.
- `pg`가 연결 문자열의 `sslmode=require`에 대해 "`verify-full`의 별칭으로 취급하며 다음 메이저 버전(pg v9)에서 의미가 바뀐다"는 경고를 냈다. 현재 연결에는 문제가 없었다.

### 문서 대조·후속 작업

- DATABASE의 컬럼·제약·인덱스·마이그레이션 원칙과 구현이 일치한다. 제약 이름은 DATABASE에 명시돼 있지 않아 구현에서 정했고(`rooms_host_id_unique` 등), 리뷰 요청에 따라 [DATABASE](../design/DATABASE.md#rooms)에 계약으로 추가했다.
- DATABASE의 "현재 구현: 없음"과 미정 사항의 "`lower(nickname)` 인덱스 확인"은 병합 때 갱신한다. TASKS·PROGRESS도 병합 뒤 완료 처리한다.
- 참고(IMPL-007에서 확인할 값): connect-pg-simple 10.0.0 README상 `ttl` 기본값은 쿠키에 `maxAge`가 없으면 1일, `pruneSessionInterval` 기본값은 900초(15분)이다. [AUTH](../design/AUTH.md#세션)의 "기본 만료 24시간·정리 기능" 확인은 연결해 실제로 보는 것까지 IMPL-007에서 한다.
- 후속: IMPL-007에서 connect-pg-simple 실연결, 배포(IMPL-013)에서 `DATABASE_URL`의 `sslmode`를 명시하는 방안 검토.

## IMPL-007 인증

### 범위와 기준 문서

- 기준: [AUTH](../design/AUTH.md), [API REST](../design/API.md#rest-api)·[오류 형식](../design/API.md#오류-형식과-코드), [로그인](../PRD.md#로그인)·[회원등록](../PRD.md#회원등록)·[캐릭터 변경](../PRD.md#캐릭터-변경), [DEC-025·028](../DECISIONS.md#결정-색인)
- 범위: 가입·로그인·로그아웃·`GET /api/me`·비밀번호 변경·캐릭터 변경 API, 세션, IP당 요청 빈도 제한, argon2id 해시, Socket.IO 연결 인증·중복 접속 대체. 기권 명령 변환은 IMPL-009, `rooms` 정리·`/health`·정적 파일은 IMPL-008·013이다.

### 작업·검증 조건

- 브랜치: `feat/impl-007-auth`(IMPL-006 병합 뒤 `main`에서 분기). 이 브랜치 하나에서 구현·문서·완료 처리까지 한다.
- 환경: Windows 11, Node 24.22.0. 통합 테스트는 IMPL-006과 같은 방식으로 Neon 개발 프로젝트에 임시 데이터베이스를 만들어 마이그레이션을 적용하고 지운다. 개발 DB(`neondb`)에는 마이그레이션을 적용하지 않았다.
- 추가한 라이브러리(정확한 버전 고정): `express` 5.3.0, `express-session` 1.19.0, `connect-pg-simple` 10.0.0, `@node-rs/argon2` 2.2.2, `express-rate-limit` 8.7.2, `socket.io` 4.8.4. 개발용: `supertest` 7.3.1, `socket.io-client` 4.8.4, `@types/express` 5.0.6, `@types/express-session` 1.19.0, `@types/connect-pg-simple` 7.0.3, `@types/supertest` 7.2.1.
- 테스트 입력: 통합 테스트는 테스트마다 다른 IP(`X-Forwarded-For`, `trust proxy 1`)로 요청해 IP당 빈도 제한 카운터가 섞이지 않게 했다. 해시 측정은 30회 반복, 워밍업 1회 제외.

### 수행과 관찰

변경:

- `packages/shared/src/auth.ts`(+`auth.test.ts`): 가입·로그인·비밀번호 변경·캐릭터 변경 Zod 스키마, 인증 오류 코드, `Me`·`PlayerRecord`·`CharacterId` 타입. 닉네임은 NFC 정규화 뒤 2~12자 한글·영문·숫자, 비밀번호는 8~64자. `protocol.ts`(개발자 A 영역)는 건드리지 않았다.
- `packages/server/src`: `config.ts`(환경 변수), `app.ts`(Express·세션·Socket.IO 조립), `auth/`(라우터·비밀번호 해시·세션·빈도 제한·오류 처리·사용자 저장소), `realtime/`(Socket.IO 인증·연결 등록부), `index.ts`(시작·종료).
- 가입은 먼저 조회하지 않고 INSERT가 `users_nickname_lower_idx`에 걸린 것(`23505`)을 `NICKNAME_TAKEN`으로 바꾼다. 없는 닉네임으로 로그인해도 더미 해시를 검증해 닉네임 없음과 비밀번호 틀림을 구분하지 못하게 한다. 로그인 성공 때 세션을 재발급(`regenerate`)한다.
- 비밀번호 변경은 새 해시를 저장한 뒤 `session` 행에서 `sess ->> 'userId'`가 같고 현재가 아닌 행을 삭제하고, 다른 세션에 연결된 소켓에 `session:replaced`를 보내 끊는다. 로그아웃은 그 세션의 소켓을 알림 없이 끊는다(문서에 없던 동작, 경기 중이면 IMPL-009에서 이탈로 처리된다).

실행과 결과:

- `npm run lint`, `npm run build -w @alkkagi/server`·`-w @alkkagi/shared`(타입 검사): 통과.
- `npm test`: 5개 파일 54건 통과(기본 설정, DB 접속 없음).
- `npm run test:db`: 2개 파일 32건 통과(`schema.db.test.ts` 11건 + `auth.db.test.ts` 21건). 오류 수정 없이 처음부터 통과했다.
- 테스트가 실패를 잡는지 확인하려고 `deleteOtherSessions` 호출과 기존 연결 대체를 일부러 지워 실행했다. 비밀번호 변경 테스트와 중복 접속 테스트 2건이 실패했고 원래 코드로 되돌렸다.
- 실제 진입점: `.env`와 임시 `SESSION_SECRET`으로 `index.ts`를 띄워 `GET /api/me`가 `401 UNAUTHENTICATED`, 깨진 JSON 로그인이 `400 INVALID_INPUT`임을 확인하고 종료했다. DB 조회가 필요한 요청은 보내지 않았다.
- argon2id(메모리 19,456KiB, 반복 2, 병렬 1) 해시 시간, 이 PC(Intel Core i5-1335U 12스레드, 32GiB, Node 24.22.0): hash 중앙값 10.9ms·p95 17.2ms, verify 중앙값 10.8ms·p95 15.1ms(30회).
- 세션 기본값: connect-pg-simple 10.0.0 README에서 `ttl` 기본값(쿠키 `maxAge`가 없으면 1일)과 `pruneSessionInterval` 기본값(900초)을 확인했다. 실제 DB에서 로그인 직후 `expire`가 현재보다 약 86,400초 뒤이고, 만료된 행을 넣은 뒤 `pruneSessions`를 호출하면 지워짐을 테스트했다.

### 한계·미검증

- Render 무료 인스턴스에서의 해시 시간은 측정하지 못했다. 이 PC의 약 11ms는 설계 목표(약 100~300ms)와 큰 차이가 있지만 환경이 달라 결론을 내지 않는다. 목표에 못 미치면 IMPL-013에서 메모리·반복을 올린다.
- 개발 DB(`neondb`)에 마이그레이션을 적용하지 않았고 개발 DB로는 가입·로그인을 직접 해 보지 않았다. 임시 DB에서 같은 마이그레이션으로 검증했다.
- 실제 브라우저에서 쿠키가 브라우저 종료 때 사라지는지, 탭 복원 때 어떻게 되는지는 확인하지 않았다. 응답 헤더에 `Max-Age`·`Expires`가 없음만 확인했다.
- 로그인 응답 시간이 닉네임 유무에 따라 같은지는 측정하지 않았다. 더미 해시 검증을 구현했을 뿐이다.
- 세션 재발급(세션 고정 방지)은 구현했지만 전용 테스트는 없다. 로그인 응답의 쿠키 발급만 확인했다.
- 로그인 요청 빈도 제한은 메모리 저장이라 서버가 재시작하면 초기화된다(설계에서 감수한 사항).
- 같은 계정이 여러 브라우저에서 로그인(세션 여러 개)하는 것은 막지 않았고 소켓 연결만 하나로 유지한다. 설계 문서에 세션 개수 제한은 없다.
- `npm audit`에 개발 도구 경고가 있다: `drizzle-kit`이 쓰는 구버전 `esbuild`(개발 서버 요청 노출), `eslint`가 쓰는 `minimatch`(정규식 DoS). 둘 다 `devDependencies`의 도구이고 서버 런타임 번들에는 들어가지 않는다. `npm audit fix --force`는 `drizzle-kit`·`eslint`를 크게 낮추므로 하지 않았다.
- `npm run format` 전체 검사는 이 PC 작업 폴더의 CRLF 줄바꿈 때문에 기존 파일 21개를 지적한다. IMPL-007의 변경 파일은 통과한다.

### 리뷰 반영 (PR #59)

개발자 A가 병합 전 정리 2건과 문서·사소한 점을 요청했다. 같은 브랜치에 커밋을 추가해 반영했다.

- 비밀번호 변경: 새 비밀번호 저장과 다른 세션 삭제를 한 DB 트랜잭션으로 묶고 연결 끊기는 커밋 뒤에 한다. 중간 실패를 일으키는 테스트는 만들지 않았고 코드 검토로만 확인했다.
- 문서: API에 로그아웃으로 끊긴 연결은 `session:replaced` 없이 `disconnect`만 받는다는 구분을, AUTH에 연결 등록부·빈도 제한의 단일 인스턴스 전제를 적었다.
- 후속(이번 PR 범위 밖): `PATCH /api/me/password`는 인증된 사용자가 argon2 검증을 반복 호출할 수 있는데 빈도 제한이 `/api/auth/*`에만 있다. 설계(AUTH)가 제한 대상을 `/api/auth/*`로 정해 두어 추가하면 계약 변경이므로 후속으로 남긴다.

## IMPL-003 `game-runtime`

### 범위와 기준 문서

- 작업: [IMPL-003](../TASKS.md#impl-003-game-runtime), 담당 개발자 A
- 기준: [GAME 명령 경합과 시간](../design/GAME.md#명령-경합과-시간)·[구현 경계](../design/GAME.md#구현-경계-ab)·[전송·실행 초기값](../design/GAME.md#전송실행), [OPERATIONS 서버 로그](../design/OPERATIONS.md#서버-로그), [LOCAL `GameSession`](../design/LOCAL.md#gamesession-시그니처)

### 작업·검증 조건

- 브랜치: `feat/impl-003-game-runtime`. 환경: WSL2 Linux, Node 24 계열. DB·네트워크는 쓰지 않는다. 시계·전송은 테스트용 가짜 구현이다.
- 변경: `packages/game-runtime/src/{types,room-runtime,index}.ts`, 테스트 `room-runtime.test.ts`, `tsconfig.json`에 `types: ["node"]`(테스트의 `node:assert` 때문, `game-core`와 같음).
- 실행: `npm ci` 뒤 `npm test`(5개 파일 60건 통과, 이 중 runtime 16건), `npm run lint`·`npm run build` 통과, `prettier --check` 통과. DB 테스트는 `DATABASE_URL`이 없어 건너뛴다.

### 수행과 관찰

- `RoomRuntime`이 방 하나의 단일 큐(`ingressSeq`는 경기가 바뀌어도 이어짐), 120Hz 고정 틱 스케줄러, 플레이어별 `game:state` 배포를 맡는다. `Game`(game-core)은 그대로 두고 감쌌다.
- 테스트로 확인한 것: 좌석별 `game:start`·본인에게만 가는 `hazard:granted`, 같은 틱 명령의 `ingressSeq` 순서(두 순서 모두), 이동 중 volatile 스냅샷(초당 30회 이하)과 정지 뒤 신뢰 전송 최종 스냅샷·`revision` 비감소, 5초 지연 때 `tick_skipped` 1건과 경기 시각 지연, 거부 명령의 순번 소비, 동시 이탈 시 먼저 관찰된 쪽 기권패와 두 번째 `GAME_NOT_ACTIVE`, 종료 뒤 틱 정지, 경기 없을 때 `GAME_NOT_ACTIVE`.

### 리뷰 반영 (PR #57)

- 틱 루프: 전송·`onFinished`·로거 오류를 각각 잡아 `onError`로 보고하고, 틱 본문 오류도 `finally`에서 다음 틱을 예약한다. 처리 중이던 대기 명령은 `GAME_NOT_ACTIVE`로 끝낸다.
- `dispose()` 뒤에는 `closed`로 명령을 거부하고 `isRunning`은 false, `startGame`은 던진다. `startGame`이 비우는 대기 명령도 `GAME_NOT_ACTIVE`로 끝낸다.
- 재대결 마감 시각은 종료 때 한 번만 정해 `game:over`·`game:state`가 같은 값을 쓴다.
- 전송 여부는 `Game.meta()`(tick·revision·phase)로 먼저 가려 이벤트 없이 revision만 오른 상태도 보내고, 뷰는 보낼 때만 만든다(틱당 `getViewFor` 낭비 제거). `game-core`에 `meta()`를 추가했다.
- 테스트 4건 추가: 전송·콜백 오류 뒤 루프 지속, `dispose` 뒤 거부, 마감 시각 고정, revision만 오른 상태 전송(대역 `Game` 사용: 현재 `game-core`에는 이벤트 없는 revision 변경 경로가 이동 중 외에는 없다).
- 반영하지 않은 것: 스키마 거부된 발사도 `shot` 이벤트에 `INVALID_INPUT`으로 남기고 `leave`·`forfeit`은 따로 남긴다. OPERATIONS가 판정 결과를 `result`로 구분하므로 소비자가 `result`로 거른다. 바꿀지는 IMPL-009 때 B와 정한다.

### 인터페이스 합의 반영 (PR #57)

- B의 답변으로 맞춘 것: `LeaveReason`을 OPERATIONS와 같은 `disconnect`·`leave_button`·`session_replaced`로 바꾸고 로그의 `reason` 필드에 넣는다. `start_commit`과 `leave`가 같은 `ingressSeq` 순번 공간을 쓴다(경기 없는 `leave`도 순번을 쓰고 `gameId`는 null, `leave` 한 번이 순번 하나만 소비하며 `forfeit` 로그가 같은 순번을 이어 씀). `forfeit` 로그에 `reason`(`leave`·`command`, 연속 시간초과는 `timeout`)을 남긴다. `RuntimeClock.now()`가 epoch 기준 단조 시각이어야 한다는 점을 `types.ts` 주석에 적었다.
- 테스트 2건 추가(순번 공간·`reason`·`forfeit` 사유), 기존 순번 기대값을 시작 커밋이 순번 0을 쓰도록 고쳤다. `npm test` 58건(runtime 14건), `lint`·`build` 통과.
- 연속 시간초과 `forfeit`(`reason: timeout`) 로그를 가짜 시계 테스트로 확인했다(7턴 안에 `forfeit`→`game_over` 순서로 한 번씩 기록).
- 실제 `setTimeout`·`performance` 시계 테스트 1건을 추가했다(무부하·WSL2·한 PC). 발사 ack, 이동 중 volatile 스냅샷, 정지 뒤 신뢰 전송 최종 스냅샷, 턴 전환이 동작했고 `tick_skipped`는 0건이었다. 5회 반복에서 모두 통과했다. 한 번의 출력은 발사 ack 9.8ms, 스냅샷 27개, 이벤트 루프 지연 p99 6.3ms·max 6.4ms였다. 이 지연값은 `monitorEventLoopDelay` 해상도(5ms)를 포함하므로 실제 초과 지연은 약 1~2ms 수준이며, 방 1개·무부하 측정이라 서버 부하 기준선이 아니다(동시 방 수별 측정은 OPS-001).
- 합의 결과 전문은 TASKS IMPL-003 절에 남겼다.

### 한계·미검증

- 긴 정지 뒤 큐의 명령은 버린 시간(최대 한 번에 250ms 이내로 제한된 보정)을 포함한 경기 시각으로 판정된다. 마감 직전 발사가 시간초과로 처리될 수 있으며 catch-up 한도로 영향을 제한한 절충이다.
- 인터페이스 형태는 B와 합의하지 않았다(TASKS 범위의 조건). 합의 전에는 병합하지 않는다.
- Socket.IO·워커 연결은 없다(서버 의존성이 아직 없고 IMPL-009·IMPL-004 소관). 실제 시계 검증은 위 한 건뿐이며 서버 부하 상태의 타이머 오차는 측정하지 않았다.
- 틱당 비용(`meta()` 호출·뷰 생성 횟수)은 측정하지 않았다(성능은 OPS-001 부하 측정에서).
- 거부된 명령이 상태를 바꾸지 않는다는 것은 `game-core` 테스트가 확인한다. 런타임 테스트는 순번 소비와 결과 코드만 본다.
- 재도전 성립 로직(`rematch:*`)과 `GameSession` 어댑터는 이 작업 범위가 아니다. `rematchWindowMs`로 `game:over`의 마감 시각만 채운다.
- 병합된 `main`을 받은 직후 `npm run build`는 `packages/server`의 `drizzle-orm`·`pg`를 찾지 못해 실패했다. `npm ci` 뒤에는 오류 없이 통과했다(원인은 이 PC의 미설치 의존성이었고 코드 문제가 아니다).

### 후속

- 인터페이스 초안을 B와 합의하고 결과를 TASKS에 남긴다. 커밋·PR(`Closes #37`은 합의 뒤).

- `local-worker.ts`(SharedWorker 진입점), `local-game-session.ts`(창 쪽 세션, ack 짝짓기·하트비트·`dispose`), `messages.ts`.
- `shared`에 `RematchStateSchema`·`RematchRequestSchema`, 오류 코드 `REMATCH_NOT_AVAILABLE`을 추가했다(둘 다 [API](../design/API.md)에 이미 있는 계약).

### 검증

- 실제 `MessageChannel` 포트와 가짜 시계로 8건: 두 창 시작·좌석별 `game:start`, 같은 좌석 거부, 상대 턴 발사 `NOT_YOUR_TURN`·정상 발사 후 양쪽 `game:state`·`turn:change`, `bye` 기권패와 재접속 거부, 하트비트 끊김 기권패, 재도전 성립, 15초 만료, 두 창 모두 닫힌 뒤 재시작. `npm test` 68건, `lint`·`format`·`build` 통과.

### 한계·미검증

- 실제 `SharedWorker`·브라우저 `pagehide` 연결, `/local` 경로, 3D 화면, 방해요소 입력은 없다(IMPL-004 다음 단계). 방해요소 사용 경로의 권한 측 테스트도 화면 단계에서 함께 본다.

## IMPL-004 추가 조작·시선·반응형 검증

사용자 추가 요청(DEC-037)에 따라 범위 복귀 취소를 오른쪽 클릭 취소로 대체했다. 프로필 흑·백 표시, 기본 세기 왕복 1초, 보유 중 막대 가속 상시 적용, 책상 흔들기 지급 제외, 상대 턴 판 돌리기 방해요소와 방향 선택을 반영했다. 손 당김은 세기와 분리해 마우스 거리로 전달한다. 1인칭 실제 카메라 방향을 좌석 로컬 시선으로 변환해 기존 20Hz 몸짓 경로로 중계하고 임의 고개 들기 동작은 제거했다. HUD는 고정 최소 크기를 제거하고 작은 창·짧은 가로 창에 맞춰 재배치했다.

검증: 전체 17개 테스트 파일·246개 테스트 통과. 이전 기록의 27개 실패는 새 입력·피로도 계약으로 수정했고 새 조건도 추가 검증했다. client build 통과(번들 크기 경고 유지), lint 통과, diff 공백 검사 통과. Chromium 두 창에서 좌석별 흑·백 프로필 대응과 1280×720, 800×600, 390×844, 844×390 레이아웃을 확인했다. 초기 검증에서 발견한 시선 벡터 타입 오류·뷰포트 8px 넘침·가로 창 버튼 겹침을 수정한 뒤 브라우저 오류 0건을 확인했다. 스크린샷과 브라우저 검증 스크립트는 `/tmp/alkkagi-*`에 보관했다.

한계: headless Linux에 한글 글꼴이 없어 스크린샷의 일부 문자가 네모로 보인다. 터치 전용 조작은 이번 범위에 포함하지 않았고, 반응형은 창 크기 대응이다. 사람의 두 창 실플레이 감각·성능 기준선은 측정하지 않았다. DB 검증은 변경 범위 밖이다. 커밋·PR·병합하지 않았다.

## IMPL-004 화면·시점·바람·기절 수정 (DEC-038)

사용자 요청([DEC-038](../DECISIONS.md#결정-색인))으로 알 위 별·가위표 무늬를 없애고 프로필의 흑·백 글자 대신 프로필 옆에 해당 색 알을 크게 그렸다. 시점은 기본·1인칭만 남기고 시점 버튼·숫자 키·휠을 없앴다. 알을 조준·발사하는 동안만 1인칭이 되고, 오른쪽 드래그는 두 시점 모두 고개 돌리기이며 놓으면 정면(기본)으로 돌아온다. 장면 배경·벽·조명을 밝게 했다. 바람은 지급 때 상시 효과를 만들고 2~4초마다 방향을 바꾸며 조준 편향은 초당 30°(제안값)로 낮췄다. 기절은 대상 캐릭터 머리 위에 별 5개가 돌고, 기절한 플레이어 화면이 지속 시간 동안 한 바퀴 돈다. 개발 하네스에 `stun=0|1` 쿼리를 추가했다.

오른쪽 클릭 취소가 안 되던 원인: 왼쪽 버튼을 누른 채 오른쪽을 누르면 브라우저는 `pointerdown`이 아니라 `pointermove`(`button`=2, `buttons`에 2 포함)만 보낸다. 장면이 `pointerdown`만 오른쪽 입력으로 처리해 취소가 전달되지 않았다. 버튼 조합 변경 `pointermove`를 오른쪽 down·up(및 왼쪽 down·up)으로 바꿔 전달하도록 고쳤다.

검증: `npm test` 17개 파일·244개 테스트 통과(시점 버튼·숫자 키·자유 회전 테스트를 제거하고 고개 돌리기 복귀·기절 회전·바람 상시·교체 해제 테스트를 추가, 바람 편향 기대값을 초당 30°로 갱신). `npm run lint` 통과, client build 통과(기존 번들 크기 경고). Chromium headless 두 창(1280×720)에서 시점 버튼 0개, 프로필 알 그림(좌석 0 흑·좌석 1 백), 무늬 없는 알, 오른쪽 드래그 둘러보기와 놓은 뒤 기본 복귀, 왼쪽 누른 채 오른쪽 클릭 시 `aim:update` mode가 `charge`→`idle`로 바뀌고 `shot:submit`이 보내지지 않음, 조준 중 1인칭 전환, 바람 화살표 표시를 확인했다. 하네스에서 상대 기절 별과 내 기절 화면 회전을 확인했다. 브라우저 오류 0건.

한계: 사람의 실제 두 창 플레이 감각(바람 세기·변경 간격, 화면 회전의 어지러움 정도)은 확인하지 않았다. 바람 방향 변경은 `hazard:triggered`를 다시 보내지 않고 뷰 효과 파라미터로만 알린다(API 문서의 이벤트 목록은 그대로). headless 환경이라 fps는 측정하지 않았다. 커밋·PR·병합하지 않았다.

## IMPL-004 PR #60 리뷰 반영

### 수행과 관찰

변경:

- `packages/shared/src/rooms.ts`(+`rooms.test.ts`): 방 생성·입장 입력, `RoomState`·`RoomSummary`·`RoomClosed`, 방 오류 코드, 방 코드 형식(6자리, 0/O·1/I 제외). `protocol.ts`(개발자 A 영역)는 건드리지 않았다.

- 입장은 `UPDATE ... SET guest_id, status = 'playing' WHERE id AND guest_id IS NULL AND status = 'waiting' RETURNING`이다. 입장과 시작이 한 문장이라 `guest_id`는 채워졌는데 `waiting`인 중간 상태가 없다. 0행이면 방을 다시 읽어 `ROOM_NOT_FOUND`·`ROOM_PLAYING`으로 가른다. 즉시 참가는 `FOR UPDATE SKIP LOCKED` 서브쿼리로 무작위 공개·대기 방 하나를 한 문장에서 채운다. 제약 위반은 이름으로 구분해 `ALREADY_IN_ROOM`·`CODE_TAKEN`으로 바꾼다.
- 입장에 성공하면 양쪽에 `room:state`(`playing`)를 보낸 뒤 `RoomHooks.onStarted`를 부른다. 경기 서버(IMPL-009)가 여기서 경기를 연다.
- 없앤 것: `room:start`와 오류 코드 `ROOM_FULL`·`NOT_IN_ROOM`·`NOT_HOST`·`ROOM_NOT_READY`(상대가 있는 방은 항상 게임 중이라 이미 찬 방은 `ROOM_PLAYING`이다).
- 한 사용자가 방장이면서 다른 방의 참여자가 되는 것은 DB 제약(`host_id`·`guest_id` 각각 유니크)만으로는 막히지 않아 생성·입장 전에 서버가 확인한다. 같은 사용자의 방 명령은 한 줄로 세워 이 확인과 쓰기 사이에 다른 명령이 끼어들지 못하게 했다.

### 한계·미검증

- 서버 시작 때 정리하는 호출(`index.ts`의 `clearRooms`)은 빌드로 타입만 확인했고 실제 진입점을 띄워 보지 않았다. 개발 DB에는 마이그레이션을 적용하지 않아 `rooms` 테이블이 없다. 테스트는 같은 함수를 직접 호출해 행이 지워짐을 확인했다.
- 한 프로세스를 가정한다. 같은 사용자의 명령을 한 줄로 세우는 잠금과 `room:join` 빈도 제한 카운터는 메모리에 있어 서버를 여러 대로 늘리면 달라진다(Render 무료 한 대 기준).
- 동시 입장은 두 사용자 한 쌍으로만 확인했다. 더 많은 사용자의 경합과 부하는 측정하지 않았다.
- 입장에 성공한 뒤 `onStarted` 훅이 실패하면 입장은 이미 DB에 반영된 상태에서 입장자의 ack가 `INTERNAL_ERROR`가 된다. 지금은 훅이 없어(IMPL-009가 연결) 이 경로를 확인하지 않았다.
- 경기 중 이탈(`status`가 `playing`일 때 퇴장·끊김)의 기권패 전적 저장은 없다. 지금은 방장이면 방 삭제, 참여자면 자리 비움과 `waiting` 복귀만 한다. 순서(전적 저장을 먼저 끝낸 뒤 방 정리)는 IMPL-009가 `RoomService.leave` 앞에 끼워 넣는다.
- 재도전 15초 만료 처리는 구현하지 않았다(IMPL-009). 규칙은 개발자 B가 상황별 예시로 정해 줬다: 재도전하기를 누르지 않은 쪽은 나가기와 같게 처리하고, 방장이 누르지 않았으면 방이 닫히며, 방장만 눌렀으면 상대만 나가 방장이 대기한다([DEC-041](../DECISIONS.md#결정-색인)). IMPL-008의 `RoomService.leave`가 이 두 경우(방장 이탈=방 삭제·`room:closed`, 참여자 이탈=자리 비움·`room:state`)를 이미 처리하며 해당 동작은 퇴장 테스트로 확인했다. 만료 타이머와 "누르지 않은 쪽" 판정은 확인하지 않았다. 두 사람이 모두 누르지 않은 경우는 방장 기준으로 방이 닫히는 해석이며 개발자 A의 확인이 필요하다.
- 같은 계정 새 연결 처리: 옛 연결이 끊기며 방에서 나간 것으로 처리된다(새로고침하면 방장은 방이 닫히고 참여자는 자리가 빈다). 새 연결이 먼저 방 명령을 보내도 같은 사용자 명령 줄에 서므로 옛 연결의 정리가 먼저 끝난다. 이 순서는 별도 테스트하지 않았다.
- `.env`의 `DATABASE_URL`로 접속하는 `pg`의 `sslmode` 경고(IMPL-006 기록과 같음)가 계속 나온다.
- 카운트다운은 서버에도 화면에도 두지 않기로 했다. 입장 직후의 화면 전환은 IMPL-012·010 범위다.

### 문서 대조·후속 작업

- [DECISIONS](../DECISIONS.md): DEC-041(재도전 15초 만료는 누르지 않은 쪽을 나가기와 같게 처리)도 추가했다. DEC-040(입장 즉시 시작, `room:start` 삭제)을 추가했다. 동의 근거는 개발자 B의 전달이며 개발자 A의 문서 확인은 PR 리뷰에서 받는다.
- [PRD](../PRD.md#대기실): 대기실의 시작 버튼·"자동 시작 안 함"을 입장 즉시 시작으로 바꾸고 `ROOM-JOIN` 예시를 고쳤다. [게임 화면](../PRD.md#게임-화면)의 재도전에는 15초 만료 규칙과 상황별 결과 표를 추가했다.
- [API](../design/API.md): `room:start` 이벤트·오류 코드 4종 삭제, `room:join`·`quickJoin`·`room:state` 설명과 이벤트 순서도·순서 규칙 2를 고쳤고, 구현에서 정한 세부(형식이 틀린 코드의 `INVALID_CODE`, 소켓 ack의 `INTERNAL_ERROR`, 끊김 처리, 목록 정렬)를 방 이벤트 절에 적었다. 개발자 A의 확인이 필요하다.
- [DATABASE](../design/DATABASE.md): 입장·시작 커밋 행과 입장 동시성 설명을 고치고 재도전 만료 행을 DEC-041에 맞췄다. 방 생명주기의 나머지(참여자·방장 퇴장, 서버 시작 정리)는 구현과 일치한다.
- [GAME](../design/GAME.md): 시작 커밋을 "상대 입장"으로 고쳤다. 방 큐에 입장을 올리는 방법과 `ingressSeq` 순번은 IMPL-009에서 정한다. 상태 표·상태도의 재도전 만료 행은 DEC-041에 맞춰 "누르지 않은 쪽은 이탈 처리"로 고쳤다.
- [TASKS](../TASKS.md)·[PROGRESS](../PROGRESS.md): IMPL-008 범위·수용 기준을 입장 즉시 시작에 맞춰 고치고 완료로 반영했다. IMPL-009에 이어받을 일(시작 훅, 이탈 기권패, 재도전 만료 결정)을 적었다. PR 번호는 PR 생성 뒤 TASKS의 Issue·PR 줄과 PROGRESS에 넣는다.
- 후속: [IMPL-009](../TASKS.md#impl-009-온라인-대전-서버)가 `RoomHooks.onStarted`(경기 시작)와 `RoomService.leave` 앞(기권패 저장)을 이어받고 DEC-041의 재도전 만료 처리를 구현한다. [IMPL-012](../TASKS.md#impl-012-계정로비대기실결과-화면)가 쓸 ack·이벤트 형태는 `shared/src/rooms.ts`다.
