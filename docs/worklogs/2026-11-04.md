## IMPL-016 자석 블랙홀식 흡입 (DEC-068)

### 범위와 기준 문서

- 작업: [IMPL-016 자석 블랙홀식 흡입 절](../TASKS.md#impl-016-자석-블랙홀식-흡입-dec-068)
- 결정: [DEC-068](../DECISIONS.md#결정-색인)([DEC-067](../DECISIONS.md#결정-색인)의 자석 가속 대체)
- 요구사항·설계: [PRD 추가 방해요소 10종](../PRD.md#추가-방해요소-10종-dec-055)·[GAME 추가 10종](../design/GAME.md#추가-방해요소-10종과-턴-교체-haz-001)
- 비교 기준: 변경 전 자석은 반지름 8.8cm 안의 움직이는 지면 알·떠 있는 알에 중심 쪽 540 cm/s² 가속만 더해, 알이 휘어 지나가거나 중심을 지나쳤다.

### 작업·검증 조건

- 브랜치 `feature/local-ai-completion`(PR #84에 추가).
- 사용자 요청: "자석의 세기가 너무 약해 블랙홀처럼 범위내에 닿기만 하면 블랙홀처럼 끌어오게 변경할거야 수치만 변경해줘 테스트나 검증은 하지 말고" → 수치(540 → 5400)만 변경. 이어 "그냥 수치를 바꾸는게 아니라 중앙으로 끌려오게 코드를 변경해줘 테스트나 검증은 하지마" → 흡입 코드로 변경.

### 수행과 관찰

- `packages/shared/src/constants.ts`: `magnetAccel` 540 → 5400, `magnetTangentDamping` 12 추가.
- `packages/game-core/src/physics.ts` 자석 처리: 범위 안 알의 속도를 중심 쪽 성분(바깥 방향은 0으로, 그 뒤 `magnetAccel·DT` 더함)과 수직 성분(`1 − magnetTangentDamping·DT` 배)으로 다시 만든다. 중심 쪽 성분으로 이번 스텝에 중심에 닿거나 지나치면 알을 중심 좌표에 놓고 수평 속도를 0으로 한다. 적용 대상(움직이는 지면 알·떠 있는 알)은 그대로다.
- 판정: 사용자가 변경 결과를 보고 "괜찮네"라고 확인했다. 사용자가 확인한 실행 경로·절차의 상세는 전달받지 않았다.

### 한계·미검증

- 사용자 요청에 따라 Claude는 이 변경 뒤 테스트·빌드·타입 검사·브라우저 확인을 실행하지 않았다.
- 이전 자석 동작(540 cm/s² 휘어짐)을 전제로 한 자동 테스트(예: `packages/game-core/src/hazards-extra.test.ts`)의 통과 여부는 확인하지 않았다. 실패하면 DEC-068 기준으로 기대값을 고친다.
- 알 두 개가 연달아 빨려 들면 나중 알은 중심의 알과 충돌해 그 옆에 멈춘다. 범위 안에 멈춰 있던 알은 끌려오지 않는다.

### 문서 대조·후속 작업

- DECISIONS(DEC-068 추가, DEC-067 일부 대체 표시)·PRD 자석 행·GAME 자석 행·TASKS·CHANGELOG·PROGRESS를 같은 변경에서 갱신했다.
- 수치는 계속 제안값이며 플레이 테스트로 확정한다.

## IMPL-019 공통 기반 첫 PR (theme.css·글꼴·일러스트)

### 범위와 기준 문서

- 작업: [IMPL-019](../TASKS.md#impl-019-l-화풍-화면-적용)의 첫 PR(공통 기반), 결정 [DEC-072](../DECISIONS.md#결정-색인)·[DEC-074](../DECISIONS.md#결정-색인). 화면 적용(로그인·로비·방 생성·대기실 등)은 이 PR에 넣지 않았다.
- 브랜치: `feat/impl-019-foundation`(PR #85 병합 커밋 `56f56f0` 기준)

### 수행

- `packages/client/src/ui/theme.css` 추가: `--l-*` 변수와 `.l-tray`·`.l-well`·`.l-label`·`.l-input`·`.l-btn`(+`-primary`·`-magic`·`-cream`)·`.l-logo`·`.l-ribbon`. 색·그림자 값은 디자인 캔버스 UiL-Login·UiL-Create 보드의 스타일에서 옮겼다. `.l-label`·`.l-input`은 DEC-072 ②의 목록에 없는 추가 클래스다. `app.tsx`에서 `app.css` 앞에 가져온다.
- 글꼴: Fontsource 5.3.0 패키지의 Jua·Black Han Sans woff2(한글·영문 각 1개, 합계 약 585KB)와 OFL 전문을 `packages/client/public/fonts/`에 넣고 `theme.css`의 `@font-face`로 쓴다. CREDITS·TECH_STACK에 기록했다.
- 글꼴 적용 범위: `app.css`(`body`)와 `hud.css`가 이미 `font-family: 'Jua'`를 첫 순서로 지정하고 있어, `@font-face`가 들어가면 **앱 전체와 인게임 HUD 글꼴이 바로 Jua로 바뀐다**(지금까지는 Jua가 설치되지 않은 PC에서 맑은 고딕 등으로 대체됐다). 의도한 화풍이며, 클래스(`.l-*`)를 쓰는 화면 적용은 아직 없다. (PR #88 A 리뷰로 정정)

- `lobby-screen.tsx`: 왼쪽 프로필바를 없애고 위쪽 줄(로고·새로고침·코드 입력·방 생성·즉시 참가·오른쪽 위 프로필 명판)과 방 테마별 지역 4열 방 목록으로 바꿨다. 명판은 캐릭터(2D 얼굴)·닉네임·전적·승률·환경설정·로그아웃이다. 캐릭터를 누르면 꾸미기 창이 열린다. "대기 중만 보기"는 두지 않았다. 방 선택·더블클릭 입장·`입장` 버튼·게임 중 표시·비공개 코드 입력 등 동작과 데이터 처리 코드는 바꾸지 않았다(화면 부분만 교체).
- 지역: 열 순서와 이름은 `THEME_IDS`·`THEME_LABEL`(바·밤 옥상·교실·해변)이며 열마다 "대기 N / 전체 M"을 보인다. 대기는 입장할 수 있는 방, 전체는 게임 중 포함이다. 방이 없는 열은 "아직 방이 없어요"를 보이고 방이 많으면 그 열만 스크롤된다. 방 카드는 제목(비공개는 자물쇠)·방장 얼굴·닉네임·승률·전적·상태(대기 중·비공개·게임 중)이며 테마는 카드가 놓인 열로 구분한다.
- `logic.ts`: 방을 테마별로 나누는 순수 함수 `groupRoomsByTheme`를 추가하고 `app.test.ts`에 단위 테스트를 더했다(순서·대기/전체 수·빈 지역).
- `region-art.tsx`(신규): 지역 머리 그림 4종을 코드로 그린 인라인 SVG로 만들었다. 도형은 디자인 캔버스 UiL-Lobby 보드에서 옮겼다(파일 에셋 없음).
- `app.css`: 옛 프로필바·방 카드 스타일을 지우고 로비 스타일을 새로 썼다. 배경은 로그인과 같은 일러스트를 쓴다. 창 폭 1100px 미만은 지역 열이 2×2, 820px 미만은 명판이 아래 줄, 640px 미만은 한 열이다. 대기실이 쓰는 `.room-host-record`는 남겼다.
- 시안과 다른 점: 시안의 로고 문구 "알까기 바"는 PR #90 결정대로 "증강 알까기"로, 시안의 지역 이름 "바 마을"은 DEC-072 ⑥에 따라 `THEME_LABEL`의 "바"로 썼다. 시안은 게임 중인 방을 고를 수 없게 했지만 PRD·기존 동작대로 고를 수 있고 `입장` 버튼만 비활성이다.

### 한계·미검증

- Claude는 가짜 데이터로 화면 배치만 확인했다. 실제 서버·계정으로 하는 방 목록 갱신, 방 선택·더블클릭·`입장` 버튼, 즉시 참가·코드 입력, 경기 뒤 로비 복귀 시 목록·전적 갱신(코드상 `LobbyScreen` 마운트 때 `refresh()`가 도는 것까지만 읽어 확인), 두 계정 흐름은 Claude가 직접 보지 못했다.
- 이후 사용자(개발자 B)가 로비의 기능들을 모두 직접 확인했다고 알려 왔다(2026-11-04, PR #92 리뷰 중). 확인한 항목·브라우저·서버 환경은 기록하지 않았고 Claude는 이 확인을 직접 보지 못했다.
- 로그아웃 중(`locked`) 상태와 목록 불러오기 실패 상태의 화면은 눈으로 확인하지 않았다.
- 로비에서 여는 창(방 생성·꾸미기·환경설정·코드 입력·규칙)은 이번 범위가 아니라 옛 화풍 그대로다.
- 명판의 캐릭터는 시안처럼 2D 얼굴이다. 3D 전신(`avatar-figure.ts`)은 방 생성·꾸미기 창 PR에서 쓴다.

## IMPL-019 방 생성 창 L 화풍 (왼쪽 3D 전신)

### 범위와 기준 문서

- 작업: [IMPL-019](../TASKS.md#impl-019-l-화풍-화면-적용). 로비 화면과 같은 PR(#92)에 넣었다(사용자 지시: 병합 전에 방 생성 화면을 같이 넣어 한 번에 병합). 결정 [DEC-070](../DECISIONS.md#결정-색인)·[DEC-074](../DECISIONS.md#결정-색인).
- 브랜치: `feat/impl-019-lobby`

### 수행

- `modals.tsx`의 `CreateRoomModal`을 로비를 덮는 L 화풍 화면으로 바꿨다. 위쪽 줄(로고·"방 생성 · 새 대결장을 열어요" 띠·`◀ 방 목록으로`), 왼쪽 배경 없는 투명 창(내 캐릭터 3D 전신), 오른쪽 설정 창(대전 상대 큰 버튼 두 개·방 제목·알 개수·판·방 테마 그림 타일 4개·공개 여부·방 코드 칸·`방 만들기`)이다. 옛 플로팅 창 껍데기(`FloatingWindow`)는 이 창에서 쓰지 않는다. ESC로 닫는 동작은 유지했다. `appearance` 속성을 새로 받으며 `lobby-screen.tsx`가 `me.appearance`를 넘긴다.
- 방 만들기·AI 시작·코드 생성·코드 겹침 처리·검증 문구 등 동작 코드는 바꾸지 않았다. AI 대전은 DEC-042 ②대로 `AiSetupForm`을 그대로 쓰되 테마 선택을 사람 방과 같은 칩 마크업으로 맞추고(`chips={false}` 제거) 시작 버튼에 `l-btn l-btn-primary` 클래스를 더했다. 테마 칩에 `data-theme` 속성을 더해 그림 타일을 입힌다.
- `avatar-figure.ts`·`avatar-hand.ts`: 2026-11-04 백업 커밋(`4b57e4c`)의 로컬 작업을 가져왔다(큰 머리·짧은 몸·통짜 다리의 코드 도형 전신과 다섯 손가락 손). 머리는 게임과 같은 `AvatarHead`다. `avatar-hand.ts`는 지금 전신만 쓰며 게임 리그(`characters.ts`)로 옮기는 것은 별도 작업이다(이 PR에서 `characters.ts`는 건드리지 않았다).
- `AvatarFigureView.tsx`(신규): 전신을 투명 배경 캔버스에 그리고 천천히 좌우를 돌아본다. WebGL을 못 쓰면 2D 얼굴(`AvatarFace`)로 대신한다. 꾸미기 창 미리보기는 이번 범위가 아니라 옛 상반신 그대로다.
- `app.css`: 옛 `.choice`·`.chip`·`.ai-setup` 규칙(방 생성 창에서만 쓰였다)을 지우고 방 생성 창 스타일을 새로 썼다. 창 폭 900px 미만은 캐릭터 창이 위로 올라가고 화면이 스크롤되며 640px 미만은 여백을 줄인다.
- 시안과 다른 점: 시안의 로고 "알까기 바"는 "증강 알까기"로, 시안의 "바 마을" 타일 이름은 `THEME_LABEL`의 "바"로, 시안의 임의 캐릭터 대신 내 외형을 쓴다. 시안은 전신이 2D 그림이지만 DEC-074에 따라 3D다. 시안에 없던 오류 문구(`msg-error`)와 AI 대전 탭은 같은 화풍으로 맞췄다.

### 검증 조건과 결과

- `npm run build`·`npm run lint` 통과, 변경 파일 prettier 통과(LF 기준), `npm test` 394개 전부 통과. 방 생성 창은 화면 컴포넌트라 단위 테스트는 더하지 않았다.
- 서버 없이 방 생성 창만 띄우는 임시 하네스(커밋하지 않고 삭제함)를 개발 서버로 띄워 Chrome 헤드리스(SwiftShader)로 확인했다.
  - 1280×720 사람 대전: 시안과 같은 배치. 3D 전신이 내 외형으로 보이고 대전 상대 큰 버튼·방 테마 타일·공개 여부·`방 만들기`가 보인다.

  - 800×1000: 캐릭터 창이 위로 올라가고 설정 창이 아래로 쌓이며 겹침 없음.
  - WebGL 끈 상태: 왼쪽 창에 2D 얼굴이 대신 보인다.

### 한계·미검증

- 가짜 데이터로 화면 배치만 확인했다. 실제 서버·계정으로 방 만들기(공개·비공개, 코드 겹침 안내), AI 대전 시작, 방 목록으로 돌아가기·ESC 닫기는 Claude가 직접 보지 못했다.
- 3D 전신은 SwiftShader(소프트웨어 렌더)로만 확인했다. 실제 GPU 성능과 낮은 사양 PC에서의 부하는 확인하지 않았다. 방 생성 창을 열어 둔 동안 캔버스가 계속 그려진다(로비 뒤 화면은 가려져 있다).
- 꾸미기 창·환경설정·코드 입력·규칙 카드는 아직 옛 화풍이다. 테마 타일은 시안의 단순 그라데이션이고 지역 그림(`region-art.tsx`)과는 다르다.
