# 2026-11-04 작업·검증 기록

## IMPL-016 자석 블랙홀식 흡입 (DEC-068)

### 범위와 기준 문서

- 작업: [IMPL-016 자석 블랙홀식 흡입 절](../TASKS.md#impl-016-자석-블랙홀식-흡입-dec-068)
- 결정: [DEC-068](../DECISIONS.md#결정-색인)([DEC-067](../DECISIONS.md#결정-색인)의 자석 가속 대체)
- 요구사항·설계: [PRD 추가 방해요소 10종](../PRD.md#추가-방해요소-10종-dec-055)·[GAME 추가 10종](../design/GAME.md#추가-방해요소-10종과-턴-교체-haz-001)
- 비교 기준: 변경 전 자석은 반지름 8.8cm 안의 움직이는 지면 알·떠 있는 알에 중심 쪽 540 cm/s² 가속만 더해, 알이 휘어 지나가거나 중심을 지나쳤다.

### 작업·검증 조건

- 브랜치 `feature/local-ai-completion`(PR #84에 추가).
- 사용자 요청: "자석의 세기가 너무 약해 블랙홀처럼 범위내에 닿기만 하면 블랙홀처럼 끌어오게 변경할거야 수치만 변경해줘 테스트나 검증은 하지 말고" → 수치(540 → 5400)만 변경. 이어 "그냥 수치를 바꾸는게 아니라 중앙으로 끌려오게 코드를 변경해줘 테스트나 검증은 하지마" → 흡입 코드로 변경.

### 수행과 관찰

- `packages/shared/src/constants.ts`: `magnetAccel` 540 → 5400, `magnetTangentDamping` 12 추가.
- `packages/game-core/src/physics.ts` 자석 처리: 범위 안 알의 속도를 중심 쪽 성분(바깥 방향은 0으로, 그 뒤 `magnetAccel·DT` 더함)과 수직 성분(`1 − magnetTangentDamping·DT` 배)으로 다시 만든다. 중심 쪽 성분으로 이번 스텝에 중심에 닿거나 지나치면 알을 중심 좌표에 놓고 수평 속도를 0으로 한다. 적용 대상(움직이는 지면 알·떠 있는 알)은 그대로다.
- 판정: 사용자가 변경 결과를 보고 "괜찮네"라고 확인했다. 사용자가 확인한 실행 경로·절차의 상세는 전달받지 않았다.

### 한계·미검증

- 사용자 요청에 따라 Claude는 이 변경 뒤 테스트·빌드·타입 검사·브라우저 확인을 실행하지 않았다.
- 이전 자석 동작(540 cm/s² 휘어짐)을 전제로 한 자동 테스트(예: `packages/game-core/src/hazards-extra.test.ts`)의 통과 여부는 확인하지 않았다. 실패하면 DEC-068 기준으로 기대값을 고친다.
- 알 두 개가 연달아 빨려 들면 나중 알은 중심의 알과 충돌해 그 옆에 멈춘다. 범위 안에 멈춰 있던 알은 끌려오지 않는다.

### 문서 대조·후속 작업

- DECISIONS(DEC-068 추가, DEC-067 일부 대체 표시)·PRD 자석 행·GAME 자석 행·TASKS·CHANGELOG·PROGRESS를 같은 변경에서 갱신했다.
- 수치는 계속 제안값이며 플레이 테스트로 확정한다.

## UI-004 디자인 참고 기준을 L 세트로 변경

### 범위와 기준 문서

- 작업: [UI-004](../TASKS.md#ui-004-디자인-참고-기준을-l-세트로-변경), 결정 [DEC-069](../DECISIONS.md#결정-색인)
- 이번 작업 범위와 비교할 기준: 사용자 메시지 "문서에서 디자인 참고를 L 한밤의 마법 알까기를 참고하는걸로 전부 변경해줘"

### 작업·검증 조건

- 브랜치: `docs/design-reference-l`(미커밋 문서 변경)
- 캔버스: claude.ai 디자인 캔버스 `PFvjbTKVncmZLbfQAUEBVV`의 L 줄 보드 `UiL-Login`·`UiL-Lobby`·`UiL-Create`. 같은 날 대화에서 사용자 요청으로 만들고 고쳤다. 로그인 배경은 사용자가 준 일러스트를 캔버스 자산으로 올린 것이다. 캔버스는 다른 계정도 함께 편집하고 있었다
- 코드·화면 구현 변경 없음

### 수행과 관찰

- `grep`으로 `알까기 바 (2)`·디자인 캔버스·시안 참조를 찾아 현재 기준을 가리키는 곳만 바꿨다: PRD 화면별 요구사항 첫 문단·화면 미정 사항(아트 세부)·결정 순서 제안 4번, LOCAL 미정 사항, TECH_STACK 글꼴 행(Black Han Sans 추가)과 로그인 일러스트 행 추가, PROGRESS 확인일·디자인 캔버스 항목.
- DECISIONS에 DEC-069를 추가하고 DEC-006·007의 대체 관계, DEC-060의 상태(일부 대체)를 적었다.
- 세트와 PRD가 다른 점 5가지를 PRD 화면 미정 사항에 미정으로 적었다.
- 링크 확인: 새로 쓴 앵커 `#ui-004-디자인-참고-기준을-l-세트로-변경`은 TASKS 절 제목에서 만든 것이고, `#화면-미정-사항`·`#에셋-종류별-방식`·`#미정-사항`은 기존 제목과 같다.

### 한계·미검증

- 캔버스 화면을 브라우저로 직접 열어 확인하지 않았다(정지 시안, 일부 보드만 눌러 볼 수 있음).
- 클라이언트 코드 주석(`app.css`·`hud.css`)은 아직 `알까기 바 (2).html`을 시안으로 적고 있다. 코드는 이번 범위가 아니어서 두었다.
- 로그인 일러스트의 출처·이용 조건은 확인하지 않았다.

### 문서 대조·후속 작업

- 남은 결정이던 L 세트 차이 5가지는 같은 날 확정했다(아래 "확정 반영").
- worklog·완료 작업·DEC-032·DEC-036 본문의 이전 시안 언급은 당시 근거라 바꾸지 않았다.

### 확정 반영 (DEC-070·DEC-071)

- 사용자 메시지: 로비 프로필 오른쪽 위 명판, 방 목록 테마별 지역 4열(대기 중만 보기 없음), 방 생성 왼쪽 캐릭터 전신 창, 로그인 배경 일러스트(직접 제작), 나머지 화면도 같은 화풍, 중력 구역 화살표 평면 표시, 얼음판 설치형(범위 끈끈이 2배), 캐릭터 기본 얼굴 위쪽, 정면 시점 살짝 낮춤. "이 내용으로 확정했고 변경해달라고 pr 올려줘".
- 반영: DECISIONS(DEC-070·071 추가, DEC-006·055·069 대체 관계), PRD(화면별 요구사항 첫 문단·로그인·로비·캐릭터 변경·방 생성·방 테마·환경설정·게임 화면 카메라·캐릭터, 추가 방해요소 표의 중력 구역·미끄럼 장판, 설치물 목록, 화면 미정 사항), GAME(미끄럼 장판 효과·수치, 위치형 목록, 중력 구역 화살표 규칙), API(`ice_floor` target·params), LOCAL(입력 모드·화풍), TECH_STACK(일러스트 직접 제작), TASKS(UI-004 기준, IMPL-019·020 등록), PROGRESS.
- 미끄럼 장판 지름 26.4cm는 GAME의 끈끈이 지름 13.2cm의 2배로 계산했다. 감속 배율·분류·지속은 그대로 두었다.
- 캐릭터 시선 각도와 시점 높이는 값이 정해지지 않아 구현에서 정하도록 IMPL-020에 남겼다.
- 방 생성의 캐릭터 전신은 3D 아바타가 상반신(DEC-059)이라 표현 방법을 IMPL-019의 미정으로 남겼다.
- API `ice_floor` 계약 변경은 개발자 B 확인이 필요하다(PR 리뷰에서 확인).
- 코드는 바꾸지 않았다. 문서 확인: `git diff --check` 통과, 새 앵커(`#impl-019-l-화풍-화면-적용`, `#impl-020-중력-구역-화살표미끄럼-장판-설치형시선시점-조정`)는 TASKS 절 제목과 맞춰 썼다.

### 구현 분담과 공통 사항 확정 (DEC-072)

- 사용자 메시지: "같이 정해야할건 지금 혼자서 확정하고 a,b로 issue한개씩만 만들어서 끝까지 진행할 수 있게 해줘".
- 정한 것: 분담(B: IMPL-019, A: IMPL-020·IMPL-021 신규), 공통 화풍 파일 `packages/client/src/ui/theme.css`와 클래스 이름, 글꼴 직접 제공, 방 생성 캐릭터 전신은 2D `AvatarFullBody`, 배경 일러스트 공용, 지역 열 이름은 `THEME_LABEL`, 1100px 미만 2×2.
- 근거: 기존 담당(A: 로컬·AI·HUD·아바타, B: IMPL-012 화면)과 파일 경계(`app/*` vs `game/*`·`avatar/*`)가 겹치지 않게 나눴다. 3D 하반신은 아바타 모델·애니메이션 범위가 커서 2D 전신이 가장 빠르다.
- 일러스트 원본을 `packages/client/public/images/login-bg.png`(1974627바이트, 1536×864 PNG)로 넣었다. 이 환경에는 WebP 변환 도구(cwebp·ffmpeg·ImageMagick·Pillow)가 없어 압축은 IMPL-019로 넘겼다.
- TASKS·DECISIONS·PRD·TECH_STACK을 갱신하고 A·B Issue를 1개씩 만들었다.
