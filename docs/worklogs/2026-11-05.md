### 범위와 기준 문서

- 이번 범위: DB 조회와 분리해 해시 시간을 직접 기록하는 로그를 추가한다. 측정·파라미터 조정은 배포 뒤 단계다.

### 작업·검증 조건

- 브랜치 `feat/impl-013-hash-timing`, 로컬 개발 PC에서 검증. 운영 배포·측정은 하지 않았다.

### 수행과 관찰

- `packages/server/src/auth/password.ts`의 `hashPassword`·`verifyPassword`가 계산 시간을 `{ts, event: "argon2_timing", op, ms}` JSON 한 줄로 stdout에 남긴다. 비밀번호·해시·닉네임은 담지 않는다. 더미 해시 첫 생성은 기록하지 않는다.
- `password.test.ts`로 허용 키만 남는지, 비밀번호·해시 문자열이 로그에 없는지 확인했다.
- 결과: 대상 테스트·eslint·prettier·`tsc --noEmit` 통과. 전체 `npm test`는 한 번 1건 실패(테스트 식별 못 함) 뒤 3회 연속 395건 통과했다.

### 한계·미검증

- 첫 전체 실행의 1건 실패는 원인을 확인하지 못했다. 변경 전 기준선(394건)은 1회 통과했다.
- Render 무료 인스턴스의 실제 해시 시간은 배포 뒤 로그로 읽는다. 아직 측정·조정하지 않았다.

### 문서 대조·후속 작업

- 후속: 병합·수동 배포 뒤 운영 로그의 `argon2_timing` 값으로 파라미터를 조정하고 AUTH·TASKS를 갱신한다. 이 배포를 롤백 확인(`ddc5337` 복원)의 기준점으로 쓴다.

### Render 실측 결과 (후속, 같은 날)

- 조건: PR #97 병합(`f830224`)이 트리거 Auto-Deploy로 Render에 배포돼 Live가 된 뒤(소요 1m 45s), 없는 닉네임 `zzmeasure97`으로 `POST /api/auth/login` 11회를 보냈다(모두 `401`, DB 쓰기 없음). 서버 로그의 `argon2_timing` `verify` 줄은 사용자가 Render Logs에서 복사해 전달했다. Claude는 Render 로그를 직접 보지 못했다.
- 파라미터: 메모리 19,456 KiB, 반복 2, 병렬 1.
- 결과(ms, 정렬): 129.9, 198.9, 200.7, 276.2, 305.9, 310.7, 332.5, 374.3, 485.7, 639.7, 715.7. 평균 약 361, 중앙값 약 311, 최소~최대 130~716. 이 PC(약 11ms)의 약 30배다.
- 판정: 목표(약 100~300ms) 상단에 걸치므로 파라미터를 조정하지 않는다. 올리면 로그인 응답이 1초를 넘는 경우가 늘고, 내리면 OWASP 최소 권장 아래가 된다. 기존 계정은 해시 문자열 안의 파라미터로 검증되므로 영향이 없다.
- 정정: 2026-11-04 약식 측정의 "해시 상한 약 70ms 이하"는 틀렸다. 로그인과 기준 요청의 응답 시간 차이를 해시 시간으로 본 추정이 네트워크 편차·공유 CPU로 어긋났다.
- 한계: 표본이 11회이고 편차가 크다(공유 CPU). 첫 값(305.9)은 별도 콜드 영향이 보이지 않아 포함했다.
- 부수 확인: 같은 배포의 Deploys 화면에서 트리거가 Auto-Deploy였다. IMPL-013 수용 기준 "자동 배포가 꺼져 있다"와 충돌하며 정책 결정(끄기 유지 또는 켜기로 변경 후 DEC-029·수용 기준·OPERATIONS 갱신)이 필요하다. 롤백 확인은 Auto-Deploy를 끈 뒤에 하는 편이 안전하다.

### 한계·미검증

- 실제로 들어 본 크기·분위기는 사용자 확인이 필요하다. 감정표현 목소리는 합성 흉내라 녹음 파일로 바꾸는 것이 2·3단계다.
- 충돌 소리는 30Hz 스냅샷에서 거리·상대 속도로 추정해 아주 빠른 스침은 놓치거나 늦을 수 있다. 벽에 튕기는 소리는 없다.
- 온라인 경기(서버 연결)에서는 확인하지 못했다. 같은 세션 이벤트를 쓰므로 같게 동작할 것으로 본다.
- 경기 중에는 환경설정 창이 없어 음량을 바꾸려면 로비로 나가야 한다.
- 켜기 스위치(DEC-085): 음량과 따로 `alkkagi.sound.<갈래>`에 저장하고(기본 켜짐) 엔진은 꺼진 갈래의 음량을 0으로 둔다. 설정 창을 임시 페이지에 띄워(배경음악 꺼짐 상태) 스위치·흐린 음량 막대를 촬영해 확인했고 임시 파일은 지웠다. `app.test.ts`에 저장·기본값 확인을 더했다. `npm test`(409개), lint, format, 빌드 통과.
- 2·3단계(DEC-086): 서브 에이전트가 CC0 후보를 찾아 페이지의 라이선스를 확인했고 사용자가 골랐다. 고른 17개 페이지를 다시 열어 Freesound "Creative Commons 0"(publicdomain/zero/1.0)·OpenGameArt License(s) "CC0"를 확인했다(교실 곡 묶음 readme도 "Creative Commons Zero (CC0)"). Freesound는 공개 HQ 미리듣기 MP3, OpenGameArt는 원본 파일을 저장소 밖 임시 폴더에 받고, 저장소 밖에 설치한 ffmpeg 6.0(static)으로 잘라(소리 구간은 silencedetect로 찾음) 크기를 맞춰(짧은 소리 최대 −2~−4dB, 음악 −18LUFS, 배경 소리 −24~−30LUFS) MP3로 만들었다(효과음 모노 96kbps, 음악 스테레오 64kbps, 배경 소리 30초 모노 48kbps). 합계 약 3.1MB(효과음 약 120KB), 기존 public 약 0.8MB와 합쳐 약 3.9MB.
- 엔진: 효과음 파일은 소리를 열 때 미리 받고, 음악·배경 소리는 요청한 화면에서 받아 같은 곡은 다시 받지 않는다. 녹음 끝·처음이 매끄럽지 않아도 끊기지 않게 2.5~3초 겹쳐 잇는다(`loopBuffer`). 파일별 크기 배율(`fileGain`)로 합성 소리와 크기를 맞췄다. 판 밖으로 떨어지는 소리는 지웠다.
- 확인: 헤드리스 Chromium에서 17개 파일을 모두 디코딩해 배율 적용 뒤 크기를 쟀다(음악 RMS 0.03~0.04로 합성 곡과 비슷, 밤 옥상 배경 소리 0.067·놀람 0.087은 커서, GG 0.013은 작아서 배율을 조정). AI 경기를 시작하면 효과음 파일 8개·로비 곡을 받고 경기 시작 때 바 곡·바 배경 소리만 받는 것(모두 200)과 콘솔 오류가 없는 것을 확인했다. 등록 파일 존재·키·효과음 100KB·합계 한도 테스트를 더했다. `npm test`(35개 파일, 410개 통과), lint, format, 빌드(파일이 `dist/audio/`에 복사됨) 통과.
- 한계: 실제로 들어 보지 않았다(크기 배율은 측정값 기준). 반복 이음매의 자연스러움, 감정표현 길이·분위기는 사용자 청취로 확인이 필요하다.
- 소리 버튼(DEC-087): 로그인 화면은 로비 곡을 요청하고 있었고, 헤드리스 Chromium에서 첫 클릭 전에는 소리 파일을 받지 않다가 클릭 직후 효과음 파일과 `music/lobby.mp3`를 받는 것을 확인했다(브라우저 자동 재생 제한). 소리 설정 칸을 `app/sound-controls.tsx`(+ 자체 완결 CSS)로 떼어 환경설정 창과 함께 쓰고, `app/sound-button.tsx`를 로그인·경기(`GameScreen`)·AI 설정 화면 오른쪽 위에 두었다. 막혀 있으면 "소리 켜기"와 빛남, 열린 뒤는 스피커(모두 끄면 ✕) SVG 아이콘이다(처음 이모지는 글꼴이 없는 브라우저에서 네모로 보여 SVG로 바꿨다). 로그인 잠김·열린 창, AI 경기 중 창을 열고 배경음악을 끈 화면을 촬영했고 바깥을 누르면 창이 닫히는 것, 콘솔 오류가 없는 것을 확인했다. `npm test`(410개), lint, 빌드 통과.

## PR #101 2차 리뷰 반영: 용량 단위 통일

- 작업: [IMPL-030](../TASKS.md#impl-030-로그인-화면-움직이는-배경과-시안-배치) PR #101 2차 리뷰 확인 요청 1(5MB 정의)
- 기준: [TECH_STACK 용량 한도](../design/TECH_STACK.md#용량-한도), [DEC-033](../DECISIONS.md#결정-색인)

### 수행과 관찰

- 문서는 "5MB"인데 테스트는 `1024` 배수(MiB·KiB)로 검사해 기준이 달랐다. DEC-033 원문의 "5MB"에 맞춰 십진법(1KB = 1,000B, 1MB = 1,000,000B)으로 통일했다. `app/assets.test.ts`의 영상 1MB와 `public` 전체 5MB, `audio/audio.test.ts`의 효과음 파일당 100KB와 소리 파일 합계 보호선 3.5MB를 모두 십진 값으로 바꿨다. TECH_STACK 용량 한도에 단위 정의를 적고 여유를 다시 계산했다(4,690,433B, 여유 약 310KB).
- 현재 파일은 모두 새 기준 안에 있다(영상 690,067B, 가장 큰 효과음 28,569B).
- 2차 리뷰 확인 요청 2(로그인 버튼 이름 "입장하기")는 고치지 않았다. 버튼이 `aria-label="로그인"` 영역 안에 있고, 버튼에 다른 `aria-label`을 덮으면 보이는 글자와 읽히는 이름이 달라진다(WCAG 2.5.3).
- 결과: `npm test`(38개 파일, 422개 통과), `npm run lint` 통과.
