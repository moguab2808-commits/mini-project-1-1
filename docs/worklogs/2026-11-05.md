## IMPL-013 argon2id 해시 시간 서버 내 로그

### 범위와 기준 문서

- 작업: [IMPL-013](../TASKS.md#impl-013-배포) 수용 기준 "argon2id 해시 시간 측정·조정"
- 기준: [AUTH 해시·프록시](../design/AUTH.md#해시프록시), 측정 한계는 [2026-11-04 약식 측정](2026-11-04.md#argon2id-해시-시간-측정-운영-서버-약식)
- 이번 범위: DB 조회와 분리해 해시 시간을 직접 기록하는 로그를 추가한다. 측정·파라미터 조정은 배포 뒤 단계다.

### 작업·검증 조건

- 브랜치 `feat/impl-013-hash-timing`, 로컬 개발 PC에서 검증. 운영 배포·측정은 하지 않았다.

### 수행과 관찰

- `packages/server/src/auth/password.ts`의 `hashPassword`·`verifyPassword`가 계산 시간을 `{ts, event: "argon2_timing", op, ms}` JSON 한 줄로 stdout에 남긴다. 비밀번호·해시·닉네임은 담지 않는다. 더미 해시 첫 생성은 기록하지 않는다.
- `password.test.ts`로 허용 키만 남는지, 비밀번호·해시 문자열이 로그에 없는지 확인했다.
- 결과: 대상 테스트·eslint·prettier·`tsc --noEmit` 통과. 전체 `npm test`는 한 번 1건 실패(테스트 식별 못 함) 뒤 3회 연속 395건 통과했다.

### 한계·미검증

- 첫 전체 실행의 1건 실패는 원인을 확인하지 못했다. 변경 전 기준선(394건)은 1회 통과했다.
- Render 무료 인스턴스의 실제 해시 시간은 배포 뒤 로그로 읽는다. 아직 측정·조정하지 않았다.

### 문서 대조·후속 작업

- 후속: 병합·수동 배포 뒤 운영 로그의 `argon2_timing` 값으로 파라미터를 조정하고 AUTH·TASKS를 갱신한다. 이 배포를 롤백 확인(`ddc5337` 복원)의 기준점으로 쓴다.

### Render 실측 결과 (후속, 같은 날)

- 조건: PR #97 병합(`f830224`)이 트리거 Auto-Deploy로 Render에 배포돼 Live가 된 뒤(소요 1m 45s), 없는 닉네임 `zzmeasure97`으로 `POST /api/auth/login` 11회를 보냈다(모두 `401`, DB 쓰기 없음). 서버 로그의 `argon2_timing` `verify` 줄은 사용자가 Render Logs에서 복사해 전달했다. Claude는 Render 로그를 직접 보지 못했다.
- 파라미터: 메모리 19,456 KiB, 반복 2, 병렬 1.
- 결과(ms, 정렬): 129.9, 198.9, 200.7, 276.2, 305.9, 310.7, 332.5, 374.3, 485.7, 639.7, 715.7. 평균 약 361, 중앙값 약 311, 최소~최대 130~716. 이 PC(약 11ms)의 약 30배다.
- 판정: 목표(약 100~300ms) 상단에 걸치므로 파라미터를 조정하지 않는다. 올리면 로그인 응답이 1초를 넘는 경우가 늘고, 내리면 OWASP 최소 권장 아래가 된다. 기존 계정은 해시 문자열 안의 파라미터로 검증되므로 영향이 없다.
- 정정: 2026-11-04 약식 측정의 "해시 상한 약 70ms 이하"는 틀렸다. 로그인과 기준 요청의 응답 시간 차이를 해시 시간으로 본 추정이 네트워크 편차·공유 CPU로 어긋났다.
- 한계: 표본이 11회이고 편차가 크다(공유 CPU). 첫 값(305.9)은 별도 콜드 영향이 보이지 않아 포함했다.
- 부수 확인: 같은 배포의 Deploys 화면에서 트리거가 Auto-Deploy였다. IMPL-013 수용 기준 "자동 배포가 꺼져 있다"와 충돌하며 정책 결정(끄기 유지 또는 켜기로 변경 후 DEC-029·수용 기준·OPERATIONS 갱신)이 필요하다. 롤백 확인은 Auto-Deploy를 끈 뒤에 하는 편이 안전하다.

## IMPL-013 마무리 사용자 확인

### 범위와 기준 문서

- 작업: [IMPL-013](../TASKS.md#impl-013-배포)의 남은 수용 기준 3개(Auto-Deploy·비밀값, 롤백)와 로그 보관 7일([DEC-047](../DECISIONS.md#결정-색인)) 확인
- 기준: [OPERATIONS](../design/OPERATIONS.md#세부-절차-확정안), DEC-029

### 작업·검증 조건

- 이 절의 확인은 **사용자가 Render 화면에서 직접 한 뒤 전한 내용**이다. Claude는 Render 대시보드·로그를 볼 수 없어 직접 보지 못했다. 환경 변수 값·비밀정보는 이 기록에 옮기지 않았다.

### 수행과 관찰

- 사용자 전언(2026-11-05): "1번 그대로 가고 2번 확인 완료, 3번 확인 완료, 4번 확인 완료". 1번은 Auto-Deploy 정책을 기준대로(꺼짐) 유지한다는 뜻으로 읽었고, 2번은 Auto-Deploy 설정과 운영 로그에 비밀값이 없는 것, 3번은 롤백, 4번은 로그 보관 7일 적용이다.
- Claude가 직접 확인한 것: 같은 날 운영 `/health`가 `200 {"status":"ok"}`다(롤백·복귀 뒤 현재 상태, 어느 커밋이 Live인지는 이 응답으로 알 수 없다).
- 수용 기준 판정: 자동 배포 꺼짐·비밀값 없음 → 충족(사용자 확인), 롤백 → 충족(사용자 확인), 로그 보관 7일 → 확인됨(사용자 확인).

### 한계·미검증

- 롤백 대상 커밋과 시각, 롤백 뒤 되돌린 여부와 Live 커밋은 전달받지 못해 기록하지 못했다. Auto-Deploy가 같은 날 Deploys 화면에서 한때 트리거로 보였다는 점(위 argon2id 절 참고)과 현재 Off라는 확인이 어떻게 이어지는지는 사용자 전언에만 의존한다.
- 사용자의 "1번 그대로"를 Auto-Deploy 꺼짐 유지로 해석했다. 다르면 TASKS·DEC-029·OPERATIONS를 고쳐야 한다.

### 문서 대조·후속 작업

- TASKS IMPL-013 수용 기준을 체크하고 완료로 표시했다(병합 직후 체크 규칙에 따라 같은 PR에서 닫는다). PROGRESS를 갱신했다. 후속 작업 없음.
