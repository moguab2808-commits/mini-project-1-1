# 2026-11-01 작업·검증 기록

## IMPL-002 `game-core`

### 범위와 기준 문서

- 작업: [IMPL-002](../TASKS.md#impl-002-game-core). 사용자 요청 "A 부분 다음 진행하자"에 따라 개발자 A 줄의 다음 착수 대상(선행 GAME-001·GAME-002·IMPL-001 완료)을 시작했다.
- 기준: [GAME](../design/GAME.md#상세-계약-초안-game-001)·[기술 초기값](../design/GAME.md#기술-초기값-조정-대상), [게임 규칙](../PRD.md#게임-규칙)·[방해요소 규칙](../PRD.md#방해요소-규칙), [API 공통 타입·경기 이벤트](../design/API.md#경기-이벤트-필드), [AUTH 검증 경계](../design/AUTH.md#검증-경계)

### 작업·검증 조건

- 브랜치: `feat/impl-002-game-core`(`main` ee105cb에서 분기). 미커밋. 커밋·PR은 만들지 않았다.
- 환경: WSL2 Linux, Node 24. 저장소 루트에서 `npm run build`·`npm test`·`npm run lint`·`npm run format`을 실행했다.
- 추가 의존성: `zod` 4.6.7(`shared`, 정확한 버전 고정).

### 수행과 관찰

만든 것:

- `shared`: 수치·방해요소·판 데이터(`constants.ts`, GAME 기술 초기값 그대로)와 명령·이벤트·뷰의 Zod 스키마(`protocol.ts`). `Seat`·`HazardKind`·`BoardId`·`CharacterId` 이름은 API 공통 타입과 같다.
- `game-core`: 시드 PRNG(`prng.ts`), 판 영역·초기 배치·원/회전 직사각형 충돌(`geometry.ts`), 고정 1/120초 물리(`physics.ts`), 상태 머신·방해요소·`getViewFor`(`game.ts`).
- 공개 인터페이스: `new Game(config)` → `start()` → `advanceTo(nowMs)`, 명령 `submitShot`·`useHazard`·`forfeit`(각각 `{ seat, observedAtMs }` 봉투와 API 명령 필드를 받아 `CommandResult` 반환), `drainEvents()`(`hazard:granted`·`hazard:triggered`·`turn:change`·`game:over`, 발생 순서), `getViewFor(seat)`. 시간·명령·난수는 모두 외부 주입이다. 명령은 먼저 `advanceTo(observedAtMs)`로 시간 정산(마감·효과 만료·랜덤 발동)과 틱을 진행한 뒤 검증한다.

### 구현에서 정한 해석 (사용자 확인 필요)

문서에 명시가 없거나 모호해 구현자가 고른 것이다. 승인된 결정이 아니다.

- 판 돌리기·책상 흔들기는 알을 즉시 옮기는 효과라 `aiming` → `moving`으로 전이시키지 않는다(GAME 전이도의 "알을 움직이는 효과"는 속도를 주는 효과가 생기면 쓴다).
- 끈끈이도 벽처럼 판 밖·알·기존 벽·끈끈이와 겹치면 `HAZARD_INVALID_TARGET`으로 거부한다(API 오류 표 문장을 그대로 따름). 격자 스냅 검증은 벽에만 적용하고 끈끈이는 자유 위치다.
- `hazard:triggered`의 `targetSeat`는 판 돌리기·책상 흔들기·벽·끈끈이에서도 상대 좌석으로 둔다(양쪽에 같게 영향).
- 방해요소 교체 때 "지속 효과를 지운다"는 그 플레이어가 쓴 방해요소의 진행 중인 효과(벽·끈끈이·기절·가림 등)를 지우는 것으로 해석했다.
- 판 돌리기 뒤 벽의 각도는 `params.angleDeg`로 보낸다(API에 추가, [API](../design/API.md#경기-이벤트-필드) 갱신).
- `game:over`의 `rematchDeadlineMs`는 코어가 `null`로 두고 재도전 창은 `game-runtime`이 채운다. `game:start`도 닉네임이 필요해 `game-runtime`·서버가 만든다(스키마는 `shared`에 있음).
- 발사 각도 (−π, π]를 확정해 API·AUTH의 미정 표시를 지웠다(AUTH가 제안한 값 그대로).

### 한계·미검증

- 10초 상한은 `forceStop`만 단위로 확인했고, 실제 게임에서 상한에 닿는 상황은 만들지 못해 `advanceTo`와 이어진 경로는 미검증이다(정지 판정이 먼저 일어남). 원형판은 이탈 판정(축·대각선)과 발사 제거까지 확인했으나 원형판 위 알–알·벽 충돌은 별도 테스트가 없다. 벽 반사는 45° 벽의 방향만 비율 범위로 확인했고 반발 크기는 정밀 비교하지 않았다.
- 물리 수치는 제안값이며 플레이 테스트를 하지 않았다. 체감·터널링 여유는 계산 근거(한 스텝 최대 약 0.98cm < 반지름 1.1cm)뿐이다.
- 성능(방당 틱 비용)은 측정하지 않았다. `getViewFor`는 매번 새 객체를 만든다.
- `game-runtime`(IMPL-003)·서버(IMPL-009)에서 이 인터페이스를 쓰는 연동은 아직 없다. 공개 인터페이스는 IMPL-003 완료 전에 B와 맞춰야 한다.
- `npm audit`·링크·앵커 검사 스크립트는 이번에 다시 돌리지 않았다. 문서 변경은 기존 문장 수정과 새 worklog 절뿐이며 새 링크는 이 절에서만 추가했다.

### 단위 테스트 보강 (같은 날)

- 사용자 요청으로 미검증 항목을 채웠다(`physics.test.ts` 9개): 알–알 충돌의 운동량 보존·반발계수·겹침 해소, `forceStop`, 원형판 이탈·발사 제거, 45° 벽 반사, 판 돌리기 뒤 벽의 `angleDeg`·좌표 회전. 보강 중 구현 결함은 발견되지 않았다.
