### 수행과 관찰

- 이름 확인: 오류 코드 9종·`HAZARD_*` 4종은 API 오류 코드 표, GAME 상태 전이·방해요소 처리, LOCAL `CommandResult`, AUTH 검사 순서에서 같은 철자로 쓰인다. `HazardKind` 9개는 PRD 방해요소 9종과 개수·의미가 같고, `game:over.reason` 4값(`all_stones_out`·`final_round`·`forfeit`·`timeout_forfeit`)은 OPERATIONS `game_over` 로그의 `reason`과 같다. 바꿀 이름이 없어 이름은 유지했다.
- private 뷰 필드: `fatigueGauge`(0~100 또는 `null`), `overheated`, `cooldownEndsAtMs`(또는 `null`), `usable`을 GAME에 정의하고 API `GameView.private`에 반영했다. 방해요소 분류별 값은 DEC-031의 과열·쿨타임·랜덤형 규칙에서 가져왔고 새 정책은 없다. 랜덤형의 자동 발동 시각은 필드에 넣지 않았다([API 비공개 점검](../design/API.md#상대-비공개-필드-점검)과 일치).
- 같은 변경: AUTH의 검사 순서를 GAME 명령 경합 절이 따르도록 한 줄을 추가했다.
- 수용 기준 판정: 1·2번 충족. 3번(병합)은 미충족이라 TASKS 상태를 "리뷰 중"으로 두었다.

## VAL-002 개발용 프레임 시간 기록 모듈

### 범위와 기준 문서

- 작업: [VAL-002](../TASKS.md#val-002-개발용-프레임-시간-기록)
- 기준: [fps 측정 절차](../ENGINEERING-VALIDATION.md#fps-측정-절차-val-001)·[DEC-034](../DECISIONS.md#결정-색인)

### 작업·검증 조건

- 새 파일: `packages/client/src/dev/frame-recorder.ts`, `frame-recorder.test.ts`. 저장소에 패키지 골격(IMPL-001)이 아직 없어 TECH_STACK의 패키지 이름(`client`)에 맞춘 위치다. 골격이 만들어질 때 경로·테스트 도구(Vitest)에 맞게 옮긴다.
- 실행 환경: Node 24 타입 제거 실행(`node --test`), 의존성 없음.

### 수행과 관찰

- 모듈: `FrameRecorder`(`start`·`frame`·`mark`·`stop`·`report`), 프레임 간격(ms) 원자료와 요약(프레임 수·측정 시간·평균 fps·프레임 시간 95백분위·하위 5% fps·100ms 이상 멈춤 시각, 평균 55·하위 5% 30 충족 여부), JSON 내보내기, 주입형 `sampleFrames`(requestAnimationFrame 등을 받음). 95백분위는 nearest-rank로 정의했다.
- 명령: `node --test packages/client/src/dev/frame-recorder.test.ts` → 9개 통과, 실패 0. 검증 내용: 60fps 일정, 95백분위 경계(느린 프레임 5개 vs 6개), 멈춤 100ms 경계(99ms 제외·100ms 포함), 평균 55fps 경계(55 충족·54 불충족), 시작 전·역행 시각 무시, 프레임 없음의 null 판정, 구간 표시와 재시작 초기화, JSON, `sampleFrames`.
- 첫 실행에서 55fps 경계 테스트가 실패했다. 원인은 `1000/55`를 55번 더하면 정확히 1000ms가 되지 않는 부동소수 오차였고, 합이 정확히 1000ms인 입력으로 바꿨다. 모듈 판정식의 오류가 아니다.
- 수용 기준 판정: 1번(개발 환경에서만 동작, 운영 빌드 영향 없음)과 2번(실제 판 시작·종료 구간 기록)은 게임 화면이 없어 확인하지 못했다. 3번은 병합 전이다. 상태는 "진행 중"이다.

### 한계·미검증

- 실제 브라우저·게임 화면에서의 측정, 운영 빌드에서 모듈이 빠지는지는 확인하지 않았다. 켜는 방식은 화면에서 `import.meta.env.DEV` 조건 동적 import로 하도록 모듈 머리 주석에 적었으나 아직 연결하지 않았다.
