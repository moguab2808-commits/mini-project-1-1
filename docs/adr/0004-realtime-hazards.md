# ADR-0004: 이동 중 방해요소를 위한 실시간 진행

DEC ID: [DEC-016](../DECISIONS.md#결정-색인)
결정일: 2026-10-30
상태: 승인
동의 근거: 2026-10-30 사용자 메시지 “실시간 계산 방식은 확정. B도 합의한거야”. API-001 상세 계약은 별도 검토한다.
대체 관계: DEC-013·ADR-0003의 기록 후 재생 부분만 대체한다.

## 배경

사용자가 내 턴·상대 턴·조준·알 이동 여부와 관계없이 방해요소를 사용하도록 명시했다. 발사 전체를 선계산하면 이후 입력을 그 계산에 반영할 수 없다.

## 선택과 핵심 조건

서버 권한·공용 game-core를 유지하며 고정 틱에서 새 입력과 물리를 처리하고 플레이어별 현재 상태를 전송하는 방식으로 진행한다. 클라이언트는 상태를 보간한다. 계약은 [GAME](../design/GAME.md)에 둔다.

## 대안과 절충

- 기록 후 재생 유지: 발사 중 새 입력을 거부해야 하므로 새 제품 규칙을 충족하지 못한다.
- 선계산 결과를 입력마다 재계산: 이미 표시한 장면을 되돌리거나 미래 기록을 교체하는 복잡성이 크다.
- 실시간 권한 계산: 진행 중 입력을 자연스럽게 반영하지만 주기 실행·지연·대역폭 관리가 필요하다.

## 영향과 위험

기존 sim:result 전송·재생 단계를 바꾸고 API·로컬 세션·운영 측정 설계를 함께 검토해야 한다. 무료 서버 부하와 네트워크 지연은 미검증이다. 물리 시간과 전송·렌더링 주기를 분리해 측정한다.

## 재검토 조건

입력 지연이나 서버 부하가 제품 목표를 충족하지 못할 때, 이동 중 개별 효과의 결과 판정이 합의되지 않을 때 재검토한다.
