# ADR: 제품 요구사항과 기술 검토의 책임 분리

DEC ID: [DEC-003](../DECISIONS.md#결정-색인)
결정일: 2026-10-28
상태: 대체됨 — 문서 구조·관리 규칙은 [DEC-004 / ADR-0002](0002-document-responsibilities.md)가 대체한다. 기술 미정 전환은 유지한다.
동의 근거: 이전 사용자 요청
대체 관계: DEC-004

## 배경

원본 PRD에 제품 규칙·기술 선정·API·DB·개발 계획이 함께 있었다. 사용자는 제품 요구사항을 남기고 나머지 기존 확정 항목을 미정으로 전환하며 문서 책임을 나누도록 요청했다.

## 대안

- 원본 한 문서에서 제품 요구사항과 기술 후보를 계속 함께 관리
- 제품 요구사항·상세 규칙·기술 검토·계획을 책임별로 분리하고 서로 연결

## 결정

두 번째 방식으로 정리한다. 루트 [PRD](../PRD.md)는 제품 목표·범위·제약·성공 기준을 관리한다. 상세 게임·증강·화면 요구사항은 연결 문서에서 관리한다. 기존 기술 스택·아키텍처·구현 수단·개발 계획은 모두 미정으로 전환하고 과거 안을 후보로 보존한다. 새로운 기술은 선정하지 않는다.

전체 문서 책임과 이관 위치는 [문서 안내](../../AGENTS.md)를 따른다. 일반 PRD에서 부족한 항목은 [보완 의견](../PRD.md#prd-보완-의견)으로 분리하며 확정 요구사항으로 취급하지 않는다.

## 영향

과거 원문의 확정 표기는 현재 기술 채택 근거로 사용하지 않는다. 결정 당시 분리 직전 작업 파일을 보관했다. 이후 [DEC-005](../DECISIONS.md#결정-색인)에 따라 보관 디렉터리를 제거하고 과거 원문은 Git 이력으로 추적한다. 실제 구현 전에는 관련 Issue에서 필요한 기술·계약·범위를 합의하고 기준 문서를 갱신해야 한다. 제품 규칙의 기존 초안·미완료 항목은 계속 미정으로 둔다.

## 위험과 재검토 조건

과거 확정 문구가 현재 명세로 오해될 수 있어 보관본과 후보 상태를 구분했다. 문서 책임·작업 관리 방식이 바뀌면 후속 결정으로 대체한다. 현재 적용 상태는 연결된 결정 색인을 따른다.
