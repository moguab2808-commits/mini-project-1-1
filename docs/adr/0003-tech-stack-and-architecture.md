# ADR-0003: 기술 스택과 아키텍처

DEC ID: [DEC-013](../DECISIONS.md#결정-색인)
결정일: 2026-10-29
상태: 승인
동의 근거: 2026-10-29 사용자 메시지 "기술 스택, 아키텍처 결정 내용은 추천대로 진행할게"
대체 관계: 기록 후 재생은 [DEC-016](../DECISIONS.md#결정-색인)·[ADR-0004](0004-realtime-hazards.md)가 대체했다. [DEC-003](../DECISIONS.md#결정-색인)의 "기술 미정 전환" 상태를 이 결정으로 해소한다.

## 배경

제품 요구사항(PRD v0.16)이 거의 확정됐지만 기술·아키텍처는 모두 미정이라 구현을 시작할 수 없었다. 기술 선택에 영향을 주는 요구사항은 다음과 같다.

- 상대가 가진 방해요소를 볼 수 없어야 한다([방해요소 규칙](../PRD.md#방해요소-규칙)). 클라이언트에 상대 정보를 보내면 숨길 수 없으므로 판정과 공개 범위를 서버가 정해야 한다.
- 한 PC 2인 로컬 모드를 먼저 만들고 온라인으로 확장한다([DEC-009](../DECISIONS.md#결정-색인)). 같은 게임 로직을 브라우저와 서버에서 함께 써야 한다.
- 게임 화면은 3D이고([DEC-007](../DECISIONS.md#결정-색인)), 알은 세기에 따라 떠오르되 떠 있는 동안 충돌하지 않는다([알 떠오름](../PRD.md#알-떠오름)).
- 월 비용 0원, 동시 접속 10명, 첫 접속 대기 5초 이내([비기능 요구사항](../PRD.md#4-비기능-요구사항과-제약)).
- 두 명이 학습 목적으로 개발하는 미니프로젝트다.

## 선택과 핵심 조건

**아키텍처**

1. **서버 권한**: 물리 시뮬레이션·승패·턴 타이머·방해요소 지급과 발동·레이팅 갱신은 서버만 판정한다. 클라이언트는 입력(발사 각도·세기, 방해요소 사용)만 보낸다.
2. **기록 후 재생 (DEC-016으로 대체됨)**: 당시 선택은 서버가 발사 전체를 선계산하는 방식이었다. 현행 실시간 계산은 [ADR-0004](0004-realtime-hazards.md)를 따른다.
3. **플레이어별 뷰**: 서버는 게임 상태를 그대로 보내지 않고 플레이어마다 공개 범위를 적용한 뷰를 보낸다.
4. **공용 게임 로직**: 규칙·물리·상태 전이는 프레임워크·DOM·네트워크·DB를 참조하지 않는 순수 TypeScript 패키지(`game-core`)로 만들고 로컬 모드와 서버가 함께 쓴다. 시간과 난수는 밖에서 주입한다.
5. **물리**: 판 평면의 2D 원 충돌을 직접 구현하고, 떠오름은 알마다 높이 값을 따로 계산한다. 고정 시간 간격과 시드 난수로 같은 입력이면 같은 결과가 나오게 한다.
6. **저장 분리**: 방과 진행 중 게임은 서버 메모리, 회원·전적·세션은 DB에 둔다.
7. **배포 단위**: 하나의 웹 서비스가 정적 클라이언트, REST API, 실시간 연결을 함께 제공한다.

**기술**

| 영역 | 선택 |
| --- | --- |
| 언어·저장소 | TypeScript, npm workspaces 모노레포 (`client`, `server`, `game-core`, `shared`) |
| 클라이언트 | Vite, React, React Router, Zustand, Three.js + React Three Fiber + drei, Howler.js, 일반 CSS(CSS Modules) |
| 서버 | Node.js 24 LTS, Express, Socket.IO |
| 검증·인증 | Zod(입출력 스키마, `shared`에서 공유), express-session + connect-pg-simple(세션을 DB에 저장), @node-rs/argon2(argon2id) |
| 저장 | PostgreSQL(Neon 무료 플랜), Drizzle ORM + node-postgres |
| 배포 | Render 무료 웹 서비스 1개, 외부 주기 요청으로 절전 방지, Render·Neon 모두 싱가포르 리전 |
| 품질 | Vitest, ESLint(`game-core` import 경계 강제 포함), Prettier, tsx(개발 실행), tsup(서버 빌드) |

**무료 운영 조건** (2026-10-29 확인)

- Render 무료 웹 서비스는 15분 동안 요청이 없으면 절전하고 깨어나는 데 약 1분이 걸린다. 첫 접속 5초 요구를 지키기 위해 외부 모니터링 서비스로 10분 간격의 헬스체크 요청을 보내 절전을 막는다. 월 750 무료 인스턴스 시간은 서비스 1개를 한 달 내내 켜 두기에 충분하다(최대 744시간). 따라서 같은 워크스페이스에 다른 무료 서비스를 두지 않는다.
- Neon 무료 플랜은 5분 동안 활동이 없으면 컴퓨트를 중지하고 월 100 CU-hour를 제공한다. 서버의 DB 연결 풀이 연결을 계속 붙잡으면 중지되지 않아 한도를 넘을 수 있다. 따라서 **유휴 연결을 짧게 닫도록** 설정하고, 헬스체크는 DB를 조회하지 않는다.

## 대안과 절충

- **클라이언트 판정 + 결과 동기화**: 구현은 단순하지만 상대 방해요소를 숨길 수 없고 결과 조작을 막을 수 없어 배제했다.
- **Matter.js 등 물리 엔진**: 기능은 많지만 결정적 재현이 보장되지 않고 높이(떠오름) 처리를 따로 붙여야 한다. 원끼리의 충돌만 필요해 직접 구현이 더 단순하다고 판단했다. 포기한 것은 검증된 충돌 처리와 복잡한 도형 지원이다.
- **3D 물리 엔진(cannon-es, Rapier)**: 떠오름을 자연스럽게 표현할 수 있지만 떠 있는 동안 충돌이 없다는 규칙이라 평면 + 높이로 충분하다. 서버 계산량과 결정성 관리 비용이 커서 배제했다.
- **TanStack Query·Tailwind CSS**: REST 호출이 적고 프로토타입이 일반 CSS라 도입 이점이 작아 제외했다. 필요해지면 추가한다.
- **WebSocket 직접 구현(ws)**: 의존성이 적지만 재연결·방(room) 브로드캐스트·이벤트 구분을 직접 만들어야 해 Socket.IO를 택했다.
- **Supabase**: 무료 DB와 인증을 함께 주지만 1주 미사용 시 프로젝트가 일시정지되고, 이 프로젝트는 자체 세션 인증을 학습 대상으로 삼아 Neon을 택했다.
- **Oracle Cloud 무료 VM**: 절전이 없어 콜드 스타트 문제가 없지만 서버 관리·보안 설정 부담이 커서 대체 경로로 남긴다.

## 영향과 위험

- 모든 설계 문서의 "후보"가 이 선택을 기준으로 정리된다. 세부 계약(API 이벤트 필드, DB 스키마, 상태 전이)은 각 상세 설계 작업에서 확정한다.
- **절전 방지 요청 위험**: Render가 무료 플랜의 주기 요청 사용을 제한하거나 무료 조건을 바꾸면 첫 접속 5초를 지킬 수 없다. 이 경우 Oracle Cloud 무료 VM 이전, 또는 PRD의 대기 허용 시간 재검토로 대응한다.
- **무료 한도 위험**: 같은 워크스페이스에 무료 서비스를 추가하면 750시간을 넘긴다. Neon 연결 설정이 잘못되면 CU-hour 한도를 넘는다. 배포 후 1개월 동안 사용량을 관찰한다([비기능 요구사항](../PRD.md#4-비기능-요구사항과-제약)).
- **서버 메모리 상태**: 서버가 재시작하면 진행 중 경기가 사라진다. PRD에서 서버 장애를 고려하지 않기로 했으므로 수용한다.
- **직접 구현한 물리**: 충돌 안정성(터널링·겹침)을 직접 다뤄야 한다. 고정 시간 간격과 단위 테스트로 완화한다.

## 재검토 조건

- Render·Neon의 무료 조건이 바뀌어 월 0원이나 첫 접속 5초를 지킬 수 없을 때
- 목표 동시 접속이 10명을 크게 넘거나, 서버 재시작 시 경기 보존이 요구될 때
- 떠 있는 알의 충돌 등 물리 규칙이 평면 + 높이로 표현할 수 없게 바뀔 때
- 로컬 2인 모드에서 직접 구현한 물리의 안정성 문제가 반복될 때
