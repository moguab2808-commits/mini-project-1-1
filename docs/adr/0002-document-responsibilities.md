# ADR-0002: 책임별 기준 문서와 작업·검증 근거 분리

DEC ID: [DEC-004](../DECISIONS.md#결정-색인)
결정일: 2026-10-28
상태: 대체됨 — 위치·통합·보관 규칙은 [DEC-005](../DECISIONS.md#결정-색인)가 대체한다. 책임·상태·검증 관리 규칙은 유지한다.
동의 근거: 사용자가 이번 메시지에서 문서별 책임과 파일 위치를 제시하고 AGENTS 및 문서 구조 변경을 지시했다.
대체 관계: [DEC-003 / ADR-0001](0001-product-and-technical-documents.md)의 문서 구조·작업 관리 규칙을 대체한다. 기술 미정 전환은 유지한다.

## 배경

이전 구조는 루트 PRD와 docs의 문서 안내·개발 계획·작업 관리에 책임이 분산돼 있었다. 작업 상태는 Issue, 검증 결과는 PR을 기준으로 했으나 사용자는 TASKS와 날짜별 worklog를 각각 기준으로 삼도록 요청했다.

## 선택과 핵심 조건

사용자가 지정한 기준 문서를 루트에 두고, 상세 제품 문서·설계·ADR·worklog를 책임별 하위 디렉터리로 분리한다. TASKS는 작업 상태·수용 기준, worklog는 날짜별 실행 근거를 관리한다. DESIGN은 진입점으로 유지한다. 현행 역할과 경로는 [AGENTS](../../AGENTS.md)를 따른다.

## 대안과 절충

- 기존 docs 중심 배치와 Issue·PR 기준 관리를 유지: 이동은 적지만 사용자 요청의 탐색·책임 구분을 충족하지 못한다.
- 요청한 기준 문서로 재편: 링크와 양식 수정이 필요하지만 정책·계약·상태·실험 결과의 위치가 명확해진다.

두 번째 방식을 적용한다. 이 프로젝트에 없는 학습 저장·음성 영역의 빈 상세 문서는 추가하지 않는다.

## 영향과 위험

경로 변경으로 링크 누락이나 기존 문서의 책임 설명이 남을 수 있다. 내부 참조와 협업·Issue·PR 양식을 함께 수정하고 링크·앵커·상태 기준을 검증한다. 제품 동작·미정 기술은 새로 승인하지 않는다. 기존 원문과 미채택 개발 단계는 역사 자료로 보존한다.

## 재검토 조건

상세 계약이 커지거나 새로운 제품 영역이 추가될 때 상세 문서 경계를 검토한다. 작업 상태를 다른 시스템으로 이전하려면 TASKS·협업 규칙·양식을 함께 변경하는 새 결정을 남긴다.
