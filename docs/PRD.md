# PRD: 증강 알까기 (Augmented Alkkagi)

버전: v0.11 · 정리일: 2026-10-29 · 상태: 제품 요구사항 초안

이 문서는 누구를 위해 무엇을 만들고, 어디까지 제공하며, 무엇으로 성공을 판단할지를 정의한다. 게임·증강·화면의 상세 요구사항과 보완 의견은 이 문서에서 함께 관리한다. 기술 선정과 구현 방법은 제품 요구사항에서 분리했으며 **기존 기술·설계·구현 계획은 모두 미정으로 재분류**했다.

기존 제품 요구사항은 유지한다. 개별 초안·미완료 항목과 본문이 충돌하면 해당 항목은 합의 전까지 미정이다. 이번 통합은 미정인 게임 규칙을 확정하는 결정이 아니다. 과거 변경은 Git 이력과 [결정 기록](DECISIONS.md)에서 추적한다.

## 1. 개요

### 1.1 한 줄 소개
전통 놀이 알까기에 **증강(능력 강화 카드)** 시스템을 더한, 웹 브라우저에서 즐기는 **1:1 온라인 대전 게임**.

### 1.2 배경

- 스팀 게임 "증강 윷놀이"에서 영감을 받아, 기존 게임에 증강을 추가하는 컨셉을 알까기에 적용한다.
- 출시가 목적이 아닌 **미니프로젝트**이며, 웹 게임을 직접 구축하고 무료로 온라인 배포하는 것을 목표로 한다. 학습을 위한 기술 구성은 [설계](DESIGN.md)에서 별도로 검토한다.

### 1.3 목표

- 서로 다른 PC에서 웹 링크로 접속해 1:1 대전을 할 수 있다.
- 증강 선택이 매 판의 전략을 바꾸는 재미를 검증한다.
- AI 봇과 대전할 수 있다 ([DEC-007](DECISIONS.md#결정-색인)).
- 회원 정보, 전적, 랭킹을 영구 보관한다.
- 모든 인프라를 무료 플랜으로 운영한다.

### 1.4 비목표 (이번 MVP에서 하지 않는 것)

- 상업적 출시, 결제, 광고
- 모바일 최적화 (데스크톱 브라우저 우선)
- 3인 이상 대전, 관전, 리플레이
- 재접속 복구 (끊기면 로그인 화면으로 이동, 진행 중이던 게임은 기권패)
- 소셜 로그인, 이메일 인증, 비밀번호 찾기
- 건의사항 첨부 파일

## 4. 비기능 요구사항과 제약

- 데스크톱 최신 Chrome / Edge, 최소 해상도 1280×720, 한국어 UI를 대상으로 한다.
- 일반 노트북에서 게임 화면 약 60fps를 목표로 한다. 기준 기기·브라우저 버전·측정 조건과 합격 기준은 미정이다.
- 회원 정보와 전적을 영구 보관한다. 재시작·장애 시 진행 중 경기와 세션을 어떻게 처리할지는 미정이다. 일반적인 사용자 연결 끊김 규칙은 게임 규칙을 따른다.
- 비밀번호 원문을 저장하거나 로그에 남기지 않으며, 다른 사용자의 정보·행동을 임의로 바꿀 수 없어야 한다.
- 발사·증강의 유효성 및 상대에게 숨겨야 하는 정보는 게임·증강 규칙을 지켜야 한다. 검증 위치와 구체적인 보안 수단은 미정이다.
- 민감한 설정값을 저장소와 공개 문서에 포함하지 않는다.
- 월 운영 비용 0원을 목표로 한다. 호스팅 업체·무료 한도·운영 방식은 미정이다.
- 배경음악은 MVP에서 제외한다. 음량 조절 기능은 화면 요구사항을 따른다.

### 아직 정하지 않은 제품 정책

- 계정 탈퇴·삭제의 제공 범위, 회원·전적·건의의 보관 기간과 삭제 요청 처리
- 건의 내용을 열람할 수 있는 사용자 범위와 사용자 본인의 재조회·취소 여부
- 서버 장애·동시 이탈·시작 직전 이탈의 경기 성립·무효·전적 처리
- 목표 동시 접속 규모, 첫 접속 대기 허용 시간과 비용 검증의 포함 범위

위 항목은 미정이며 이번 문서 재편에서 정책을 새로 확정하지 않는다. 권한·보관 방법을 구현할 기술은 [상세 설계](DESIGN.md#상세-설계-선택)에서 다룬다.

## 5. 성공 기준

- 서로 다른 PC의 두 사용자가 웹 링크로 접속해 한 판을 끝까지 플레이할 수 있다.
- 증강을 고를 때 선택을 고민하게 된다.
- 한 판을 마친 후 다시 하고 싶어진다.
- 회원 정보와 전적이 서버 재시작 후에도 유지된다.
- 월 비용 0원으로 운영된다.

이 기준은 기존 목표를 유지한 것이다. 재미·재플레이 의향의 측정 방법, 테스트 인원·횟수, 성공률과 관찰 기간은 아직 정하지 않았다. [보완 의견](#prd-보완-의견)에서 제안한다.

## 게임 규칙

상태: 기존 제품 규칙을 이관했다. 아래 미정 항목과 충돌하는 설명은 확정으로 보지 않는다. 상위 범위는 [PRD](#1-개요), 증강은 [증강 규칙](#증강-규칙)을 따른다.

### 기본 규칙

- 1:1 턴제 대전. 선공은 무작위로 정한다.
- 각 플레이어는 같은 개수의 알을 가진다 (기본 5개, 방 생성 시 3~8개 설정).
- 자기 턴에 **자기 알 하나**를 고르고, 마우스를 움직여 발사 방향을 정한다. 마우스 버튼을 누르고 있으면 **세기 막대가 0~100 사이에서 증감**하고, 버튼을 놓는 순간의 세기로 발사한다 ([화면 요구사항](#화면별-요구사항)).
- 판 밖으로 나간 알은 제거된다 (자기 알이 나가도 제거).
- 모든 알이 멈추면 턴이 넘어간다.
- 상대 알을 모두 제거하면 승리한다. 한 번의 발사 결과로 **양쪽 알이 동시에 모두 제거되면 무승부**다 (예: 양쪽에 알이 1개씩 남았을 때 동시에 판 밖으로 떨어지는 경우).

### 턴 제한시간

- 한 턴의 제한시간은 **30초**다. 화면에 남은 시간을 표시한다.
- 제한시간 안에 발사하지 않으면 그 턴은 **넘어간다** (발사 없이 상대 턴).
- 증강을 고르거나 위치를 미리 보는 동안에도 턴 타이머는 멈추지 않는다. 시간초과 시 확정되지 않은 증강 선택은 취소되고 턴이 넘어간다 (임시 기준, [DEC-008](DECISIONS.md#결정-색인)).
- **같은 플레이어가 3번 연속으로 시간초과**하면 **강제 기권**으로 처리하고 상대가 승리한다. 연속 횟수는 플레이어별로 세며, 발사하면 0으로 초기화된다.
- **증강 선택 시간은 20초**다. 증강은 3개가 제시되며 그중 1개를 고른다. 시간 안에 고르지 않으면 후보 3개 중 하나가 무작위로 선택된다.
- 증강 선택 시간초과(무작위 자동 선택)는 **연속 시간초과 횟수에 포함하지 않는다.** 턴 시간초과만 센다.

### 최종 라운드와 승패

- 방 설정과 별개로 게임에는 **최종 라운드**가 있다. 최종 라운드 수 초기값은 **15라운드**다.
- **1라운드 = 양쪽이 각자 턴을 한 번씩 진행**한 것이다. 시간초과로 넘어간 턴도 1턴이며, 쌍발의 추가 발사는 같은 턴 안의 발사이므로 턴 수를 늘리지 않는다 (임시 기준, [DEC-008](DECISIONS.md#결정-색인)).
- 최종 라운드가 끝날 때까지 승부가 나지 않으면 **남은 알이 더 많은 쪽이 승리**한다.
- 남은 알 수가 같으면 **무승부**다.
- 무승부의 레이팅 / 전적 처리는 [아래 랭킹 시스템](#랭킹-시스템)을 따른다.

### 연결 끊김과 중복 접속

- 게임 중 연결이 끊기거나 나가기를 누르면 **기권패**로 처리한다.
- 연결이 끊긴 클라이언트는 **로그인 화면으로 이동**한다 (자동 재접속 복구 없음).
- 같은 계정이 다른 탭 / 기기에서 새로 접속하면 **기존 접속은 로그아웃 처리**한다 (새 접속 우선). 기존 접속이 게임 중이었다면 기권패로 처리한다.

### 판 (Board)

- 방 생성 시 판을 선택한다.
- 판의 크기는 **일반 바둑판과 같거나 더 크게** 한다. 알 크기와 배치도 게임 시작 직후 알이 떨어지지 않도록 정한다. 게임 내 단위로 환산한 구체적인 크기와 원형판의 크기 비교 기준은 아래 미정 사항에서 정한다.
- MVP 판 목록:
  - **기본판**: 정사각형, **바둑판 모양 디자인으로 고정**
  - **원형판**: 원형
- 판 종류는 앞으로 **다양하게 추가할 예정**이다. 확장 구현 방식은 미정이다.

### 랭킹 시스템

경쟁 게임에서 널리 쓰이는 **Elo 레이팅** 방식을 사용한다.

- 신규 가입 시 레이팅 **1000**
- 경기 종료 시 양쪽 레이팅 갱신:
  - 기대 승률: `E_A = 1 / (1 + 10^((R_B - R_A) / 400))`
  - 새 레이팅: `R_A' = R_A + K × (S_A - E_A)` (승리 S=1, **무승부 S=0.5**, 패배 S=0)
  - **K = 32**
  - 갱신한 레이팅은 **정수로 반올림**해 저장·표시한다.
- 강한 상대를 이기면 많이 오르고, 약한 상대에게 지면 많이 내려간다.
- 기권패, 연결 끊김, 3회 연속 시간초과로 인한 강제 기권도 일반 패배와 동일하게 계산한다.
- **배치 경기**: 5판 미만(승 + 패 + 무)은 랭킹에 표시하지 않는다 (레이팅 계산은 첫 판부터 적용).
- 정렬: 레이팅 내림차순 → 동점 시 승수 내림차순. 점수 도달 시각은 사용하지 않으며, 레이팅과 승수가 모두 같으면 같은 순위로 표시한다.
- 승률(`승 / 판수`)은 표시용이며 정렬에는 사용하지 않는다.

## 증강 규칙

상태: 기존 제품 규칙·19종 목록을 이관했다. 초안·미정 항목은 합의 전까지 미정이다. [PRD](#1-개요)의 상세 요구사항이며 구현 구조는 [설계](DESIGN.md)에서 별도로 다룬다.
증강은 선택해서 **보유**하고, 이후 자기 턴에 **직접 사용**하는 방식이다.

**획득**

- **선택 시점**: 게임 시작 시 1회, 이후 3라운드마다 1회 (라운드 정의는 [최종 라운드와 승패](#최종-라운드와-승패)).
- **선택 방식**: 무작위로 제시된 3개 중 1개를 선택한다. 두 플레이어가 동시에 고르며, 양쪽 모두 선택해야 게임이 진행된다 (제한시간 20초). 후보는 플레이어별로 따로 뽑는다.
- **후보 중복 제외**: 나에게 한 번 **후보로 제시된 증강은 이후 내 후보에서 제외**한다 (고르지 않은 증강 포함). 남은 증강이 3개 미만이면 제외 목록을 초기화하고 직전 후보 3개만 제외한다. 이미 보유한 증강도 다시 후보가 될 수 있다 (임시 기준, [DEC-008](DECISIONS.md#결정-색인)).
- 선택한 증강은 게임 화면의 **내 증강 영역**에 표시된다(화면 내 배치는 [게임 화면](#게임-화면)의 미정 항목). 상대가 고른 증강도 상대의 증강 영역에 공개된다.

**사용**

- 사용자는 보유한 증강을 **필요할 때 선택적으로 사용**한다. 사용하지 않고 발사해도 된다.
- **자기 턴에만 최대 1개** 사용할 수 있으며, **증강 사용은 턴을 소비하지 않는다.** 사용 후에도 같은 턴에서 조준하고 발사한다.
- 증강의 적용 대상은 **알** 또는 **위치**다. 증강마다 아래 적용 방식을 정한다.

| 적용 대상 | 적용 방식 | 사용 흐름 |
|---|---|---|
| 알 | **내 알 1개 지정** | 증강 선택 → 내 알 1개 클릭 → 사용. 대상은 **자신의 알만** 가능하며 **발사할 알과 달라도 된다.** |
| 알 | **전체 적용** | 증강 선택 → 증강이 정한 범위의 알 전체에 적용. 개별 알을 직접 지정하지 않는다. 전체의 범위(내 알 / 상대 알 / 양쪽)는 증강별로 명시하며, 미정인 범위는 아래 미정 사항에서 정한다. |
| 위치 | **위치 지정** | 증강 선택 → 판 위 원하는 위치를 클릭해 확정 → 사용. 확정 전 효과 범위를 미리 보여준다. |
| 위치 | **랜덤 위치** | 증강 선택 → 판 위 위치를 무작위로 정해 적용. 사용자가 위치를 직접 고르지 않는다. |

- **내 알 1개 지정 증강의 적용 기준** (임시 기준, [DEC-008](DECISIONS.md#결정-색인)): 효과는 지정한 알을 기준으로 적용된다. 지속이 "그 발사"인 효과는 이번 발사 시뮬레이션이 끝날 때까지다. 강한 발사는 지정한 알을 발사할 때만 효과가 있다. 크기·질량·탄성·마찰 변화와 정지탄·폭발·자석·분열의 충돌·이동 효과는 지정한 알이 발사되지 않았더라도 이 시뮬레이션 안에서 움직이거나 충돌하면 적용된다.
- 쌍발처럼 턴 구조에 적용되는 효과는 별도 대상 지정 없이 사용한다. 부활 등 특수 증강의 대상·배치 세부는 아래 미정 사항에서 정한다.
- 기존 증강의 입력 방식도 이 기준에 맞춘다. **발사할 알에만 적용하는 제한은 없으며**, **상대 알을 직접 선택하는 증강은 제외한다.** 위치 교환은 증강 목록에서 제거한다. 상대 알 전체나 위치·범위에 영향을 주는 증강은 유지한다.

- **상대 턴에 적용되는 증강**: **내 발사 시뮬레이션이 끝난 뒤부터 상대의 바로 다음 한 턴이 끝날 때까지** 적용된다.
- **사용한 증강은 사라진다** (한 번 쓰면 끝). 증강 영역에서 사용한 증강은 **회색**, 아직 사용하지 않은 증강은 **흰색**으로 표시하며 다시 쓸 수 없다.
- **효과 지속 범위**: 기본적으로 증강 효과는 **그 발사 한 번(시뮬레이션이 끝날 때까지)** 에만 적용되고, 알은 다음 턴에 원래 상태로 돌아온다. 아래 표의 **지속** 칸에 따로 적힌 증강(분신, 방어막, 닻, 구멍, 안개, 빙판, 족쇄 등)은 그 규칙을 따른다.
- **한 턴에 사용할 수 있는 증강은 1개**다. 쌍발의 두 번째 발사에서는 증강을 사용할 수 없다.

**사용 확정과 추가 발사**

- 사용이 확정된 증강은 취소할 수 없다. 위치가 유효하고 보유·사용 조건을 만족해야 한다.
- 사용 후 같은 턴에서 별도로 발사한다. 통신 이벤트와 검증 구현은 [설계](DESIGN.md)에서 검토한다.
- 쌍발의 추가 발사·새 제한시간 규칙은 아래 초안과 미정 사항을 함께 따른다.

**MVP 증강 19종** (분류: 나 = 내 알에 적용 / 상대 = 상대에게 영향. 수치와 세부는 플레이 테스트로 조정. 표의 "초안" 표시는 아래 미정 사항에서 확정)

*스탯형 (6종)*

| ID | 이름 | 분류 | 입력 | 지속 | 효과 |
|---|---|---|---|---|---|
| `big-piece` | 큰 알 | 나 | 내 알 1개 지정 | 그 발사 | 알 반지름 증가 |
| `small-piece` | 작은 알 | 나 | 내 알 1개 지정 | 그 발사 | 알 반지름 감소 (상대 알과 부딪힐 면적이 줄고 틈을 지나가기 쉬워짐) |
| `heavy-piece` | 무거운 알 | 나 | 내 알 1개 지정 | 그 발사 | 질량 증가, 발사 속도 소폭 감소 |
| `power-shot` | 강한 발사 | 나 | 내 알 1개 지정 | 그 발사 | 최대 발사 세기 증가 |
| `bouncy` | 탄성 강화 | 나 | 내 알 1개 지정 | 그 발사 | 충돌 시 반발력 증가 |
| `slippery` | 미끄러운 알 | 나 | 내 알 1개 지정 | 그 발사 | 마찰 감소 (더 멀리 미끄러짐) |

*충돌 / 판 이탈에 개입하는 훅형 (7종)*

| ID | 이름 | 분류 | 입력 | 지속 | 효과 |
|---|---|---|---|---|---|
| `decoy` | 분신 | 나 | 내 알 1개 지정 | 상대 알에 맞을 때까지 | 지정한 내 알 주변에 **분신 3개**가 생긴다. **나에게는 진짜 알과 구분되어 보이고, 상대에게는 진짜 알과 똑같이 보인다.** 상대 알이 분신 하나라도 맞히면 **3개가 모두 사라진다.** 분신은 남은 알 개수와 승패 판정에 포함하지 않으며, 개수 표시도 진짜 알만 센다. |
| `shield` | 방어막 | 나 | 내 알 1개 지정 | 한 번 막을 때까지 | 지정한 내 알이 **상대의 공격으로 판 밖에 떨어지게 될 때 1회 막아준다.** 막으면 방어막은 사라진다. |
| `anchor` | 닻 | 나 | 내 알 1개 지정 | 상대의 다음 턴 동안 | 지정한 내 알은 **상대 공격에 밀리지 않는다** (질량 무한). |
| `stopper` | 정지탄 | 나 | 내 알 1개 지정 | 그 발사 | **지정한 내 알이 첫 충돌 직후 즉시 멈춘다.** 지정한 알은 떨어지지 않고 상대만 밀어낸다. |
| `explosion` | 폭발 | 나 | 내 알 1개 지정 | 그 발사 | 첫 충돌 시 주변 알을 밀어내는 폭발 (아군 피해 여부와 범위는 초안) |
| `magnet` | 자석 | 나 | 내 알 1개 지정 | 그 발사 | 이동 중 주변 상대 알을 끌어당김 (범위와 세기는 초안) |
| `split` | 분열 | 나 | 내 알 1개 지정 | 그 발사 | 첫 충돌 시 **임시 조각**이 생긴다. 조각은 그 발사가 끝나면 사라지고 승패와 개수에 영향이 없다 (초안) |

*턴 구조, 상대, 판에 개입하는 특수형 (6종)*

| ID | 이름 | 분류 | 입력 | 지속 | 효과 |
|---|---|---|---|---|---|
| `double-shot` | 쌍발 | 나 | 대상 지정 없음 | 이번 턴 | **이번 턴에 한 번 더 발사**한다 (두 번째 발사는 다른 알이어도 됨). 첫 발사의 시뮬레이션이 끝난 뒤 새 30초 타이머로 두 번째 발사를 입력하며, 이때 증강은 사용할 수 없다 (초안). |
| `revive` | 부활 | 나 | 즉시 | 즉시 | 판 밖으로 떨어진 **내 알 1개를 내 진영에 되살린다.** 떨어진 알이 없으면 사용할 수 없다. (복귀 위치는 초안) |
| `ice` | 빙판 | 상대 | 전체 적용 | 상대의 다음 턴 동안 | 상대 알 전체의 마찰이 감소한다. |
| `shackle` | 족쇄 | 상대 | 전체 적용 | 상대의 다음 턴 동안 | 상대의 **최대 발사 세기가 감소**한다. |
| `hole` | 구멍 | 상대 | 위치 지정 | 상대의 다음 턴 동안 | 판 위 지정 지점에 **구멍**이 생겨, 알(내 알 포함)이 들어가면 떨어진다 (범위는 초안) |
| `fog` | 안개 | 상대 | 위치 지정 | 상대의 다음 턴 동안 | 판 위 **내가 원하는 지점에 안개**를 낀다. **안개 안에 있는 내 알(분신 포함)은 상대 화면에서 보이지 않는다.** 안개의 위치는 상대에게도 보이며, 내 화면에서는 안개 속 알이 반투명하게 보인다. 상대는 안개 속으로 발사할 수 있고 충돌은 정상 적용된다. |

- 직접 지정은 효과 범위를 미리 보여주고 클릭으로 확정한다. 무작위 위치 선정 방식은 미정이다.
- 분신과 안개는 플레이어마다 다른 정보를 보여주는 요구사항이다. 상대가 분신을 진짜 알과 구별하거나 안개 속 알의 위치를 알 수 없어야 한다. 데이터 구성·전송 방식은 미정이다.
- 증강 추가는 [향후 확장](#6-향후-확장-mvp-이후)을 따른다.

### 증강 미정 사항

- [ ] 증강 수치 (플레이 테스트로 조정)
- [ ] 증강별 전체 적용 범위(내 알 / 상대 알 / 양쪽), 랜덤 위치를 적용할 증강과 무작위 위치 선정 규칙
- [ ] **증강 밸런스**: 19종 중 쌍발, 부활은 게임 흐름을 크게 바꾼다. 후보 풀 가중치(등장 확률), 증강 수치를 플레이 테스트로 조정한다. 한 턴 사용 상한은 1개다.
- [ ] **분신 세부**: 생성 위치와 시점(발사 직전 / 직후), 분신도 물리적으로 충돌하는지(상대에게 똑같이 보이려면 충돌해야 함), 분신이 판 밖으로 나가면 어떻게 되는지, 내 알이 분신을 맞히면 어떻게 되는지, 분신 3개가 한꺼번에 사라질 때의 연출 (개수 표시는 진짜 알만 세는 것으로 결정됨)
- [ ] **방어막 / 닻 세부**: 방어막이 막았을 때 알이 어디에 서는지(가장자리 안쪽 복귀 / 튕겨 되돌아옴), 내가 쏜 발사로 스스로 떨어지는 경우는 막지 않는지(현재 가정: 막지 않음), 방어막이 걸린 알을 상대에게 표시할지, 한 알에 여러 증강(방어막 + 닻 등)을 동시에 쓸 수 있는지
- [ ] **안개 세부**: 안개 범위(반지름)와 모양, 안개 속 알이 상대 화면에서 사라지는 연출(서서히 / 즉시), 상대가 안개 속 알을 맞혔을 때 충돌 효과를 보여줄지, 안개 속에서 알이 판 밖으로 떨어질 때 상대에게 보이는지, 안개 속 비공개 정보를 상대에게 노출하지 않는 방법(구현 대안은 [설계](DESIGN.md)에서 검토)
- [ ] **구멍 세부**: 범위와 모양, 구멍이 내 알에도 작용하는지(현재 가정: 작용함), 효과 시작 시점(내 발사 종료 후), 구멍 위에 이미 알이 있을 때 처리
- [ ] **쌍발 세부**: 현재 초안은 두 번째 발사도 새 30초 타이머, 증강 사용 불가. 남은 결정: 두 번째 발사 시간초과가 연속 시간초과 횟수에 반영되는지, 쌍발 중 승패가 결정되면 즉시 종료(현재 가정: 즉시 종료)
- [ ] **부활 세부**: 부활의 알 선택과 복귀 위치(빈 시작 위치 자동 지정 / 직접 지정), 부활이 최종 라운드 승패에 반영되는 방식
- [ ] **분열 조각 처리**: 조각 개수와 크기, 조각이 판 밖으로 나가는 경우, 조각이 승패 / 개수에 영향 없음(현재 가정)을 유지할지
- [ ] 큰 알 / 작은 알의 크기 배율, 판 위 다른 알과 겹치는 위치에서 크기가 바뀔 때의 처리
- [ ] 증강 사용 UI 세부: 상대용 증강 사용 시 상대에게 알림 표시 여부 (선택 취소 방법은 [화면 요구사항](#화면별-요구사항)에서 결정)
- [ ] 증강 선택 주기 (현재: 시작 시 + 3라운드마다)
- [ ] 약점이 있는 증강(트레이드오프형) 추가 여부

## 화면별 요구사항

상태: 기존 화면 요구사항을 이관했다. 기술 선택은 미정으로 전환했다. 미완료 항목과 충돌하는 설명은 확정으로 보지 않는다. 상위 범위는 [PRD](#1-개요)다. 2026-10-29 사용자 요청으로 계정·로비·게임 화면 구성을 바꿨다([DEC-006](DECISIONS.md#결정-색인)).

화면 표현은 저장소 루트의 `알까기 바 (2).html` 프로토타입(3D 바 테이블·캐릭터·Jua 글꼴·나무색 계열)을 기반으로 확장한다. 화면 구성 시안은 [UI-001](TASKS.md#ui-001-로비인게임-화면-프로토타입)의 claude.ai 디자인 캔버스에서 다듬는다. 게임 화면은 3D로 표현하며, 화면 요소의 배치는 디자인 캔버스를 기준으로 한다([DEC-007](DECISIONS.md#결정-색인)). 시안의 표본 데이터·세부 수치는 요구사항이 아니다.

### 로그인

- **닉네임, 비밀번호** 입력 → 로그인 → [로비](#로비)로 이동
- 회원등록으로 전환하는 링크(같은 화면의 탭 전환 여부는 미정)
- 로그인에 **연속 5회 실패**하면 로그인을 제한하고 안내한다. 제한 시간·해제 방법과 실패 횟수를 세는 단위는 미정이다.
- 첫 요청 지연 시 대기 안내를 표시한다. 구체적인 원인·문구·허용 대기 시간은 운영 방식과 함께 정한다.
- 연결 끊김 / 중복 접속으로 이동해 온 경우 사유 안내 메시지 표시

### 회원등록

- 계정은 **닉네임과 비밀번호만으로** 만든다. 별도 아이디는 없으며 닉네임이 로그인 식별자다.
- 입력: **닉네임, 비밀번호, 비밀번호 확인** (이 순서)
- 검증 규칙:
  - 닉네임: 2~12자, **한글 / 영문 / 숫자만 허용** (공백과 특수문자 불가), 중복 불가
  - 비밀번호: 8자 이상
- 가입 성공 시 **로그인 화면으로 이동**하며 가입 완료 안내를 표시한다. 자동 로그인은 하지 않고, 사용자가 로그인한 뒤 접속한다.
- 대소문자·유니코드 정규화 등 닉네임 중복 판정 기준은 미정이다.

### 로비

로그인 직후 화면이다. 기존 메인메뉴·방 참여 화면을 대체한다.

- 레이아웃: **왼쪽에 얇은 프로필바**, 나머지 영역은 **방 화면**.
- **프로필바**: 내 캐릭터, 닉네임, **레이팅, 승률, 전적**(판수 / 승 / 패 / 무)을 표시한다. 프로필을 누르면 [캐릭터 변경](#캐릭터-변경) 창이 열린다. 로그아웃을 제공한다.
- **방 화면**: 현재 생성되어 대기 중인 **공개 방 목록**과 **방 생성 / 즉시 참가 / 코드 입력** 버튼.
  - **방 목록**: 실시간으로 표시하며 **2열 그리드**로 배치한다. 방 카드에는 방 제목, 방장의 닉네임·캐릭터, 방장의 전적(판수 / 승 / 패 / 무)과 승률만 표시한다. 알 개수와 판 종류, 참여 인원은 표시하지 않는다.
  - 방 카드를 누르면 하이라이트 표시와 함께 **`참여` 버튼**이 나타나고, 누르면 입장한다. 같은 방을 다시 누르면 선택이 해제되고 다른 방을 누르면 선택이 바뀐다.
  - **방 생성**: [방 생성](#방-생성) 창을 연다.
  - **즉시 참가**: 대기 중인 공개 방 중 하나에 바로 입장한다. 방 선택 기준과 입장 가능한 방이 없을 때의 처리는 미정이다.
  - **코드 입력**: 비공개 방의 6자리 코드를 입력해 입장한다. 비공개 방은 목록에 보이지 않으며, 방장이 코드를 알려준 사람만 들어갈 수 있다.
- 방이 가득 찼거나 존재하지 않거나 코드가 틀리면 오류 안내를 표시한다.
- 랭킹 / 건의 / 환경설정으로 가는 진입 위치는 미정이다.

### 캐릭터 변경

- 프로필바의 프로필을 누르면 **플로팅 창**으로 열린다. 로비 화면을 덮지 않고 그 위에 떠 있다.
- 선택 가능한 캐릭터 목록에서 하나를 고르면 내 캐릭터가 바뀐다. 캐릭터는 프로필바, 방 카드, 게임 화면에 표시된다.
- 캐릭터 종류·수, 획득 조건(전부 기본 제공 / 해금), 적용 시점(선택 즉시 / 확인 버튼)과 계정에 저장하는지는 미정이다.

### 방 생성

- **방 제목**: 기본값 `{닉네임}의 방`, 수정 가능 (최대 20자)
- **알 개수**: 기본 5개, 3~8개 선택
- **판 선택**: 판 목록에서 선택 (미리보기 표시)
- **공개 여부**: 공개 / 비공개 중 선택
  - **공개**: 방 목록에 노출되며 **방 코드는 표시하지 않는다**. 방 목록에서 클릭해 입장한다.
  - **비공개**: 방 목록에 노출되지 않고, **방 코드가 6자리로 자동 생성**된다 (수정 불가, 혼동되는 문자 0/O, 1/I 제외). 코드를 아는 사람만 입장할 수 있다.
- 생성 후 대기실에서 상대 입장을 기다린다. 비공개 방은 방 코드 복사 버튼을 제공한다.

### 대기실

- 표시: 방 제목, 판 종류, 알 개수, 방장과 상대의 닉네임 / 레이팅 / 전적. 상대가 없으면 "상대를 기다리는 중" 표시. 비공개 방은 방 코드와 복사 버튼.
- 버튼: **시작**(방장만, 상대가 입장했을 때만 활성), **나가기**.
- **게임 시작 방식**: 방장이 시작 버튼을 누르면 게임이 시작된다 (자동 시작 안 함).
- **방장이 나가면** 방이 닫히고 상대는 안내 메시지와 함께 [로비](#로비)로 이동한다.
- **상대가 나가면** 방은 유지되고 다시 상대를 기다리는 상태로 돌아간다. 공개 방은 방 목록에 다시 노출된다.
- 게임이 시작되면 방은 목록에서 사라진다.

방 참여(공개 방 목록·코드 입장)는 [로비](#로비)에서 제공한다.

### 프로필

- 로비 프로필바의 요약(레이팅·승률·전적)과 별도로, 상세 프로필 화면의 제공 여부와 진입 위치는 미정이다. 아래는 상세 프로필을 제공할 때의 기존 요구사항이다.
- 표시: 닉네임, 캐릭터, 레이팅, 전적(총 판수 / 승 / 패 / 무), 승률, 최근 경기 10개
- 수정 가능: **비밀번호** (현재 비밀번호 + 새 비밀번호 입력 방식)
- 닉네임은 로그인 식별자이므로 **변경할 수 없다**.
- 수정 불가: 레이팅, 전적, 승률
- 비밀번호는 `********`처럼 **\* 표시로만** 나타낸다 (고정된 마스킹 문자열이며 실제 비밀번호나 글자 수는 노출하지 않는다).

### 랭킹

- 정렬 기준은 [게임 규칙](#랭킹-시스템) 참고 (Elo 레이팅)
- 표시: 순위, 닉네임, 레이팅, 판수, 승, 패, 무, 승률
- **10명씩 페이지로** 나누어 보여주고, **최대 5페이지(50위)** 까지만 표시한다. 내 순위는 목록 하단에 별도 표시
- 배치 경기(5판) 미만 사용자는 랭킹에 표시하지 않고 "배치 중"으로 안내

### 건의

- 입력: 제목(최대 100자), 내용(최대 2000자)
- 제출한 내용을 보관하고 완료 메시지를 표시
- 첨부 파일은 MVP 이후 추가
- 건의 내용은 개발자가 확인한다. 확인 방법은 미정이며 관리자 화면은 MVP 이후다.

### 환경설정

- 게임 음량 (효과음 0~100)
- 설정 저장 위치와 유지 범위(브라우저·계정 등)는 미정이다. 기존 localStorage 방식은 설계 후보로 이동했다.

### 게임 화면

- 레이아웃 (최소 해상도 1280×720): **화면 가운데에 알까기 판**, 판을 사이에 두고 **두 플레이어 캐릭터**가 있다.
  - **오른쪽 하단에 내 프로필**, **왼쪽 상단에 상대 프로필**을 표시한다. 프로필에는 캐릭터, 닉네임, 레이팅, 승률을 표시한다.
  - 프로필은 **배경 패널 없이(투명)** 표시해 뒤의 게임 장면이 보이게 하고, 글자 그림자로 가독성을 보조한다.
  - 기존 오른쪽 30% 정보 패널은 사용하지 않는다. 디자인 캔버스 기준으로 **턴·남은 시간·라운드는 화면 위쪽 가운데**, **남은 알 개수는 각 프로필 아래 점 표시**, **기권 버튼은 왼쪽 하단**에 둔다. 증강 영역의 배치는 미정이다.
- 게임판:
  - 내 알과 상대 알을 색상으로 구분한다. 판·알·캐릭터는 **3D로 표현**한다. 렌더링 라이브러리는 [설계](DESIGN.md)에서 정한다.
  - **카메라**: 내 알이 있는 방향에서 바라보는 **고정 시점** (자유 회전 없음). 두 플레이어 모두 내 알이 아래쪽, 상대 알이 위쪽으로 보인다. 좌표계와 카메라 구현 방식은 미정이다.
  - **조준·발사 규칙**: 내 턴에 내 알을 클릭해 선택한 뒤, 알을 기준으로 마우스를 돌려 **발사 방향**을 정한다. 조준선으로 방향을 표시한다. 이후 **마우스 버튼을 누르고 있으면 세기 막대가 0에서 시작해 100까지 증가하고, 100에 도달하면 0까지 감소하는 동작을 반복**한다. **버튼을 놓는 순간 표시된 세기(0~100)로 발사**한다. 증감 속도, 누르는 동안 방향 변경 가능 여부, 세기 0에서 놓았을 때의 처리와 취소 조작은 아래 미정 사항에서 정한다.
  - 두 사용자에게 같은 발사 결과를 보여준다. 계산·전달·재생 방식은 미정이다.
  - 판 밖으로 나간 알은 **떨어지는 연출**(중력 애니메이션, 회전)을 시각 효과로만 보여주고, 게임 판정에는 "제거됨"만 반영한다. 판정·기록 위치는 [설계](DESIGN.md)에서 정하며 미정이다.
- 게임 정보:
  - 현재 턴 표시와 **턴 남은 시간(30초)**
  - 현재 라운드 / 최종 라운드
  - **증강 영역**: 내가 보유한 증강을 표시한다. **미사용 증강은 흰색, 사용한 증강은 회색**으로 표시한다. 내 턴에만 증강을 선택할 수 있고, 선택한 증강의 **적용 방식**([증강 규칙](#증강-규칙))에 따라 내 알 1개 지정, 전체 적용, 위치 지정, 랜덤 위치로 사용한다. 증강을 사용해도 턴은 유지되며 발사를 이어갈 수 있다. 상대의 증강 영역도 같은 방식으로 표시된다.
  - **증강 선택 / 취소**: 선택 상태의 증강을 **다시 클릭하거나 ESC**로 취소한다. 사용이 확정된 증강은 취소할 수 없다. 한 턴에 증강은 최대 1개만 사용할 수 있다.
  - **위치 지정 미리보기**: 구멍과 안개는 증강을 선택하면 마우스 위치에 효과 범위(원)를 미리 보여주고, 클릭으로 위치를 확정한다. 확정 전에는 이동 / 취소가 가능하다. 랜덤 위치 적용은 직접 위치를 고르는 단계가 없다.
  - **분신 표시**: 내가 만든 분신은 내 화면에서만 진짜 알과 구분해서 보여준다 (예: 반투명 / 테두리). 상대 화면에서는 진짜 알과 똑같이 보인다.
  - **방어막 표시**: 방어막이 걸린 내 알에는 표시(예: 빛나는 테두리)를 한다. 상대에게도 보일지는 아래 미정 사항 참고.
  - 남은 알 개수
  - 기권 버튼
- 증강 선택 시 화면 위에 카드 3장을 오버레이로 표시 (남은 시간 20초 표시)
- 게임 종료 시 결과(승 / 패 / 무, 레이팅 변화)를 표시하고 **재도전하기 / 나가기** 버튼을 제공한다. 나가기는 [로비](#로비)로 이동한다.
  - 재도전하기의 상대 동의 필요 여부, 같은 방·설정 유지, 한쪽만 누르거나 상대가 나간 경우의 처리는 미정이다.

## PRD 보완 의견

2026-10-28 제품 요구사항을 검토한 의견이다. 아래 가설·예시·우선순위 제안은 합의된 요구사항이 아니며 제품 범위를 변경하지 않는다.

현재 문서는 게임 규칙과 화면 정보가 상세하다. 먼저 보완할 부분은 “누구에게 어떤 재미를 검증할지”, “어디까지 완성하면 MVP인지”, “무엇을 관찰하면 성공인지”다. 미니프로젝트인 만큼 시장 규모나 사업 계획을 길게 추가하기보다 플레이 가설과 완료 기준을 분명히 하는 편이 유용하다.

### 문제·가치 가설 예시

> 검토용 가설: 지인과 설치 없이 대전하고 싶은 데스크톱 사용자가 익숙한 알까기 규칙으로 시작하고, 매번 다른 증강 선택으로 새로운 전략을 시도한다.

이 가설은 실제 사용자 의견으로 확인해야 한다. “증강이 있으면 재미있다”와 “기본 조작 자체가 재미있다”를 나누어 관찰하면 증강 종류를 늘리는 것이 필요한지 판단하기 쉽다.

### 성공 지표를 구체화하는 방법

| 기존 기준 | 추가로 정할 내용 | 검증 방법 제안 |
| --- | --- | --- |
| 서로 다른 PC에서 한 판 완료 | 시도 수·완료율·방해 오류의 정의 | 방 생성부터 결과 확인까지 진행하고 중단 원인을 기록 |
| 증강 선택을 고민 | 선택 이유 설명 여부·특정 후보 쏠림·관찰 횟수 | 플레이 후 고른 이유와 선택에 영향을 준 상황을 질문 |
| 다시 하고 싶음 | 재대전 의향 응답·자발적 재대전 여부·목표 비율 | 한 판 후 의향을 묻고 다음 판 시작 행동을 함께 관찰 |
| 전적이 재시작 후 유지 | 확인할 데이터·재시작 절차·일치 기준 | 경기 전후와 재시작 후 회원·전적·레이팅을 비교 |
| 월 비용 0원 | 포함 비용·무료 한도·관찰 기간 | 배포 후 사용량과 실제 청구를 확인 |

목표 숫자는 아직 제안하지 않는다. 예상 참여자 수와 테스트 가능 횟수를 정한 뒤 합의해야 임의의 숫자가 출시 조건이 되는 일을 피할 수 있다. 첫 테스트 후 목표를 조정한다면 조정 근거도 결정 기록에 남긴다.

### 수용 기준 작성 예시

아래는 기존 동작을 검사 가능한 문장으로 바꾸는 예시다. ID 체계와 검사 범위는 아직 미정이다.

- `ROOM-JOIN`: 대기 중인 공개 방을 선택하고 참여했을 때 대기실에 두 사용자가 표시되고, 방장에게 시작 버튼이 활성화된다.
- `AUGMENT-USE`: 내 턴에 보유한 미사용 증강 하나를 유효한 대상에 사용하면 사용됨으로 표시되고, 턴을 유지한 채 발사할 수 있다. 같은 턴의 두 번째 증강 사용은 거부된다.
- `TURN-TIMEOUT`: 30초 동안 발사하지 않으면 상대 턴으로 넘어간다. 같은 사용자의 연속 시간초과가 3회가 되면 기권패로 종료한다.

위 예시는 [TASKS](TASKS.md)의 작업별 수용 기준을 작성할 때 참고한다.

### 결정 순서 제안

1. 핵심 사용자 상황과 재미 가설을 정한다.
2. 출시 필수 기능과 증강 범위를 정한다. 건의·랭킹 등 부가 기능의 우선순위도 함께 검토한다.
3. 성공 지표와 핵심 기능 수용 기준을 정한다.
4. 게임 흐름을 막는 미정 규칙·예외 처리를 합의한다.
5. 이 요구사항을 충족할 기술·설계를 비교하고 개발 계획을 다시 작성한다.

기존 기능을 삭제하거나 위 제안을 확정하려면 관련 작업과 [결정 기록](DECISIONS.md)에 근거를 남기고 해당 기준 문서를 갱신한다.
