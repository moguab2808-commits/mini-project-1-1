# PRD: 증강 알까기 (Augmented Alkkagi)

버전: v0.17 · 정리일: 2026-10-30 · 상태: 제품 요구사항 초안

이 문서는 누구를 위해 무엇을 만들고, 어디까지 제공하며, 무엇으로 성공을 판단할지를 정의한다. 게임·방해요소·화면의 상세 요구사항과 보완 의견은 이 문서에서 함께 관리한다. 기술 선정과 구현 방법은 [설계](DESIGN.md)에서 다룬다.

2026-10-30까지 승인된 결정([DEC-006~DEC-026](DECISIONS.md#결정-색인))을 반영했다. 랭킹·레이팅 제외, 로비·방 생성·AI 대전 진입, 알 개수, 로그인 제한은 개발자 B의 검토 의견을 사용자가 채택한 [DEC-022·024·025](DECISIONS.md#결정-색인)가 이전 결정을 대체한다. [DEC-012](DECISIONS.md#결정-색인)는 사용자가 판단을 위임해 Claude가 정한 항목이며, 플레이 테스트나 사용자 검토로 바꿀 수 있다. "임시 기준"으로 표시한 규칙은 재검토할 예정이다. 정하지 않은 항목은 각 절의 미정 사항에 둔다. 과거 변경은 Git 이력과 [결정 기록](DECISIONS.md)에서 추적한다.

## 1. 개요

### 1.1 한 줄 소개
전통 놀이 알까기에 무작위로 받는 **방해요소** 시스템을 더한, 웹 브라우저에서 즐기는 **1:1 온라인 대전 게임**.

### 1.2 배경

- 스팀 게임 "증강 윷놀이"에서 영감을 받아, 기존 게임에 특수 규칙을 더하는 컨셉을 알까기에 적용한다. 처음 구상한 증강은 2026-10-29 방해요소로 대체했다([DEC-010](DECISIONS.md#결정-색인)).
- 출시가 목적이 아닌 **미니프로젝트**이며, 웹 게임을 직접 구축하고 무료로 온라인 배포하는 것을 목표로 한다. 학습을 위한 기술 구성은 [설계](DESIGN.md)에서 별도로 검토한다.

### 1.3 사용 상황과 핵심 경험

- **사용 상황**: 개발자와 지인이 설치 없이 링크 하나로 모여, 쉬는 시간에 한 판(10분 이내)씩 가볍게 겨룬다.
- **핵심 경험**: 익숙한 알까기 조작에, 상대가 조준하는 동안 방해요소로 상대를 흔드는 재미를 더한다. 상대가 무엇을 가졌는지 모르는 긴장감과 "언제 쓸지"의 판단이 매 판을 다르게 만든다.

### 1.4 목표

- 서로 다른 PC에서 웹 링크로 접속해 1:1 대전을 할 수 있다.
- 무작위로 받는 방해요소가 매 판의 전략을 바꾸는 재미를 검증한다.
- AI 봇과 대전할 수 있다 ([DEC-007](DECISIONS.md#결정-색인)).
- 회원 정보와 전적(판수·승·패)을 영구 보관한다.
- 모든 인프라를 무료 플랜으로 운영한다.

### 1.5 비목표 (이번 MVP에서 하지 않는 것)

- 상업적 출시, 결제, 광고
- 모바일 최적화 (데스크톱 브라우저 우선)
- 3인 이상 대전, 관전, 리플레이
- 재접속 복구 (끊기면 로그인 화면으로 이동, 진행 중이던 게임은 기권패)
- 소셜 로그인, 이메일 인증, 비밀번호 찾기
- 건의 기능 ([DEC-011](DECISIONS.md#결정-색인))
- 계정 탈퇴·삭제
- 상세 프로필 화면·최근 경기 목록 ([DEC-012](DECISIONS.md#결정-색인))
- AI 난이도 선택
- 랭킹·레이팅, 경기별 기록 저장 ([DEC-022](DECISIONS.md#결정-색인))

## 4. 비기능 요구사항과 제약

- 데스크톱 최신 Chrome / Edge, 최소 해상도 1280×720, 한국어 UI를 대상으로 한다.
- 게임 화면은 **평균 60fps에 가깝게, 하위 5% 구간 30fps 이상**을 목표로 한다. 기준은 개발자 노트북의 최신 Chrome, 1280×720 창에서 한 판을 끝까지 플레이한 구간이다. 측정 방법은 [검증 계획](ENGINEERING-VALIDATION.md)을 따른다.
- 회원 정보와 전적은 **기간 제한 없이** 보관한다. 계정 탈퇴·삭제는 제공하지 않는다.
- MVP에서는 **서버 장애 상황을 고려하지 않는다**. 서버 재시작·장애 시 진행 중 경기와 세션의 처리 규칙을 두지 않는다. 사용자 연결 끊김 규칙은 [게임 규칙](#연결-끊김과-중복-접속)을 따른다.
- 목표 동시 접속 규모는 **10명**이다.
- 첫 접속 시 대기 허용 시간은 **5초**다.
- 비밀번호 원문을 저장하거나 로그에 남기지 않으며, 다른 사용자의 정보·행동을 임의로 바꿀 수 없어야 한다.
- 발사·방해요소의 유효성과 상대에게 숨겨야 하는 정보(상대가 가진 방해요소)는 게임·방해요소 규칙을 지켜야 한다. 검증 위치와 구체적인 보안 수단은 [설계](DESIGN.md)에서 정한다.
- 민감한 설정값을 저장소와 공개 문서에 포함하지 않는다.
- **월 운영 비용 0원**을 목표로 한다. 호스팅·DB·도메인 등 운영에 드는 모든 비용을 포함하며, 배포 후 1개월 동안 실제 청구로 확인한다. 호스팅 업체·무료 한도는 [설계](DESIGN.md)에서 정한다.
- 배경음악은 MVP에서 제외한다. 효과음과 음량 조절은 [환경설정](#환경설정)·[게임 화면](#게임-화면)을 따른다.
- 내 알과 상대 알은 색상 외에 **무늬(테두리)로도 구분**한다. 시야 방해는 화면을 완전히 가리지 않는다([방해요소 규칙](#방해요소-규칙)).

## 5. 성공 기준

| 기준 | 판정 방법 |
| --- | --- |
| 서로 다른 PC의 두 사용자가 웹 링크로 접속해 한 판을 끝까지 플레이할 수 있다 | 지인 4명 이상이 각 3판 이상 플레이했을 때 오류로 중단되지 않고 끝난 판이 90% 이상 |
| 받은 방해요소를 언제 어떻게 쓸지 고민하게 된다 | 플레이 후 질문에서 응답자 과반이 방해요소를 쓴 시점과 이유를 설명할 수 있음 |
| 한 판을 마친 후 다시 하고 싶어진다 | 응답자 과반이 재대전 의향을 밝히거나, 결과 화면에서 재도전하기가 성립한 판이 과반 |

| 월 비용 0원으로 운영된다 | 배포 후 1개월 동안 실제 청구 0원 |

판정용 플레이 테스트의 기록 방법은 [보완 의견](#prd-보완-의견)의 제안을 참고하고, 실제 결과는 worklog에 남긴다.

## 게임 규칙

상태: 2026-10-29 결정까지 반영했다. 상위 범위는 [PRD](#1-개요), 방해요소는 [방해요소 규칙](#방해요소-규칙)을 따른다.

### 기본 규칙

- 1:1 턴제 대전. 선공은 무작위로 정하며, 선공에 대한 별도 보정은 두지 않는다 (플레이 테스트로 재검토).
- 각 플레이어는 같은 개수의 알을 가진다 (기본 5개, 방 생성 시 5·7·9개 중 선택).
- 자기 턴에 **자기 알 하나**를 고르고, 마우스를 움직여 발사 방향을 정한다. 마우스 버튼을 누르고 있으면 **세기 막대가 0~100 사이에서 증감**하고, 버튼을 놓는 순간의 세기로 발사한다 ([조준·발사 조작](#조준발사-조작)).
- 판 밖으로 나간 알은 제거된다 (자기 알이 나가도 제거).
- 모든 알이 멈추면 턴이 넘어간다.
- 상대 알을 모두 제거하면 승리한다. 한 번의 발사 결과로 **양쪽 알이 동시에 모두 제거되면 무승부**다 (예: 양쪽에 알이 1개씩 남았을 때 동시에 판 밖으로 떨어지는 경우). 시뮬레이션 도중 어느 쪽이 먼저 0개가 됐는지는 따지지 않고, 그 발사가 끝났을 때 양쪽 모두 0개면 무승부다.

### 조준·발사 조작

- 내 턴에 내 알을 클릭해 선택하고, 알을 기준으로 마우스를 돌려 방향을 정한다. 조준선으로 방향을 표시한다.
- 마우스 버튼을 누르고 있으면 세기 막대가 0에서 100까지 오르고 다시 0까지 내려가기를 반복한다. **한 번 오르내리는 데 2초**가 걸린다.
- 버튼을 누르고 있는 동안에도 마우스로 **방향을 바꿀 수 있다**.
- 버튼을 놓으면 그 순간의 세기로 발사한다. **세기 0에서 놓으면 발사하지 않고** 조준 상태로 돌아간다.
- 버튼을 누르고 있는 중에 **오른쪽 클릭이나 ESC**를 누르면 발사를 취소한다. 다른 알을 클릭하면 선택이 바뀐다.
- 세기 막대는 선택한 알 옆에 **세로 막대**로 표시한다.

### 알 떠오름

- 세기 **80 이상**으로 발사하면 알이 지면에서 떠올랐다가 떨어진다. 세기가 클수록 높고 멀리 뜬다. 최대 높이는 알 지름의 2배다.
- 떠 있는 동안에는 **다른 알과 충돌하지 않고** 위를 지나간다. 착지한 뒤부터 다시 충돌한다.
- 착지 지점이 판 밖이면 그 알은 제거된다.

### 턴 제한시간

- 한 턴의 제한시간은 **30초**다. 화면에 남은 시간을 표시한다. 방해요소의 효과(기절 포함) 중에도 타이머는 멈추지 않는다.
- 제한시간 안에 발사하지 않으면 그 턴은 **넘어간다** (발사 없이 상대 턴).
- **같은 플레이어가 3번 연속으로 시간초과**하면 **강제 기권**으로 처리하고 상대가 승리한다. 연속 횟수는 플레이어별로 세며, 발사하면 0으로 초기화된다.

### 최종 라운드와 승패

- 방 설정과 별개로 게임에는 **최종 라운드**가 있다. 최종 라운드는 **10라운드**다([DEC-010](DECISIONS.md#결정-색인)).
- **1라운드 = 양쪽이 각자 턴을 한 번씩 진행**한 것이다. 시간초과로 넘어간 턴도 1턴이다 (임시 기준, [DEC-008](DECISIONS.md#결정-색인)).
- 최종 라운드가 끝날 때까지 승부가 나지 않으면 **남은 알이 더 많은 쪽이 승리**한다.
- 남은 알 수가 같으면 **무승부**다.
- 무승부의 전적 처리는 [아래 전적](#전적)을 따른다.

### 연결 끊김과 중복 접속

- 게임 중 연결이 끊기거나 나가기를 누르는 등 **이유와 관계없이 한쪽이 경기에서 이탈하면 그 플레이어의 기권패**로 처리한다.
- 양쪽이 모두 이탈하면 서버가 **이탈을 먼저 확인한 플레이어를 기권패**로 처리한다.
- 게임 시작 직전에 이탈한 경우는 **서버에 남은 로그를 기준으로** 판단한다. 서버가 게임 시작을 처리하기 전에 나갔으면 대기실 이탈로 보고 전적에 남기지 않는다. 처리한 뒤에 나갔으면 기권패다.
- 연결이 끊긴 클라이언트는 **로그인 화면으로 이동**한다 (자동 재접속 복구 없음).
- 같은 계정이 다른 탭 / 기기에서 새로 접속하면 **기존 접속은 로그아웃 처리**한다 (새 접속 우선). 기존 접속이 게임 중이었다면 기권패로 처리한다.

### 판 (Board)

- 방 생성 시 판을 선택한다.
- 게임 내 길이 단위는 **1단위 = 1cm**로 본다. 실제 바둑판(약 45×42cm)과 바둑알(지름 약 2.2cm)을 기준으로 한다.
- MVP 판 목록:
  - **기본판**: 한 변 **46단위**의 정사각형, **바둑판 모양 디자인으로 고정**
  - **원형판**: 지름 **52단위**의 원형 (기본판과 면적이 거의 같음)
- 알 지름은 **2.2단위**다.
- 판 종류는 앞으로 **다양하게 추가할 예정**이다. 확장 구현 방식은 [설계](DESIGN.md)에서 정한다.

### 알 초기 배치

- 각 플레이어의 알은 자기 쪽 가장자리에서 판 길이의 1/4 지점에 **가로 한 줄로 같은 간격**으로 놓는다. 알 개수(5·7·9개)와 관계없이 같은 규칙을 쓴다.
- 원형판은 같은 거리의 **호** 위에 같은 간격으로 놓는다.
- 양쪽 배치는 판 중심을 기준으로 대칭이다.

### 전적

랭킹·레이팅·경기별 기록은 MVP에서 제공하지 않는다. 사용자마다 누적 전적만 저장한다([DEC-022](DECISIONS.md#결정-색인)).

- 경기가 끝나면 두 사용자의 **판수**를 1 늘리고, 승자는 **승**, 패자는 **패**를 1 늘린다. 무승부는 판수에만 더한다(무 = 판수 − 승 − 패).
- 기권패, 연결 끊김, 3회 연속 시간초과로 인한 강제 기권도 패배로 센다.
- 승률(`승 / 판수`)은 표시용이다.
- AI 대전은 전적에 반영하지 않는다.

### AI 대전

- [방 생성](#방-생성) 창에서 대전 상대를 **AI**로 고르고 판과 알 개수를 정하면 시작한다. AI 대전은 방 목록에 올리지 않고 브라우저에서 진행하며, 서버·DB에 아무것도 남기지 않는다([DEC-021](DECISIONS.md#결정-색인)·[DEC-024](DECISIONS.md#결정-색인)).
- 난이도는 1단계(보통)만 제공한다. AI의 조준에는 무작위 오차를 둔다.
- AI도 같은 규칙으로 방해요소를 받고, 내 턴 중 무작위 시점에 사용 가능한 방해요소를 쓴다.
- 결과 화면은 같다. 재도전하기를 누르면 같은 설정으로 바로 새 AI 대전을 시작한다.

### 게임 미정 사항

- [ ] 마찰·반발계수·최대 발사 속도 등 물리 수치 (이후 정함, 플레이 테스트로 조정)

## 방해요소 규칙

상태: 2026-10-29 사용자 요청으로 기존 증강 시스템을 방해요소로 대체했다([DEC-010](DECISIONS.md#결정-색인)). 공통 규칙과 방해요소별 효과는 [DEC-012](DECISIONS.md#결정-색인)에서 정했다. 이전 증강 19종과 사용 규칙은 Git 이력에서 확인한다.

### 지급과 보유

현재 교체·사용 규칙은 [DEC-014·015·017](DECISIONS.md#결정-색인)을 따른다.

- 경기는 10라운드이며, **1·3·5·7·9라운드 시작 시** 각 플레이어의 방해요소를 무작위로 정한다. **각자 동시에 보유하는 방해요소는 1개**이며, 새 지급 시 기존 방해요소·효과·게이지·쿨타임을 모두 제거하고 새 방해요소 기준으로 시작한다. 후보를 고르는 단계는 없다. ([DEC-014](DECISIONS.md#결정-색인))
- 두 플레이어는 각자 따로 뽑는다. 교체는 새 추첨이므로 직전과 같은 종류가 다시 나올 수 있다.
- **상대가 가진 방해요소의 종류는 볼 수 없다.** 받은 방해요소는 나에게만 알리고, 내 화면의 방해요소 영역에만 표시한다.
- 받은 방해요소는 **다음 교체 시점까지 보유**하며, 쿨타임·게이지 등 해당 분류의 제한에 맞춰 반복해서 쓸 수 있다.

### 사용

- 방해요소는 **게임 진행 중 내 턴·상대 턴 모두, 조준 여부와 관계없이, 알이 움직이는 도중에도** 사용할 수 있다. 보유한 방해요소의 게이지·쿨타임·효과 진행 제한은 지켜야 한다. 대기실과 경기 종료 후에는 사용할 수 없다. ([DEC-015](DECISIONS.md#결정-색인))
- 방해요소 영역의 카드 1개를 클릭해 사용한다. 단일 보유에 맞춘 숫자키 단축키는 LOCAL-001에서 정한다. 위치를 정하는 방해요소는 사용 후 판 위를 클릭해 위치를 확정하고, 확정 전에는 효과 범위를 미리 보여주며 ESC로 취소할 수 있다. 벽은 판 위의 빈 위치만 선택할 수 있도록 격자 후보를 표시한다. 배치 가능한 후보는 초록색, 불가능한 후보는 빨간색으로 표시한다.
- 효과가 진행 중인 방해요소가 있으면 끝날 때까지 다른 방해요소를 사용할 수 없다. 즉시 끝나는 방해요소는 이 제한에 걸리지 않는다.
- 방해요소가 발동하면 **이름과 효과를 양쪽 화면에 모두 표시**한다. 비공개는 "무엇을 가지고 있는가"이며, 사용된 효과는 숨기지 않는다.

## 화면별 요구사항

상태: 2026-10-29 결정까지 반영했다([DEC-006](DECISIONS.md#결정-색인)·[DEC-007](DECISIONS.md#결정-색인)·[DEC-009~DEC-012](DECISIONS.md#결정-색인)). 상위 범위는 [PRD](#1-개요)다.

화면 표현은 저장소 루트의 `알까기 바 (2).html` 프로토타입(3D 바 테이블·캐릭터·Jua 글꼴·나무색 계열)을 기반으로 확장한다. 화면 구성 시안은 [UI-001](TASKS.md#ui-001-로비인게임-화면-프로토타입)의 claude.ai 디자인 캔버스에서 다듬는다. 게임 화면은 3D로 표현하며, 화면 요소의 배치는 디자인 캔버스를 기준으로 하되 이후 이 문서에서 바꾼 배치가 우선한다([DEC-007](DECISIONS.md#결정-색인)·[DEC-009](DECISIONS.md#결정-색인)). 시안의 표본 데이터·세부 수치는 요구사항이 아니다.

### 공통 안내

- 요청이 진행 중이면 해당 버튼을 비활성화하고 로딩 표시를 한다 (중복 클릭 방지).
- 요청 실패·만료된 방 등 오류는 화면 위쪽에 **3초간 토스트 메시지**로 안내한다.
- 목록이 비어 있으면 빈 상태 문구를 표시한다 (예: "대기 중인 방이 없어요").
- 처음 로그인한 사용자에게는 규칙 설명 카드 1장(조작·승패·방해요소)을 보여준다. 환경설정에서 다시 볼 수 있다.

### 로그인

- **닉네임, 비밀번호** 입력 → 로그인 → [로비](#로비)로 이동
- 로그인과 회원등록은 **같은 화면의 탭**으로 전환한다.
- 같은 IP에서 로그인·회원등록 등 인증 요청이 **1분에 20회**를 넘으면 요청을 거부하고 잠시 후 다시 시도하라고 안내한다. 닉네임별 실패 횟수 제한은 두지 않는다([DEC-025](DECISIONS.md#결정-색인)).
- 첫 요청 지연 시 "서버를 깨우는 중이에요" 대기 안내를 표시한다. 허용 대기 시간은 5초다([비기능 요구사항](#4-비기능-요구사항과-제약)).
- 연결 끊김 / 중복 접속으로 이동해 온 경우 사유 안내 메시지 표시

### 회원등록

- 계정은 **닉네임과 비밀번호만으로** 만든다. 별도 아이디는 없으며 닉네임이 로그인 식별자다.
- 입력: **닉네임, 비밀번호, 비밀번호 확인** (이 순서)
- 검증 규칙:
  - 닉네임: 2~12자, **한글 / 영문 / 숫자만 허용** (공백과 특수문자 불가), 중복 불가
  - 중복 판정은 유니코드 NFC 정규화 후 **영문 대소문자를 구분하지 않고** 비교한다. 표시는 가입할 때 입력한 그대로 한다.
  - 비밀번호: 8자 이상 64자 이하
- 가입 성공 시 **로그인 탭으로 이동**하며 가입 완료 안내를 표시한다. 자동 로그인은 하지 않고, 사용자가 로그인한 뒤 접속한다.

### 로비

로그인 직후 화면이다. 기존 메인메뉴·방 참여 화면을 대체한다.

- 레이아웃: **왼쪽에 얇은 프로필바**, 나머지 영역은 **방 화면**.
- **프로필바**: 내 캐릭터, 닉네임, **승률, 전적**(판수 / 승 / 패 / 무)을 표시한다. 프로필을 누르면 [캐릭터 변경](#캐릭터-변경) 창이 열린다. 아래쪽에 **환경설정·로그아웃** 버튼을 둔다.
- **방 화면**: **방 목록**과 **방 생성 / 즉시 참가 / 코드 입력 / 새로고침** 버튼 ([DEC-024](DECISIONS.md#결정-색인)).
  - **방 목록**: 로비에 들어올 때와 **새로고침** 버튼을 누를 때 갱신하며(자동 실시간 갱신 없음) **2열 그리드**로 배치한다. 공개 방과 비공개 방을 모두 표시하고 비공개 방은 **자물쇠** 아이콘으로 구분한다. 게임이 시작된 방도 목록에 남고 **"게임 중"**으로 표시한다. 방 카드에는 방 제목, 방장의 닉네임·캐릭터, 방장의 전적(판수 / 승 / 패 / 무)과 승률만 표시한다. 알 개수와 판 종류, 참여 인원은 표시하지 않는다.
  - 방 카드를 누르면 하이라이트 표시와 함께 **`입장` 버튼**이 나타나고, 누르면 입장한다. 방 카드를 **더블클릭**해도 입장한다. 같은 방을 다시 누르면 선택이 해제되고 다른 방을 누르면 선택이 바뀐다. 게임 중인 방에는 입장할 수 없다(관전 없음).
  - **방 생성**: [방 생성](#방-생성) 창을 연다.
  - **즉시 참가**: 대기 중인 공개 방 중 하나를 **무작위로** 골라 바로 입장한다. 입장 가능한 방이 없으면 방이 없다는 알림을 표시한다.
  - **코드 입력**: **플로팅 창**에서 비공개 방의 6자리 코드를 입력해 입장한다. 6칸 입력이며 붙여넣기를 지원하고 영문은 대문자로 바꿔 받는다. 비공개 방은 목록에 자물쇠로 표시되지만, 방장이 코드를 알려준 사람만 들어갈 수 있다.
- 방이 가득 찼거나 존재하지 않거나 코드가 틀리면 오류 안내를 표시한다.
- 환경설정·방 생성·코드 입력·캐릭터 변경은 모두 로비 위에 뜨는 **플로팅 창**으로 연다.

### 캐릭터 변경

- 프로필바의 프로필을 누르면 **플로팅 창**으로 열린다. 로비 화면을 덮지 않고 그 위에 떠 있다.
- 캐릭터는 **곰·고양이·여우·토끼·부엉이·개구리 6종**이다 (디자인 캔버스 기준). **모든 캐릭터를 처음부터 사용할 수 있다** (해금 없음).
- 고르는 **즉시 적용**되고 **계정에 저장**된다. 가입 시 기본 캐릭터는 무작위다.
- 캐릭터는 프로필바, 방 카드, 대기실, 게임 화면에 표시된다. 프로필·카드에는 2D 얼굴 그림을, 게임 장면의 판 양쪽에는 같은 동물의 3D 모델을 쓴다.

### 방 생성

- **대전 상대**: 사람(PvP) / AI 중 선택. AI를 고르면 [AI 대전](#ai-대전)으로 바로 시작한다 ([DEC-024](DECISIONS.md#결정-색인)).
- **방 제목**: 기본값 `{닉네임}의 방`, 수정 가능 (최대 20자)
- **알 개수**: 기본 5개, 5·7·9개 중 선택
- **판 선택**: 판 목록에서 선택 (미리보기 표시)
- **공개 여부**: 공개 / 비공개 중 선택
  - **공개**: 방 목록에 노출되며 **방 코드는 표시하지 않는다**. 방 목록에서 선택해 입장한다.
  - **비공개**: 방 목록에 자물쇠로 표시되고, **방 생성 창에서 방 코드가 6자리로 자동 생성**된다 (수정 불가, 혼동되는 문자 0/O, 1/I 제외). 방 생성 창에서 코드를 **복사**할 수 있다. 코드를 아는 사람만 입장할 수 있다.
- 사람(PvP) 방은 생성 후 대기실에서 상대 입장을 기다린다.

### 대기실

- 표시: 방 제목, 판 종류, 알 개수, 방장과 상대의 캐릭터 / 닉네임 / 전적. 상대가 없으면 "상대를 기다리는 중" 표시.
- 버튼: **시작**(방장만, 상대가 입장했을 때만 활성), **나가기**.
- **게임 시작 방식**: 방장이 시작 버튼을 누르면 게임이 시작된다 (자동 시작 안 함).
- **방장이 나가면** 방이 닫히고 상대는 안내 메시지와 함께 [로비](#로비)로 이동한다.
- **상대가 나가면** 방은 유지되고 다시 상대를 기다리는 상태로 돌아간다.
- 게임이 시작되면 방은 목록에 **"게임 중"**으로 남는다. 대기실로 돌아오면 다시 대기 중으로 표시한다.

방 참여(공개 방 목록·코드 입장)는 [로비](#로비)에서 제공한다.

### 환경설정

- 프로필바의 환경설정 버튼으로 여는 플로팅 창이다.
- **효과음 음량** (0~100). 설정은 **브라우저에 저장**하며 다른 기기로 이어지지 않는다.
- **비밀번호 변경**: 현재 비밀번호 + 새 비밀번호(+ 확인) 입력. 비밀번호는 `********`처럼 고정된 마스킹 문자열로만 표시하며 실제 글자 수를 노출하지 않는다.
- 닉네임은 로그인 식별자이므로 **변경할 수 없다**. 전적·승률도 수정할 수 없다.
- **규칙 다시 보기**: [공통 안내](#공통-안내)의 규칙 설명 카드를 다시 연다.
- 효과음 목록: 발사, 알 충돌, 알 떨어짐, 내 턴 시작, 시간 5초 남음, 방해요소 받음, 방해요소 발동, 승리 / 패배 / 무승부

### 게임 화면

- 레이아웃 (최소 해상도 1280×720): **화면 가운데에 알까기 판**, 판을 사이에 두고 **두 플레이어 캐릭터**가 있다.
  - **오른쪽 하단에 내 프로필**, **왼쪽 상단에 상대 프로필**을 표시한다. 프로필에는 캐릭터, 닉네임, 승률을 표시한다.
  - 프로필은 **배경 패널 없이(투명)** 표시해 뒤의 게임 장면이 보이게 하고, 글자 그림자로 가독성을 보조한다.
  - **현재 턴은 해당 플레이어의 프로필 하이라이트**로 표시하고, **남은 시간·라운드는 화면 위쪽 가운데**, **내 방해요소 영역은 내 프로필 위**, 남은 알 개수는 각 프로필 아래 점 표시, 기권 버튼은 왼쪽 하단에 둔다. 상대의 방해요소는 표시하지 않는다.
- 게임판:
  - 내 알과 상대 알을 색상과 무늬로 구분한다. 판·알·캐릭터는 **3D로 표현**한다. 렌더링 라이브러리는 [설계](DESIGN.md)에서 정한다.
  - **카메라**: 내 알이 있는 방향에서 판을 비스듬히 내려다보는 **고정 시점** (자유 회전 없음). 두 플레이어 모두 내 알이 아래쪽, 상대 알이 위쪽으로 보인다. 발사 중에도 카메라는 움직이지 않는다.
  - 조준·발사 조작은 [게임 규칙](#조준발사-조작)을 따른다.
  - 두 사용자에게 같은 발사 결과를 보여준다. 계산·전달·재생 방식은 [설계](DESIGN.md)에서 정한다.
  - 판 밖으로 나간 알은 **떨어지는 연출**(중력 애니메이션, 회전)을 시각 효과로만 보여주고, 게임 판정에는 "제거됨"만 반영한다.
- 게임 정보:
  - 현재 턴 표시와 **턴 남은 시간(30초)**
  - 현재 라운드 / 최종 라운드
  - **방해요소 영역**: 현재 보유한 방해요소 1개를 카드로 표시한다. 상대에게는 보이지 않는다. 피로도 게이지를 영역 위에 막대로 표시하고, 쿨타임 중인 카드는 회색과 남은 턴 수로 표시한다. 사용할 수 없는 때(쿨타임·게이지·진행 중 효과 제한 등)는 영역 전체를 흐리게 표시한다.
  - 남은 알 개수
  - 기권 버튼
- 방해요소를 받으면 화면 가운데에 카드 1장을 1.5초 동안 보여준 뒤 내 방해요소 영역으로 옮긴다 (나에게만 표시).
- 방해요소가 발동하면 화면 위쪽에 "○○님이 [방해요소]를 사용했어요"를 2초간 양쪽에 표시한다. 랜덤형은 에어컨 아이콘과 함께 표시한다.
- 게임 종료 시 결과(승 / 패 / 무)를 표시하고 **재도전하기 / 나가기** 버튼을 제공한다. 나가기는 [로비](#로비)로 이동한다.
  - **양쪽이 모두 재도전하기를 누르면(상호 동의)** 같은 방·같은 설정(판·알 개수)으로 다시 대전한다. 방 유지는 **방장 기준**이다. 방장이 나가면 방이 닫히고, 상대가 나가면 방장은 방에 남아 새 상대를 기다린다([대기실](#대기실) 규칙과 같음).
  - 한쪽이 누르면 상대 결과 화면에 "상대가 재도전을 원해요"를 표시한다. **15초** 안에 둘 다 누르지 않으면 두 사람 모두 같은 방의 대기실로 돌아간다.

### 화면 미정 사항

- [ ] 비공개 방을 방 목록에서 입장할 때 코드를 입력받는 방식, AI를 고른 방 생성 창에서 방 제목·공개 여부 입력의 표시 여부, 인증 요청 제한 안내 문구 (UI-002에서 시안 후 확정)
- [ ] 아트 세부(기반: `알까기 바 (2).html`), 카메라 각도 수치, 3D 캐릭터·효과음 에셋의 제작·조달 방법 (에셋 출처는 [설계](design/TECH_STACK.md)에서 정함)

### 수용 기준 작성 예시

- `ROOM-JOIN`: 대기 중인 공개 방을 선택하고 참여했을 때 대기실에 두 사용자가 표시되고, 방장에게 시작 버튼이 활성화된다.
- `HAZARD-GRANT`: 1·3·5·7·9라운드 시작 시 각 플레이어의 방해요소 1개가 새 방해요소로 교체되고 누적되지 않는다. 받은 방해요소는 본인 화면의 방해요소 영역에만 표시되고, 상대의 화면과 상대에게 전송되는 데이터에는 나타나지 않는다.
- `HAZARD-USE`: 사용 제한을 충족하는 방해요소를 사용하면 양쪽 화면에 발동 안내가 표시되고 효과가 적용된다. 내 턴·상대 턴과 알 이동 여부에 관계없이 사용할 수 있고, 쿨타임·게이지 등 제한을 충족하지 못한 요청은 거부된다.
- `TURN-TIMEOUT`: 30초 동안 발사하지 않으면 상대 턴으로 넘어간다. 같은 사용자의 연속 시간초과가 3회가 되면 기권패로 종료한다.
- `LEAVE-FORFEIT`: 게임 중 한쪽이 나가거나 연결이 끊기면 그 플레이어가 기권패로 기록되고 양쪽 전적이 갱신된다.

### 결정 순서 제안

1. 기술 스택과 아키텍처를 정한다. 상대 비공개 정보, 로컬 2인 모드 우선, 알 떠오름(높이 처리), 실시간 초 단위 방해요소 효과를 함께 고려한다.
2. 위 수용 기준 예시를 바탕으로 구현 작업을 TASKS에 등록한다.
3. 로컬 2인 모드로 수치 기본값을 넣고 플레이 테스트한다.
4. 디자인 캔버스를 현재 화면 요구사항(턴 하이라이트, 방해요소 영역, 프로필바 버튼, 방 생성 창의 AI/PvP 선택, 로비 새로고침)에 맞춰 갱신한다.

기존 기능을 삭제하거나 위 제안을 확정하려면 관련 작업과 [결정 기록](DECISIONS.md)에 근거를 남기고 해당 기준 문서를 갱신한다.
