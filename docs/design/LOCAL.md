# 로컬 구성·개발 모드 설계

## 상태

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 모노레포 패키지 경계와 `GameSession` 교체 구조 ([DEC-013](../DECISIONS.md#결정-색인)) |
| 현재 구현 | 없음 |
| 미정 | 인터페이스 세부 시그니처, 로컬 모드의 비공개 정보·방해요소 입력 방식 |

설치·실행 명령은 [README](../../README.md) 한 곳에서 관리한다. 이 문서는 프로세스·패키지 경계, 로컬/온라인 대체 구성, 개발용 설정 범위를 다룬다.

## 패키지 구성 (승인)

| 패키지 | 역할 | 의존 |
| --- | --- | --- |
| `shared` | 타입, Zod 스키마, 방해요소·판 데이터 | 없음 |
| `game-core` | 규칙·물리·상태 머신 (순수 TypeScript) | `shared` |
| `client` | Vite + React + R3F 화면, 로컬·원격 게임 세션 | `shared`, `game-core` |
| `server` | Express + Socket.IO, 인증·방·대전 진행, DB | `shared`, `game-core` |

`client`와 `server`는 서로 의존하지 않는다. 개발 실행은 Vite 개발 서버와 tsx로 띄운 서버를 함께 쓰고, 배포 시에는 서버가 빌드된 클라이언트를 정적 파일로 제공한다.

## 로컬·온라인 모드 경계 (승인)

로컬에서 먼저 게임을 완성하고 온라인으로 넘어가는 순서를 위해, **UI가 "게임을 진행하는 방법"을 인터페이스 뒤에 숨긴다.**

```
        ┌──── UI (3D 장면, 투명 프로필·상단 턴 정보, 방해요소 영역) ─┐
        │          GameSession 인터페이스에만 의존                    │
        └───────────────┬──────────────────────┬───────────────────┘
                        │                      │
              LocalGameSession          RemoteGameSession
              (M1: 브라우저 안에서       (M2: Socket.IO로
               game-core 직접 호출)       서버와 통신)
                        │                      │
                        └──── game-core ───────┘  ← 서버도 같은 코드를 호출
```

- **`GameSession` 인터페이스**: 명령(`useHazard`, `submitShot`, `forfeit`)을 보내고, 이벤트(`hazardGranted`, `turnChanged`, `simulationResult`, `gameOver`)를 구독한다. 이벤트 모양은 [API](API.md)와 **같은 타입**을 쓴다. M2에서는 `LocalGameSession`을 `RemoteGameSession`으로 바꾸는 것이 전환의 전부가 되도록 한다.
- **M1 로컬 모드**: 한 PC에서 두 플레이어가 번갈아 플레이한다 (개발용 `/local` 경로). 서버, DB, 로그인이 필요 없다.
- **로컬 모드의 비공개 정보 문제**: 한 화면을 같이 보면 상대가 받은 방해요소가 노출된다. 로컬 테스트에서는 (a) 턴이 넘어갈 때 "화면 가리기 / 교대" 화면을 두거나, (b) 개발용 토글로 상대 방해요소 표시를 켜고 끄는 방식을 쓴다 (아래 미정 항목).
- **게임 상태 머신**은 `game-core`에 둔다: 턴 → 시뮬레이션 → 판정 → (1·3·5·7·9라운드 시작 시 보유 1개 교체) → 종료. 턴 타이머(30초)는 `game-core`가 시계를 직접 읽지 않고 **외부에서 시간을 주입**받는다 (로컬은 브라우저 타이머, 서버는 서버 타이머).

## 개발 순서

한 PC에서 두 사용자가 번갈아 플레이하는 로컬 모드를 온라인보다 먼저 만든다([DEC-009](../DECISIONS.md#결정-색인)). 비공개 방해요소 검증 방식은 아래 미정 사항을 따른다.

## 미정 사항

- `GameSession` 명령·이벤트의 세부 시그니처 ([API](API.md)와 함께 확정)
- 한 PC에서 비공개 방해요소·시야 방해를 검증할 화면 교대·시점 토글 방식
- AI 대전은 브라우저에서 실행한다([DEC-021](../DECISIONS.md#결정-색인)). AI 입력의 경계는 LOCAL-001에서 정한다
- 로컬 2인 모드에서 양쪽 플레이어가 어느 턴·알 이동 중에도 방해요소를 쓰는 입력과 벽·끈끈이 위치 지정 방법 (마우스를 함께 쓰므로 개발용으로 무작위 위치를 쓰는 안 포함)
- 화면 배치는 [게임 화면](../PRD.md#게임-화면)과 UI-001 디자인 캔버스를 따른다
- 온라인 개발 시 로컬 DB(로컬 PostgreSQL / Neon 개발 브랜치) 선택
- 개발용 설정·환경변수 이름과 안전한 예제 관리: [운영 설계](OPERATIONS.md)

실제 설치 명령과 접속 주소는 구성 후 README에 추가하고 검증 결과는 worklog에 기록한다.
