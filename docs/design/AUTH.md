# 인증·권한·입력 검증 설계

## 상태

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 없음 |
| 현재 구현 | 없음 |
| 미정 | 아래 후보 전체. 합의·채택 전 구현 계약으로 사용하지 않는다. |

제품의 가입·로그인·중복 접속·정보 수정 동작은 [화면](../PRD.md#화면별-요구사항)과 [게임 규칙](../PRD.md#게임-규칙), 민감정보·권한의 제품 제약은 [PRD](../PRD.md)를 따른다. 이 문서는 인증 상태 전달·인가·검증 구현을 관리한다.

## 기존 후보 — 모두 미정

- 세션 인증과 저장소, HTTP와 실시간 연결의 인증 공유
- 비밀번호 해시로 argon2id와 관련 라이브러리 검토
- 세션 쿠키의 httpOnly·배포 시 secure·sameSite 설정
- Zod 등의 입력 스키마 검증, 요청 빈도 제한
- 접속 대체 이벤트와 기존 연결 종료 방식: [API](API.md)
- 프록시 신뢰 설정, CORS, 인증 실패·만료·로그아웃 처리

## 검증 경계 — 미정

[게임 규칙](../PRD.md#게임-규칙)과 [증강 규칙](../PRD.md#증강-규칙)의 유효성·권한을 어디에서 어떻게 강제할지 정해야 한다. 턴·알·증강 소유권, 사용 횟수·대상·위치·조건, 후보 선택의 적합성, 비공개 정보 노출을 포함한다. 규칙 값과 전체 동작은 제품 문서를 링크하고 검사 위치·오류 계약만 여기서 설계한다.

계정·건의의 조회·삭제 정책이 합의되면 필요한 인가 경계를 추가한다. 인증 만료 시간·로그인 시도 제한·비밀번호 최대 길이·해시 파라미터·요청 오류 형식은 미정이다.
