# 인증·권한·입력 검증 설계

## 상태

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 세션 쿠키 인증(express-session + connect-pg-simple), argon2id(@node-rs/argon2), Zod 입력 검증 ([DEC-013](../DECISIONS.md#결정-색인)) |
| 현재 구현 | 없음 |
| 미정 | 아래 세부 설정 |

제품의 가입·로그인·중복 접속·정보 수정 동작은 [화면](../PRD.md#화면별-요구사항)과 [게임 규칙](../PRD.md#게임-규칙), 민감정보·권한의 제품 제약은 [PRD](../PRD.md)를 따른다. 이 문서는 인증 상태 전달·인가·검증 구현을 관리한다.

## 인증 구성 (승인)

- 로그인 성공 시 서버 세션을 만들고 세션은 PostgreSQL에 저장한다(connect-pg-simple). Socket.IO 연결은 같은 세션 쿠키로 인증한다.
- 비밀번호는 argon2id(@node-rs/argon2)로 해시한다.
- 요청·이벤트 입력은 `shared`의 Zod 스키마로 검증한다.
- 세션 쿠키는 httpOnly, 배포 시 secure, sameSite=lax로 둔다. 클라이언트와 서버가 같은 출처라 CORS를 열지 않는다.

## 세부 미정

- 요청 빈도 제한의 단위·한도
- 접속 대체 이벤트와 기존 연결 종료 방식: [API](API.md)
- 프록시 신뢰 설정(Render 프록시), 인증 실패·만료·로그아웃 처리

## 검증 경계 — 미정

[게임 규칙](../PRD.md#게임-규칙)과 [방해요소 규칙](../PRD.md#방해요소-규칙)의 유효성·권한을 어디에서 어떻게 강제할지 정해야 한다. 턴·알·방해요소 소유권, 사용 횟수·대상·위치·조건, 무작위 지급의 공정성, 비공개 정보 노출을 포함한다. 규칙 값과 전체 동작은 제품 문서를 링크하고 검사 위치·오류 계약만 여기서 설계한다.

## 로그인 시도 제한

[로그인](../PRD.md#로그인)의 연속 5회 실패 제한은 제품 규칙이다. 닉네임이 방 목록·랭킹에 공개되는 로그인 식별자라서 필요한 보호 수단이다. 제품 규칙상 실패 횟수는 **닉네임 단위**로 세고, 제한은 5분이며 로그인 성공 시 초기화한다. 횟수와 제한 시각의 저장 위치는 미정이다.

계정 삭제와 건의 기능은 MVP에서 제공하지 않으므로 해당 인가 경계는 두지 않는다. 비밀번호 길이는 제품 규칙(8~64자)을 따른다. 닉네임 중복 검사는 NFC 정규화·영문 대소문자 무시 기준([회원등록](../PRD.md#회원등록))으로 한다. 인증 만료 시간·해시 파라미터·요청 오류 형식은 미정이다.
