# 배포·데이터 운영 설계

## 상태

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 없음 |
| 현재 구현 | 없음 |
| 미정 | 아래 후보 전체. 합의·채택 전 구현 계약으로 사용하지 않는다. |

비용·보관·삭제·장애 시 제품 약속은 [PRD](../PRD.md), 실행 절차는 [README](../../README.md), 성능·실패 실험 방법은 [ENGINEERING-VALIDATION](../ENGINEERING-VALIDATION.md)을 따른다.

## 기존 구성 후보 — 모두 미정

- 하나의 상시 서비스에서 정적 웹·HTTP·실시간 연결을 제공
- 방·진행 중 게임은 메모리, 회원·전적·세션은 DB에 보관
- 사용 중이지 않은 무료 인스턴스의 첫 요청 지연에 대기 안내 제공
- 시뮬레이션 기록의 30fps 샘플링과 좌표 소수점 축소
- 환경 설정 후보 이름: `DATABASE_URL`, `SESSION_SECRET`, `PORT`, `NODE_ENV`
- 로컬 `.env`와 값이 없는 `.env.example`, 배포 환경의 비밀 설정 주입
- 브라우저 입력 후 오디오 활성화, 품질 설정으로 렌더링 부담 조절

실제 서비스·무료 한도·배포 정책·환경변수는 선정하지 않았다. 무료 한도와 이용 조건은 채택 전에 최신 근거를 확인한다. 값과 비밀정보는 문서에 기록하지 않는다.

## 미정 사항

- 배포 단위·인스턴스 수·SPA fallback·헬스체크·자동 배포·롤백
- 인스턴스 대기·절전·콜드 스타트 대응 (첫 접속 허용 대기 5초, 목표 동시 접속 10명: [PRD](../PRD.md#4-비기능-요구사항과-제약))
- 동시 이탈 판정과 시작 직전 이탈 판정에 쓸 서버 로그의 기록 항목, 중복 결과 기록 방지. 서버 장애 시 처리는 MVP에서 고려하지 않는다.
- 백업·복구 검증 (보관 기간 무제한, 삭제 기능 없음)
- 로그·관측·민감정보 제거·비용과 사용량 확인 방법
- 클라이언트 음량 설정의 브라우저 저장 방식 (저장 범위는 [환경설정](../PRD.md#환경설정)에서 브라우저로 정함)

제품 정책이 미정인 항목은 구현 편의로 결정하지 않는다. 실제 장애 사례는 [TROUBLESHOOTING](../TROUBLESHOOTING.md), 날짜별 실행·결과는 worklog에서 관리한다.
