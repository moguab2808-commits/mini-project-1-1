## 배포 구성 (승인)

- **Render 무료 웹 서비스 1개**가 빌드된 정적 클라이언트, REST API, Socket.IO를 함께 제공한다. 같은 워크스페이스에 다른 무료 서비스를 두지 않는다(월 750 무료 시간 안에서 상시 실행).
- **절전 방지**: Render 무료 서비스는 15분 동안 요청이 없으면 절전하고 깨어나는 데 약 1분이 걸린다. 첫 접속 5초 요구를 지키기 위해 외부 모니터링 서비스가 `/health`를 요청하는 방식을 검토한다. `/health`는 DB를 조회하지 않는다. 서비스와 간격, 지속 요청의 실제 사용 여부는 아래 [헬스체크](#헬스체크)를 따른다.
- **DB**: Neon 무료 플랜 PostgreSQL. 5분 동안 활동이 없으면 컴퓨트가 중지되도록 서버의 연결 풀은 유휴 연결을 짧게 닫는다(월 100 CU-hour 한도 보호).
- **리전**: Render와 Neon 모두 싱가포르.
- 진행 중 경기 상태는 서버 메모리, 방 정보(`rooms`)·회원·전적·세션은 DB에 보관한다([DEC-023](../DECISIONS.md#결정-색인)).
- 환경 설정 이름: `DATABASE_URL`, `SESSION_SECRET`, `PORT`, `NODE_ENV`. 로컬은 `.env`와 값이 없는 `.env.example`을 쓰고, 배포 환경은 Render의 환경 변수로 주입한다. 값과 비밀정보는 문서에 기록하지 않는다.
- 기존 시뮬레이션 기록 30fps 샘플링은 기록 후 재생 기준이었다. 이동 중 방해요소 입력을 위한 실시간 방식은 [ADR-0004](../adr/0004-realtime-hazards.md)로 승인됐다. 전송 주기는 물리와 분리하며 부하 측정으로 정한다(아래 사용량·부하).
- 오디오는 브라우저 입력 후 활성화한다.

무료 조건은 2026-10-29에 확인했다([ADR-0003](../adr/0003-tech-stack-and-architecture.md#관련-기준과-근거)). 조건이 바뀌면 ADR의 재검토 조건을 따른다.

## 세부 절차 (확정안)

### 헬스체크

- 외부 헬스체크 서비스는 **UptimeRobot**을 쓴다. 무료 플랜의 최소 간격이 5분이라 사용한다면 **5분 간격**으로 `/health`를 요청하도록 설정한다([DEC-029](../DECISIONS.md#결정-색인)). cron-job.org(무료, 최소 1분)가 대안이다.
- 확인할 것: UptimeRobot 무료 플랜의 비상업적 용도 제한이 공식 이용약관에 있는지(현재는 제3자 자료에서만 확인), 확인일을 여기에 기록한다.
- 서버 절전 방지를 위해 계속 요청을 보내는 방식을 실제로 쓸지는 구현 단계에서 다시 정한다. 쓰지 않으면 절전 후 첫 접속에 약 1분이 걸려 [첫 접속 대기 5초](../PRD.md#4-비기능-요구사항과-제약) 요구를 만족하지 못한다. 이 경우 PRD의 요구를 조정할지 정해야 한다.

### SPA fallback

`/api`·`/socket.io`·`/health`를 제외한 GET 요청은 `index.html`을 반환한다. `[제안]`

### 배포·롤백

- **자동 배포를 끄고 Render 대시보드에서 수동으로 배포한다**([DEC-029](../DECISIONS.md#결정-색인)). 코드·문서 작업이 끝나도 커밋·푸시·배포를 단계별로 확인한 뒤 진행한다. 자동 배포를 켜 두면 `main`에 푸시하는 순간 배포되어 이 결정과 맞지 않는다. 배포는 서버를 재시작해 진행 중인 경기와 연결이 끊기므로 사용자가 없을 때 한다.
- 확인할 것: Render 무료 서비스에서 자동 배포를 끄고 수동 배포(Manual Deploy)하는 방법과 롤백 방법을 공식 문서로 확인해 기록한다.
- 롤백은 Render 대시보드에서 이전 배포를 다시 배포한다. 마이그레이션은 되돌림 스크립트 대신 "앞으로 호환되는 변경만" 원칙을 쓴다([DATABASE](DATABASE.md#마이그레이션)). `[제안]`

### 서버 로그

[GAME의 명령 경합과 시간](GAME.md#명령-경합과-시간)이 정한 필드를 기본으로 하고 운영에 필요한 항목을 더한다. 구조화 JSON 한 줄 로그를 stdout으로 내보내 Render 로그에서 본다. `[제안]`

| 항목 | 내용 |
| --- | --- |
| 시각 | UTC 시각, 단조 시각 |
| 식별 | `roomId`, `gameId`, `turnId`, `userId` |
| 순서 | `ingressSeq`, `serverTick` |
| 이벤트 | 턴 시작, 발사, 방해요소 사용·발동, 기권·이탈·접속 끊김, 중복 접속 대체, 경기 종료 |
| 결과 | 명령 판정 결과, 종료 사유(`finishOnce`) |

- 이 로그가 동시 이탈과 시작 직전 이탈의 판정 근거다([게임 규칙](../PRD.md#게임-규칙)). 경기 종료 사유는 DB에 저장하지 않고 여기에만 남는다([DATABASE](DATABASE.md#경기-종료-저장)).
- 틱마다 로그를 남기지 않는다. 비밀번호·세션·쿠키·상대의 비공개 보유 상태는 기록하지 않는다. 재접속 복구가 없어 재접속 이벤트는 두지 않는다.

### 사용량·부하 확인

- Render 대시보드의 월 사용 시간과 Neon 콘솔의 CU-hour를 월 1회 확인해 worklog에 기록한다. `[제안]`
- 방 상태를 DB에서 관리해 Neon 접속이 늘 수 있다. 방 목록은 새로고침으로만 조회하고 연결 풀 유휴 시간을 짧게 유지한다. 사용량으로 확인한다.
- 실시간 상태 전송의 서버 부하는 "동시 방 수 × 상태 전송 주기"별 CPU·지연·대역폭을 측정해 정한다([GAME](GAME.md#전송과-표시-초안), [ENGINEERING-VALIDATION](../ENGINEERING-VALIDATION.md)). 측정 항목 추가는 ENGINEERING-VALIDATION에서 한다.

### 백업·복구

Neon 기본 복구(시점 복구)만 쓰며 별도 백업을 만들지 않는다([DEC-029](../DECISIONS.md#결정-색인)). 무료 플랜의 복구 가능 기간과 한도를 공식 문서로 확인해 확인일과 함께 기록한다. 보관 기간 무제한 정책과 복구 기간의 차이(복구 기간 밖 데이터는 복구할 수 없음)를 위험으로 적는다.

## 미정 사항

- Render·Neon 무료 조건 재확인 날짜 기록, UptimeRobot 이용 조건 확인
- 수동 배포·롤백의 구체적 절차(공식 문서 확인 후)
- Neon 기본 복구의 가능 기간과 한계
- 서버 시작 시 `rooms` 정리 절차: 전부 삭제안을 제안했다([DATABASE](DATABASE.md#방-생명주기)). 서버 장애 시 처리는 MVP에서 고려하지 않는다.
- 서버 로그 항목 최종 확정(위 표는 제안)
- 상태 전송 부하 측정의 구체적 항목
- 로그·관측·민감정보 제거 방식
- 클라이언트 음량 설정의 브라우저 저장 방식 (저장 범위는 [환경설정](../PRD.md#환경설정)에서 브라우저로 정함)

제품 정책이 미정인 항목은 구현 편의로 결정하지 않는다. 실제 장애 사례는 [TROUBLESHOOTING](../TROUBLESHOOTING.md), 날짜별 실행·결과는 worklog에서 관리한다.
