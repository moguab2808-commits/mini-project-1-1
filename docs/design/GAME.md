# 게임 처리·동기화 설계

## 상태

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 없음 |
| 현재 구현 | 없음 |
| 미정 | 아래 후보 전체. 합의·채택 전 구현 계약으로 사용하지 않는다. |

제품 규칙은 [게임](../PRD.md#게임-규칙)·[증강](../PRD.md#증강-규칙), 화면 동작은 [UI](../PRD.md#화면별-요구사항)를 따른다. 아래는 기존 구현 후보이며 선택 이유·절충은 채택 시 [결정 기록](../DECISIONS.md)에 남긴다.

### 후보: 핵심 설계 원칙

1. **서버 권한 (Server Authoritative)**: 물리 계산, 승패 판정, 턴 타이머, 레이팅 갱신은 서버에서만 한다. 클라이언트가 보낸 결과는 신뢰하지 않는다.
2. **기록 후 재생 (Record & Replay)**: 클라이언트는 `{알 id, 각도, 세기}`만 전송한다. 서버가 시뮬레이션을 끝까지 실행하며 프레임별 알 위치를 기록해 한 번에 전송하고, 클라이언트는 이를 재생만 한다.
   - **물리는 2D(평면 좌표)로 계산하고 렌더링만 3D**로 한다. 3D는 클라이언트의 렌더링 계층에 한정되어 서버, 소켓 이벤트, DB에 영향을 주지 않는다.
   - 알이 판 밖으로 떨어지는 연출 같은 시각 효과는 클라이언트에서만 처리한다.
3. **게임 로직 분리**: 게임 규칙, 물리, 턴 진행, 증강 적용은 `game-core/` 패키지에 **순수 TypeScript**로 작성한다. Express, Socket.IO, DB, DOM, Three.js를 참조하지 않고 시간과 난수도 외부에서 주입받아(시드 기반 난수) 같은 입력이면 같은 결과가 나오게 하며, 단독 테스트가 가능해야 한다. 로컬(M1)과 서버(M2)가 이 패키지를 그대로 공유한다. 경계는 ESLint `no-restricted-imports`로 강제한다 (`game-core`에서 `express`, `socket.io`, DB 패키지, `three`, DOM 접근 금지).
4. **데이터 기반 증강과 판**: 증강 메타데이터(id, 이름, 분류, 입력 방식, 설명, 수치)와 판은 `shared/`에 데이터로 정의한다. 스탯 변화형 증강은 순수 데이터로 정의하고, 충돌 / 판 이탈 / 이동 중에 개입하는 **훅형 증강과 특수형 증강의 동작은 `game-core`의 시뮬레이션 훅(함수)과 상태 머신으로 구현**한다 (구조는 아래 미정 항목).
5. **플레이어별 뷰 (비공개 정보)**: 분신과 안개는 상대에게 숨겨야 하므로 `game-core`는 상태를 그대로 내보내지 않고 `getViewFor(playerId)`로 **플레이어별 뷰**를 만든다. 상대에게 보내는 뷰와 시뮬레이션 기록에는 분신 여부를 알 수 있는 정보(분신 플래그, 알 id 규칙 등)를 넣지 않고, 안개 안에 있는 알은 프레임별로 위치를 제외한다. 이를 위해 시뮬레이션 기록은 **플레이어마다 따로 만들어 전송**한다.
6. **휘발성과 영구 데이터 분리**: 방과 진행 중인 게임은 서버 메모리, 회원 / 전적 / 세션 / 건의는 DB.

## 기술 초기값 후보

아래는 과거 튜닝 제안이며 모두 미정이다. 제품의 라운드·시간 제한은 [게임 규칙](../PRD.md#게임-규칙), 판 크기와 배치의 미정 사항도 해당 문서를 따른다. 상수 저장 위치와 길이 단위도 미정이다.

| 항목 | 초기값 | 비고 |
|---|---|---|
| 반발계수 | 0.9 | 증강 `bouncy`가 보정 |
| 시뮬레이션 간격 | 고정 1/120초 | 기록 샘플링은 30fps ([운영 후보](OPERATIONS.md)) |
| 시뮬레이션 종료 | 모든 알의 속도가 0.1r/초 미만인 상태가 0.3초 지속 | |
| 시뮬레이션 최대 시간 | 10초 | 초과 시 모든 알 강제 정지 |
| 최대 발사 세기 | 알이 판 가로 길이를 한 번 이상 이동하는 정도 | 구현 후 조정, `power-shot`이 보정 |

## 미정 사항

- 물리 차원·엔진·수치 안정성, 고정 시간 간격·시드 난수의 필요성과 적용 방법
- 게임 단계·턴 내 발사 단계·종료·이탈의 상태 전이와 경합 처리
- 스탯 보정 순서 후보: `기본값 → 가산 보정 → 곱연산 보정`
- 충돌·판 이탈·시뮬레이션 종료 훅과 데이터/동작의 분리
- 기록 재생 또는 다른 동기화 방식, 충돌·제거 이벤트와 보간
- 플레이어별 뷰에서 분신 식별자·안개 속 위치가 노출되지 않게 하는 방법
- 공통 좌표계, 대칭 초기 배치, 마우스 좌표 변환, 카메라와 낙하 표현
- 로컬·온라인의 로직 공유 여부: [로컬 설계](LOCAL.md)

위 후보 안의 “한다”는 채택된 구현 지시가 아니다. 제품 규칙의 시간·승패·공개 범위는 연결 문서를 따르며 이 문서에서 재정의하지 않는다.
