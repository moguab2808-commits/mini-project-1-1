## 핵심 설계 원칙 (승인)

1. **서버 권한 (Server Authoritative)**: 물리 계산, 승패 판정, 턴 타이머, 방해요소 지급·발동, 종료 시 전적 갱신은 서버에서만 한다. 클라이언트가 보낸 결과는 신뢰하지 않는다.
2. **실시간 진행 (승인)**: [DEC-015](../DECISIONS.md#결정-색인)의 이동 중 방해요소 사용을 지원하기 위해 서버가 고정 스텝으로 물리를 진행하고 현재 상태를 계속 전송한다. 클라이언트는 받은 상태를 보간해 표시한다. 기존 기록 후 재생 선택은 [ADR-0004](../adr/0004-realtime-hazards.md)로 대체됐다. 상세 이벤트 계약은 API-001에서 정한다.
3. **물리**: 판 평면의 2D 원 충돌을 직접 구현하고, [알 떠오름](../PRD.md#알-떠오름)은 알마다 높이 값을 따로 계산한다. 높이가 0보다 큰 알은 충돌 판정에서 빠지고, 착지할 때 판 안·밖을 판정한다. 렌더링은 클라이언트의 3D 계층에 한정한다.
4. **게임 로직 분리**: 게임 규칙, 물리, 턴 진행, 방해요소 적용은 `game-core` 패키지에 **순수 TypeScript**로 작성한다. Express, Socket.IO, DB, DOM, Three.js를 참조하지 않는다. 시간과 난수도 외부에서 주입받아(시드 기반 난수) 같은 입력이면 같은 결과가 나오게 하고, 단독으로 테스트할 수 있어야 한다. 로컬 모드와 서버가 이 패키지를 그대로 공유한다. 경계는 ESLint `no-restricted-imports`로 강제한다.
5. **데이터 기반 방해요소와 판**: 방해요소 메타데이터(id, 이름, 분류, 효과, 지속, 수치)와 판 정의는 `shared`에 데이터로 둔다. 판·알·입력에 개입하는 동작은 `game-core`의 시뮬레이션 훅과 상태 머신으로 구현한다.
6. **플레이어별 뷰 (비공개 정보)**: `game-core`는 상태를 그대로 내보내지 않고 `getViewFor(playerId)`로 플레이어별 뷰를 만든다. 상대에게 보내는 뷰에는 내 보유 방해요소의 종류·개수를 넣지 않는다. 시야 방해(후레쉬·물총)는 대상 플레이어 뷰에만 "가림 효과" 상태로 넣는다.
7. **휘발성과 영구 데이터 분리**: 경기 진행 상태(알 위치·턴·방해요소)는 서버 메모리, 방 정보(`rooms`)·회원·전적·세션은 DB ([DEC-023](../DECISIONS.md#결정-색인)).

## 기술 초기값 (조정 대상)

아래는 GAME-002가 제안한 **구현 시작용 기본값**이다. 승인된 확정값이 아니며 플레이 테스트로 조정한다(아래 [수치 변경 절차](#수치-변경-절차)). 길이 단위는 [판](../PRD.md#판-board)의 1단위 = 1cm, 시간은 실제 초다. 제품 수치(라운드·턴 시간·판·알 크기·효과 지속 시간)는 PRD를 따르고 여기서 바꾸지 않는다. 값은 구현 시 `shared`의 데이터 한 곳에 두고 `game-core`가 읽는다.

## 상세 계약 초안 (GAME-001)

아래는 개발자 A의 검토안이다. [DEC-014·015](../DECISIONS.md#결정-색인)의 제품 규칙은 승인됐으며, 실시간 계산 방식은 DEC-016, 개발자 B 검토에 따른 명령·종료·전송 경계는 DEC-026으로 승인됐다. 이벤트 이름·필드는 API-001에서 확정한다. 선계산과 재생을 분리한 이전 초안은 이동 중 새 입력을 처리할 수 없어 이 초안으로 교체했다.

### 상태 전이와 순서

게임의 주 상태와 방해요소 효과는 별도로 관리한다. 방해요소 사용은 전용 게임 상태가 아니라 현재 상태에 효과를 추가하는 입력이다.

```mermaid
stateDiagram-v2
    waiting --> aiming: 경기 시작
    aiming --> moving: 발사 / 알을 움직이는 효과
    aiming --> resolving: 턴 시간초과
    moving --> resolving: 발사 후 모든 알 정지
    moving --> aiming: 발사 전 효과로 움직인 알 정지
    resolving --> aiming: 다음 턴
    resolving --> finished: 승패 확정
    aiming --> finished: 기권 / 이탈
    moving --> finished: 기권 / 이탈
    finished --> waiting: 15초 안에 양쪽 재도전 (새 gameId)
    finished --> [*]: 재도전 만료 / 한쪽 나가기 → 대기실
```

| 경기 상태 | 방 상태(`rooms.status`) | 비고 |
| --- | --- | --- |
| 시작 커밋 전 | waiting | 대기실. 이탈은 대기실 처리, 전적 미반영 |
| waiting(경기 생성)·aiming·moving·resolving | playing | 시작 커밋 이후. 이탈은 기권패 |
| finished, 재도전 대기 15초 | playing | 결과 화면. 이 구간의 나가기는 기권이 아니며 결과도 바꾸지 않음 |
| 재도전 성립 | playing 유지 | 같은 방·같은 설정으로 새 경기 생성 |
| 재도전 만료·한쪽 나가기 | waiting | 두 사람(또는 남은 방장)이 대기실로 이동. 방장 이탈 시 방 닫힘 |

- **시작 커밋**: 방 큐에서 시작 명령을 처리하며 `rooms.status`를 waiting → playing으로 바꾼 직후, `game:start` 전송 직전이다. 이 명령보다 ingressSeq가 앞선 이탈은 대기실 처리, 뒤의 이탈은 기권패와 전적 반영 대상이다. 첫 틱은 기준으로 쓰지 않는다 ([DEC-026](../DECISIONS.md#결정-색인)).

| 상태 | 의미 | 방해요소 입력 |
| --- | --- | --- |
| waiting | 경기 시작 전 | 거부 |
| aiming | 현재 플레이어 조준, 알은 정지 | 양쪽 모두 허용. 제한·배치 검증 후 적용 |
| moving | 알이 움직이며 계산·화면 표시가 동시에 진행 | 양쪽 모두 허용. 다음 권한 틱에 효과 반영 |
| resolving | 같은 틱 안에서 종료·라운드·교체·다음 턴을 정리 | 외부 대기 단계가 아님. 큐 입력은 전이 후 상태에서 재검증 |
| finished | 확정 결과 표시 | 거부, 결과 불변 |

- `moving`은 계산 결과 재생 단계가 아니다. 발사 도중 벽 사용 → 다음 서버 틱에서 벽 생성 → 이후 알이 벽에 부딪힘 → 그 상태를 양쪽 화면에 전송한다. 이미 지나간 충돌 결과를 소급 변경하지 않는다.
- `turnContext`는 activePlayerId, turnId, round, deadlineMs, shotCommitted를 가진다. 주 상태와 별도로 effects에 후레쉬·벽 등 활성 효과를 둔다. 기절·시야 가림만으로 주 상태를 바꾸지 않는다.
- 조준 중 책상 흔들기로 알이 움직여도 자기 알 선택·조준·발사는 계속 허용한다. 알의 현재 위치를 기준으로 입력을 검증하고 발사하며, 턴 타이머는 계속 간다. 같은 틱의 흔들기와 발사는 ingressSeq 순서로 처리한다.
- 발사 결과 승패는 모든 알이 멈춘 뒤 전체 결과로 판정한다. 양쪽 0개면 무승부다. 판 돌리기·책상 흔들기 자체는 알을 판에서 제거하지 않는다. 이 효과 뒤에 계속된 물리 움직임의 제거는 발사 전체 결과로 판정한다.
- 턴 종료가 확정되면 completedTurns를 한 번 증가시킨다. 2턴마다 라운드가 끝난다. 종료 판정 → 필요한 방해요소 교체 → 다음 턴 주인 변경 → 회복·쿨타임·자동 발동 처리 → 플레이어별 뷰·turn:change 순이다. 교체는 1·3·5·7·9라운드 시작에 보유 1개와 그 게이지·쿨타임·지속 효과를 지우고 새 방해요소로 교체한다. 판·알에 이미 반영된 즉시 효과의 상태는 되돌리지 않는다.

### 명령 경합과 시간

- 경기별 단일 큐에 서버 관찰 순번 ingressSeq와 단조 시각 observedAtMs를 붙인다. 같은 틱 입력은 순번대로 처리한다. 클라이언트 시각으로 과거 틱을 변경하지 않는다.
- 고정 틱마다 마감·효과 만료 정산 → 대기 명령 검증·적용 → 물리 적분·충돌·착지·제거 → 정지·종료 판정 → 플레이어별 상태 전송 순이다. 실제 시간과 물리 진행을 같은 권한 시간축에 맞추며 CPU 계산 완료 시간을 게임 경과로 삼지 않는다.
- 발사는 관찰 시각이 deadlineMs보다 작아야 한다. 정확히 마감이면 시간초과가 우선이다. 발사 시 해당 플레이어의 연속 시간초과를 0으로 만들고 턴 타이머는 끝낸다. 시간초과는 플레이어별 누적·강제 기권 조건을 PRD대로 적용한다.
- 방해요소는 발사 전후 모두 허용하므로 같은 틱에 발사가 먼저 처리돼도 방해요소를 단순히 moving이라는 이유로 거부하지 않는다. 종료·교체·제한 상태는 순서대로 재검증한다.
- commandId와 그 저장소는 두지 않는다 ([DEC-026](../DECISIONS.md#결정-색인)). 끊기면 기권패이고 재접속 복구가 없어 ack 유실 후 재전송이 생기지 않으며, Socket.IO는 한 연결 안에서 순서·중복이 없다. 응답은 ack 콜백으로 짝짓는다.
- 발사는 gameId·turnId로 검사하고 `shotCommitted`로 같은 턴의 두 번째 발사를 거부한다. 방해요소는 gameId·hazardInstanceId로만 검사해 교체 전 카드 명령을 거부한다. 방해요소는 상대 턴에도 쓸 수 있으므로 turnId로 거르지 않는다. 재도전 시 turnId가 다시 시작하므로 gameId로 이전 경기 명령을 구분한다. 오류 형식은 API-001에서 정한다.
- 이탈·기권·접속 대체(`session:replaced`, 비밀번호 변경으로 끊긴 연결 포함)도 같은 큐의 기권 명령으로 처리한다. 먼저 관찰된 이탈자를 기권패 처리하며 동시 시각은 ingressSeq로 구분한다. 시작 커밋 전 이탈은 대기실 처리다.
- `game-core`는 종료를 finished 결과로 돌려줄 뿐 저장하지 않는다. 서버가 finished 결과를 받아 `finishOnce`로 전적 갱신을 1회만 실행하고, 이후 결과를 바꾸지 않는다. 이름은 `finishOnce`로 통일한다(`settled`는 알 정지 훅 `onSettled`와 겹쳐 쓰지 않는다). 종료 사유는 DB에 저장하지 않고 서버 로그에만 남긴다.
- 로그는 턴 시작·발사·방해요소 사용/발동·이탈·종료 때만 남기고 틱마다 남기지 않는다. 필드는 경기·턴 ID, UTC·단조 시각, ingressSeq, serverTick, 명령 종류·판정 결과에 userId·roomId·종료 사유를 더한다. 비공개 보유 상태·세션·쿠키는 기록하지 않는다. 이벤트 이름과 판정 방법은 [OPERATIONS 서버 로그](OPERATIONS.md#서버-로그)에서 정했다.
- 초 단위 효과는 expiresAtMs까지 유지한다. 조준과 이동 사이에서 타이머를 새로 시작하거나 중복 차감하지 않는다. 서버 지연 시 따라잡기 틱 수·전송 주기·클라이언트 보간 지연은 측정 후 기술값으로 정한다.

### 상태 위치와 플레이어별 뷰

| 위치 | 필드 |

| 본인 비공개 | heldHazard(instanceId·kind·교체 라운드), 현재 방해요소의 fatigue·cooldown 상태, timeoutStreak |
| 공개 GameView | gameId, serverTick, serverNowMs, revision, phase, turnId, round, activePlayerId, deadlineMs, 판 변환, 알(id·ownerId·x·y·h), 공개 활성 효과·발동 안내, 확정 결과 |

`getViewFor(playerId)`는 허용 목록으로 새 객체를 만든다. 상대 보유 종류·교체 추첨 결과·게이지·쿨타임·난수 시드는 보내지 않는다. 보유 개수도 별도 전송하지 않는다. 사용된 효과의 이름과 효과는 양쪽 공개하고 화면 가림 표현은 대상 뷰에만 담는다.

`playerId`·`ownerId`·`activePlayerId`는 경기 안의 좌석 값 0·1이며 뷰에 `users.id`를 넣지 않는다. 서버만 좌석과 `users.id`를 매핑해 전적을 저장한다([DEC-030](../DECISIONS.md#결정-색인)).

### 방해요소별 처리

직접 사용형은 aiming과 moving 양쪽에서 처리한다. 방해요소 효과는 턴 마감·턴 변경과 독립이다. 30초 마감은 효과와 관계없이 그대로 처리하고, 효과는 마감·턴 변경 뒤에도 자기 지속 시간만큼 유지된다. 효과·보유가 초기화되는 시점은 라운드 교체(1·3·5·7·9라운드 시작)뿐이다([DEC-031](../DECISIONS.md#결정-색인)). 예를 들어 바람이 발동한 채 마감되면 턴은 넘어가고 바람은 남은 시간 동안 다음 조준에 계속 적용된다. 슬롯은 1개이며 비용·쿨타임 검증에 실패한 입력은 상태와 난수를 바꾸지 않는다. 효과별 대상과 제한의 미정 항목은 아래를 따른다.

| 종류 | 적용 훅·상태 |
| --- | --- |
| 판 돌리기 | 기본 판 돌리기의 상대 턴 제한과 독립적으로 보유 중 언제든 사용. 판·알 좌표 회전 후 알을 판 안에 유지. 알의 속도 벡터·벽·끈끈이의 위치와 방향도 같은 각도로 회전. 카메라는 고정 |
| 후레쉬 | 대상 뷰에 만료 시각을 가진 화면 가림 추가, 물리에는 영향 없음 |
| 물총 | 대상 뷰에 별도 가림 추가, 물리에는 영향 없음 |
| 책상 흔들기 | 시드 난수로 현재 알 위치 이동. 결과 좌표는 판 안으로 보정하고 이 효과 자체로 제거하지 않음. 흔들리는 중에도 조준·발사 허용 |
| 벽 | 판 좌표계의 격자 후보 중심과 방향으로 배치. 판 밖·알·기존 벽·끈끈이와 겹치면 거부. 이후 틱 충돌에 반영. 떠 있는 알과의 접촉 규칙은 물리 설계에 따름 |
| 끈끈이 | 원 영역 추가, 지면 알의 적분 전 감속 적용 |
| 기절 | 사용자의 턴과 관계없이 상대의 조준·발사 입력 차단·만료 시각 관리. 이미 움직이는 알을 멈추거나 발사를 취소하지 않음 |
| 세기 막대 속도 조절 | 보유 중 턴과 관계없이 상대에게 15초 구간마다 1회 자동 발동. 서버는 발동 시작·만료 시각과 배율만 알리고, 클라이언트가 약 1초 동안 막대 조작에 배율을 적용. 조준하지 않으면 조작 변화 없음 |
| 바람 | 보유 중 턴과 관계없이 상대에게 15초 구간마다 1회 자동 발동. 서버는 발동 시작·만료 시각과 방향을 알리고, 클라이언트가 약 1초 동안 상대의 조준 방향에 자동 편향을 더함. 상대가 조작하지 않아도 방향이 움직임. 알의 속도·좌표에는 영향 없음 |

조준 방향·세기 막대 값은 서버 권한 상태가 아니다 ([DEC-026](../DECISIONS.md#결정-색인)). `aim:update` 같은 조준 전송 이벤트는 두지 않는다. 클라이언트가 바람·세기 막대 효과를 반영한 최종 각도·세기를 `shot:submit`으로 보내고, 서버는 값 범위·알 소유·기절·마감·turnId를 검증한다. 조작된 클라이언트가 바람 편향을 무시해도 서버는 알 수 없다. 랭킹·레이팅이 없는 MVP에서는 이 위험을 감수한다. 상대 조준선을 실시간으로 보여주는 요구가 생기면 다시 검토한다.

### 물리와 입력 경계

- 판 중심 원점, 선공 기준 오른쪽 x·상대 방향 y·높이 h. 후공 화면은 180도 돌리며 판 평면 ray 교차점을 역변환해 기준 좌표 명령을 보낸다.
- 효과 만료·명령 적용 후 가속/감속 → 이동 → 벽·원 충돌 → 겹침 보정 → 착지·판 이탈 → 정지 판정 순으로 고정한다. 알 ID 순으로 접촉을 안정적으로 처리하며 swept 충돌로 터널링을 다룬다.
- 세기 p를 수평 속도 v(p), 높이 H(p)로 변환한다. 떠오름은 h(t)=vz·t−g·t²/2, vz=sqrt(2gH). PRD의 문턱·높이 한도를 따르며 떠 있는 알은 알 충돌에서 제외하고 착지 시 판 이탈을 검사한다.
- 판 이탈은 `game-core`의 직접 구현한 물리 계산에서 판 모양별 경계를 판정한다. 지면 알의 중심이 판 영역 밖으로 넘어가면 제거하고, 떠 있는 알은 착지 때 같은 기준으로 검사한다. 정사각형·원형판의 영역 함수와 벽·알 충돌은 같은 좌표계를 쓴다. 경계값의 허용 오차는 [기술 초기값](#물리)을 따른다.
- 벽 배치 미리보기는 판 좌표계 격자에 맞춰 후보를 스냅하고 실제 배치 검증과 같은 기하 조건을 사용한다. 판 밖·알·기존 벽·끈끈이와 겹치지 않는 후보만 초록색, 나머지는 빨간색으로 표시한다. 서버가 확정 시 현재 상태로 다시 검증하므로 이동 중 알이 후보에 들어오면 거부될 수 있다. 격자 간격·벽 두께·방향은 [기술 초기값](#방해요소-수치)을 따른다.
- BoardDefinition은 영역 판정·초기 배치·표시 메타데이터를 분리한다. 제거 알은 재충돌하지 않는다. 물리 훅은 beforeIntegrate, onContact, onLanding, onExit, afterStep, onSettled다. shared에는 직렬화 가능한 데이터만 둔다.
- `game-core`는 외부에서 tick 시간·명령·난수를 주입받는다. 네트워크·DB·DOM을 참조하지 않는다. AI도 자기 뷰만 보고 같은 명령 검증을 거친다. 온라인 대전은 서버, 로컬 2인은 브라우저의 로컬 권한 측이 진행한다. AI 대전은 브라우저에서 실행한다([DEC-021](../DECISIONS.md#결정-색인), [LOCAL](LOCAL.md#ai-대전)).

### 구현 경계 (A·B)

| 담당 | 범위 |
| --- | --- |
| 개발자 A | `game-core`·`shared`: 규칙, 틱 진행(step), `getViewFor`, 방해요소 훅, 시드 PRNG, 명령·이벤트 타입 이름. 로컬 2인 SharedWorker·AI Web Worker에 `game-runtime`을 워커 시계·MessagePort로 연결 |
| 개발자 B | `game-runtime`: 방별 단일 큐(ingressSeq·observedAtMs 부여), 단조 시계 틱 스케줄러, 플레이어별 뷰 배포(시계·전송 주입). 서버 실행: Socket.IO 전송 연결, 이탈·중복 접속의 큐 명령 변환, `finishOnce` 종료 저장, 서버 로그 |

큐·틱·뷰 배포는 서버·로컬·AI가 같은 `game-runtime`을 쓰고 시계와 전송만 주입한다([DEC-030](../DECISIONS.md#결정-색인)). 이벤트 이름·명령 필드는 `shared` 한 곳에 정의하고 LOCAL의 [`GameSession`](LOCAL.md#gamesession-시그니처)과 같은 타입을 쓴다. 이름 목록은 API-001에서 먼저 맞춘다.

### 전송과 표시 초안

- 서버는 플레이어별 스냅샷을 보내고 클라이언트는 짧은 버퍼로 보간한다. 틱·revision이 오래된 상태는 버린다. 경기 전체 결과를 기다렸다가 재생하지 않는다.
- 전송 주기는 물리 간격(1/120초)과 분리한다 ([DEC-026](../DECISIONS.md#결정-색인)). 알이 움직이는 동안의 스냅샷은 오래된 틱을 건너뛰어도 되는 volatile로 보낸다. 조준 중에는 상태가 바뀔 때만 보낸다. `turn:change`·`hazard:triggered`·`game:over`와 모든 알이 정지한 뒤의 최종 스냅샷은 신뢰 전송으로 보내 클라이언트가 서버 상태에 수렴하게 한다. 주기 수치는 GAME-002와 개발자 B의 "동시 방 수 × 전송 주기"별 CPU·지연 측정(OPS-001)으로 정한다.
- game:state를 상태 전송에 사용하고 hazard:triggered는 적용 틱·효과를 알린다. 기존 sim:result 일괄 기록 이벤트는 이 초안에서 사용하지 않는다. 이름·필드·응답·유실 시 정합성은 API-001에서 확정한다.
- 클라이언트 표시의 네트워크·보간 지연은 존재한다. 렌더링 프레임률과 서버 물리·전송 주기를 구분하고 지연·대역폭·서버 부하를 측정한다. 낙하 연출은 표시 계층에 둔다.

## 미정 사항

- 수치는 위 [기술 초기값](#기술-초기값-조정-대상)의 제안값으로 시작하고 플레이 테스트로 확정한다.
- API-001 상세 이벤트 이름·필드·오류 형식. 실시간 방식(ADR-0004)과 명령·종료·전송 경계(DEC-026)는 승인됨. 로컬 2인의 입력·구성은 [LOCAL](LOCAL.md#상세-계약-초안-local-001)을 따른다.

제품 규칙은 PRD, 기술 선택 이유는 ADR, 검증 결과는 worklog에서 관리한다.
