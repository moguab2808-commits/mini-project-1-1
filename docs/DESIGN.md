# 설계

## 상태와 책임

전체 구조·경계·핵심 흐름의 진입점이다. 상세 계약은 [아래 상세 설계](#상세-설계-선택)에서 관리하며, 다른 문서와의 작성 경계는 [AGENTS](../AGENTS.md#작업-목적에-따라-읽을-문서)를 따른다.

| 구분 | 상태 |
| --- | --- |
| 승인된 미구현 설계 | 없음 |
| 현재 구현 | 없음. 구현 현황은 [PROGRESS](PROGRESS.md), 근거는 연결된 worklog 참조 |
| 미정 | 기술 스택·아키텍처·API·데이터 모델·인증·게임 처리·운영 전체 |

이전 문서의 3티어·서버 권한·2D 물리/3D 렌더링·공용 게임 코어·기록 재생은 모두 미정인 후보다. 제품 요구사항의 승인과 구현 설계의 승인을 구분한다.

## 전체 구성과 경계 — 미정

아래는 검토 대상 책임을 나타내며 프로세스 수·배포 단위·라이브러리를 정한 구조가 아니다.

| 책임 | 경계에서 합의할 내용 | 상세 |
| --- | --- | --- |
| 사용자 화면·입력 | 입력을 명령으로 변환하고 사용자별 결과·오류를 표현 | [게임](design/GAME.md)·[API](design/API.md) |
| 방·대전 진행 | 참여·턴·증강·승패의 상태 전이와 권한 있는 판정 위치 | [게임](design/GAME.md) |
| 인증·권한 | 사용자 식별, 명령 허용 범위, 비공개 정보 경계 | [인증](design/AUTH.md) |
| 영구 데이터 | 회원·경기 결과·랭킹·건의의 저장과 일관성 | [DB](design/DATABASE.md) |
| 실행·배포 | 로컬·온라인 구성, 환경 설정·배포·관측·복구 | [로컬](design/LOCAL.md)·[운영](design/OPERATIONS.md) |

## 핵심 데이터 흐름 — 검토 대상

1. 사용자 인증 후 방 생성·참여 명령을 처리한다.
2. 대전 상태에 따라 증강 선택·사용과 발사 입력을 검증한다.
3. 판정 결과에서 사용자별 공개 범위를 적용해 화면에 전달한다.
4. 경기 종료 결과를 회원 전적·레이팅과 일관되게 저장한다.

각 단계의 실행 위치·통신 방식·경합 처리·저장 원자성은 미정이다. 위 흐름의 제품 동작·예외 자체는 PRD와 상세 요구사항을 따른다.

## 상세 설계 갱신 규칙

- 각 상세 문서는 승인된 미구현 설계·현재 구현·미정 사항을 구분한다. 승인 시 DEC ID를 연결한다.
- 구현과 승인 설계가 다르면 차이와 영향을 명시하고, 작업·검증 근거는 TASKS와 worklog로 연결한다.
- 연동 계약은 구현 전에 합의한다. 계약 변경 시 관련 문서·코드를 함께 갱신한다.
